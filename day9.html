字符串常用操作（先复习基础）

字符串是 Python 中最常用的数据类型。LLM 返回的内容就是字符串，你需要对它进行各种处理。

text = "  不良资产收购成本：10,000,000 元  "

# ====== 基础操作 ======
print(text.strip())            # 去首尾空格："不良资产收购成本：10,000,000 元"
print(text.replace(",", ""))     # 替换："  不良资产收购成本：10000000 元  "
print(text.split("："))        # 按冒号切割：['  不良资产收购成本', '10,000,000 元  ']
print(text.startswith("不良")) # 判断开头：False（因为有前导空格）
print(text.strip().startswith("不良")) # True
print("不良" in text)           # 包含判断：True

# ====== 字符串格式化（f-string，最常用） ======
project = "项目A"
amount = 10000000
print(f"项目【{project}】收购成本：{amount / 10000:.0f} 万元")
# 输出：项目【项目A】收购成本：1000 万元

# ====== 实用技巧：从混合文本中提取数字 ======
raw = "收购成本10,000,000元，已回收6,500,000元"
# 思路：去掉逗号 → 用正则提取数字（下一节学）
cleaned = raw.replace(",", "")  # 先去掉逗号
💡 f-string 格式化速记：{变量} 直接输出，{变量:.2f} 保留2位小数，{变量:.0f} 取整，{变量:,} 千分位逗号。{变量!r} 显示引号（调试用）。

正则表达式入门：re 模块

正则表达式就是"用模式描述你想匹配的文本规则"。不用一次全记住，掌握下面 5 个最常用的就够了。

import re

# ====== 最核心的 4 个函数 ======

# 1. re.findall() — 找出所有匹配项（返回列表）
text = "项目A金额1000万，项目B金额2000万，项目C金额500万"
amounts = re.findall(r'\d+', text)  # 提取所有数字
print(amounts)  # ['1000', '2000', '500']（注意：返回的是字符串列表）

# 2. re.search() — 找第一个匹配（返回 Match 对象或 None）
result = re.search(r'金额(\d+)万', text)
if result:
    print(result.group(0))  # '金额1000万'（整个匹配）
    print(result.group(1))  # '1000'（括号内的捕获组）

# 3. re.sub() — 替换匹配的文本
cleaned = re.sub(r'[，。！？、；：""'']', "", text)
print(cleaned)  # '项目A金额1000万项目B金额2000万项目C金额500万'

# 4. re.match() — 从字符串开头匹配
m = re.match(r'项目\w+', text)
if m:
    print(m.group())  # '项目A'
3

正则速查表（LLM 应用最常用的模式）

不用背，遇到时回来查就行。重点理解加粗的几个。

模式含义示例
\d任意一个数字\d+ → 匹配 1 个或多个数字
\w字母/数字/下划线\w+ → 匹配单词
\s空白字符（空格/Tab/换行）\s+ → 匹配连续空白
.任意字符（除换行外）.+ → 匹配任意非空文本
*前一个字符出现 0 次或多次ab*c → ac, abc, abbc
+前一个字符出现 1 次或多次\d+ → 123, 45
?前一个字符出现 0 次或 1 次colou?r → color, colour
[...]字符集合[，。、] → 匹配这些标点之一
(...)捕获组（提取子匹配）金额(\d+)万 → group(1) 是数字
r'...'原始字符串（r = raw）r'\n' → 真正的 \n 而非换行

LLM 场景正则实战（15分钟练习）

模拟 LLM 返回的文本，用正则提取关键字段：

import re

# ====== 场景 1：从 LLM 文本中提取金额 ======
llm_output = """
根据分析，该项目的主要指标如下：
- 收购成本：10,000,000 元
- 已回收金额：6,500,000 元
- 处置费用：800,000 元
- 净回收率：52%
"""

# 提取所有金额（含逗号的数字）
money_pattern = r'([\d,]+)\s*元'
amounts = re.findall(money_pattern, llm_output)
amounts_int = [int(a.replace(",", "")) for a in amounts]
print(amounts_int)  # [10000000, 6500000, 800000]

# ====== 场景 2：提取 "字段名：值" 对 ======
kv_pattern = r'-\s*(\S+?)：(.+)'
pairs = re.findall(kv_pattern, llm_output)
data = {k: v.strip() for k, v in pairs}
print(data)
# {'收购成本': '10,000,000 元', '已回收金额': '6,500,000 元', ...}

# ====== 场景 3：从 JSON 字符串中提取（即使 LLM 输出混了其他文字） ======
messy = '这是分析结果：{"project": "项目A", "amount": 10000000, "status": "处置中"} 希望对你有帮助'
json_match = re.search(r'\{.*\}', messy)
if json_match:
    import json
    parsed = json.loads(json_match.group())
    print(parsed["project"])  # 项目A
💡 实战经验：LLM 输出往往不完美——可能多了前缀文字、可能 JSON 格式有细微问题。正则表达式是最后一道保险：先尝试 json.loads()，失败了再用正则提取。这就是"防御性编程"的思路。
⚠️ 新手常见错误：
  • 忘写 r'' 前缀 → \d 被解释成特殊字符（r = raw string，让反斜杠保持原样）
  • .* 太贪心 → 用 .*?（非贪婪匹配），否则会匹配过多内容
  • re.findall() 返回的是字符串列表 → 计算前记得 int() 转换

今天的目标：让 LLM 返回结构化的 JSON 数据（而不是自由文本），然后用 Python 解析和校验。这是 LLM 应用开发中最核心的技能之一——RAG 系统、Agent 工具调用、数据抽取，全都依赖这个能力。

Step 1：用 Prompt 让 LLM 返回 JSON

LLM 默认返回自由文本。要在 Prompt 中明确要求 JSON 格式，并给出字段定义。

from openai import OpenAI
import json

client = OpenAI(
    api_key="你的智谱API Key",
    base_url="https://open.bigmodel.cn/api/paas/v4/"
)

SYSTEM_PROMPT = """你是不良资产数据分析师。请严格按照指定的 JSON 格式回答。
不要输出任何 JSON 之外的解释文字。只输出 JSON，不要用 markdown 代码块包裹。"""

user_prompt = """
请分析以下不良资产项目信息，按 JSON 格式输出：
- 项目名称：宁波XX债权包
- 收购本金：10,000,000 元
- 已回收：6,500,000 元
- 处置费用：800,000 元
- 处置方式：债权转让
- 债务人：某某制造有限公司

输出格式（严格遵守）：
{
  "project_name": "项目名称",
  "principal": 数字（元）,
  "recovered": 数字（元）,
  "fee": 数字（元）,
  "disposal_method": "处置方式",
  "debtor": "债务人名称",
  "net_recovery_rate": 百分比数字（如52.0）,
  "risk_level": "高/中/低",
  "analysis_summary": "一句话分析总结"
}
"""

response = client.chat.completions.create(
    model="glm-4-flash",
    messages=[
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": user_prompt}
    ],
    temperature=0.3  # 温度调低，让输出更稳定
)

raw_output = response.choices[0].message.content
print("=== LLM 原始输出 ===")
print(raw_output)
💡 关键技巧：temperature 设为 0.1~0.3（而不是默认的 0.7），这样模型输出更稳定、格式更一致。让 LLM 输出 JSON 时，低温度 = 更可靠的格式。

Step 2：鲁棒解析函数（处理 LLM 输出的各种"意外"）

LLM 可能会：用 markdown 代码块包裹 JSON、在 JSON 前后加解释文字、格式有小错误。你需要一个能容错的解析函数。

import json
import re

def parse_json_from_llm(raw_output: str, required_fields: list = None) -> dict:
    """
    从 LLM 输出中鲁棒地解析 JSON

    处理策略（按优先级）：
    1. 直接 json.loads（最理想情况）
    2. 去掉 markdown 代码块标记后重试
    3. 用正则提取 {} 内容后重试
    4. 修复常见问题（尾逗号、单引号）后重试

    Args:
        raw_output: LLM 原始输出文本
        required_fields: 必须存在的字段列表（用于校验）
    Returns:
        解析后的字典
    Raises:
        ValueError: 所有解析策略都失败时
    """
    text = raw_output.strip()

    # 策略 1：直接解析
    try:
        return json.loads(text)
    except json.JSONDecodeError:
        pass

    # 策略 2：去掉 markdown 代码块（```json ... ``` 或 ``` ... ```）
    text_clean = re.sub(r'^```(?:json)?\s*', '', text)
    text_clean = re.sub(r'\s*```$', '', text_clean)
    try:
        return json.loads(text_clean)
    except json.JSONDecodeError:
        pass

    # 策略 3：用正则提取 { } 之间的内容
    match = re.search(r'\{.*\}', text, re.DOTALL)
    if match:
        try:
            return json.loads(match.group())
        except json.JSONDecodeError:
            pass

    # 策略 4：修复常见格式问题
    fixed = text_clean if 'text_clean' in dir() else text
    fixed = fixed.replace(",}", "}")      # 去掉尾逗号
    fixed = fixed.replace(",\n}", "\n}") # 多行尾逗号
    fixed = fixed.replace("'", '"')       # 单引号 → 双引号（简单替换，可能有副作用）
    try:
        return json.loads(fixed)
    except json.JSONDecodeError:
        pass

    # 全部失败
    raise ValueError(f"无法从 LLM 输出中解析 JSON：{raw_output[:200]}")

# ====== 校验必需字段 ======
def validate_fields(data: dict, required_fields: list) -> dict:
    """校验必需字段是否存在，缺失的填入 None 并发出警告"""
    missing = [f for f in required_fields if f not in data]
    if missing:
        print(f"⚠️ 缺失字段：{missing}")
        for f in missing:
            data[f] = None
    return data

Step 3：完整流程——调用 + 解析 + 校验 + 保存

把前面的代码串联成一个完整的工作流：

# ====== 必需字段定义 ======
REQUIRED = [
    "project_name", "principal", "recovered",
    "fee", "disposal_method", "debtor",
    "net_recovery_rate", "risk_level"
]

# ====== 解析 + 校验 ======
try:
    data = parse_json_from_llm(raw_output)
    data = validate_fields(data, REQUIRED)
    print("\n=== 解析成功 ===")
    print(json.dumps(data, ensure_ascii=False, indent=2))
except ValueError as e:
    print(f"解析失败：{e}")
    print("请检查 LLM 输出格式，调整 Prompt 后重试")

# ====== 保存到 JSON 文件（复用 Day 8 学的） ======
try:
    with open("project_analysis.json", "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)
    print("已保存到 project_analysis.json")
except:
    print("保存失败（data 可能不存在）")

Step 4：加分——批量处理多个项目

LLM 应用的真实场景往往是批量处理：传入多个项目，逐一解析，汇总保存。

projects_text = [
    "项目A：收购1000万，回收650万，费用80万，债权转让，宁波某制造公司",
    "项目B：收购2000万，回收1200万，费用150万，债务重组，杭州某贸易公司",
    "项目C：收购500万，回收500万，费用30万，诉讼执行，温州某房地产公司",
]

results = []
for i, text in enumerate(projects_text, 1):
    print(f"\n--- 处理第 {i} 个项目 ---")

    # 调用 LLM（这里用之前封装的 ask_llm 函数）
    reply = ask_llm(
        system_prompt=SYSTEM_PROMPT,
        user_prompt=text + "\n\n请按上面的 JSON 格式输出。",
        temperature=0.3
    )

    # 解析 + 校验
    try:
        parsed = parse_json_from_llm(reply)
        parsed = validate_fields(parsed, REQUIRED)
        results.append(parsed)
        print(f"✅ 第 {i} 个项目解析成功")
    except ValueError:
        print(f"❌ 第 {i} 个项目解析失败")

# 批量保存
with open("batch_analysis.json", "w", encoding="utf-8") as f:
    json.dump(results, f, ensure_ascii=False, indent=2)
print(f"\n完成！共解析 {len(results)}/{len(projects_text)} 个项目")
⚠️ 生产级注意事项：
  • LLM 可能返回数字类型不一致（有时是字符串 "10000000"，有时是数字 10000000）→ 解析后要统一类型
  • 字段名可能有细微差异（如 "project_name" vs "项目名称"）→ Prompt 中明确字段名 + 后处理做映射
  • 多次 API 调用有失败风险 → 加 try/except + 日志记录（Day 10 会学 logging 模块）
📖 碎片知识：向量相似度直觉 ~10 分钟
为什么今天学向量相似度？ — 昨天（Day 8）你了解了 Embedding（文本→向量），今天进一步建立"相似度计算"的直觉。这是 Phase 2 RAG 系统的数学基础，现在建立概念，后面写代码就不慌。

核心直觉：两个 Embedding 向量越"像"，它们之间的距离越近，余弦相似度越接近 1。

打个比方：把每个词想象成地图上的一个点。"债权转让"和"债权打包出售"因为意思相近，在地图上的位置就靠得很近——测量它们之间"方向一致程度"的指标就是余弦相似度。

文本对余弦相似度解读
"债权转让" vs "债权打包出售"~0.92非常相似（意思接近）
"债权转让" vs "债务重组"~0.78比较相似（都是处置方式）
"债权转让" vs "煎饼果子"~0.15几乎无关
"债权转让" vs "债权转让"1.00完全相同

用 10 行 Python 直观感受余弦相似度

不需要记公式，看代码就能理解：

from math import sqrt

def cosine_similarity(a, b):
    """计算两个向量的余弦相似度"""
    # 分子：点积（对应位置相乘再求和）
    dot = sum(x * y for x, y in zip(a, b))
    # 分母：各自长度相乘
    mag_a = sqrt(sum(x**2 for x in a))
    mag_b = sqrt(sum(x**2 for x in b))
    return dot / (mag_a * mag_b)

# 模拟两个 Embedding 向量（实际是几百到几千维，这里简化为 5 维）
v1 = [0.23, 0.87, -0.12, 0.45, 0.33]  # "债权转让"
v2 = [0.21, 0.85, -0.10, 0.42, 0.30]  # "债权打包出售"
v3 = [-0.65, 0.11, 0.92, -0.33, 0.78]  # "煎饼果子"

print(f"债权转让 vs 债权打包出售: {cosine_similarity(v1, v2):.4f}")  # ≈ 0.9998（极相似！）
print(f"债权转让 vs 煎饼果子: {cosine_similarity(v1, v3):.4f}")      # ≈ -0.06（几乎无关）

你在 Hive 里写 WHERE name LIKE '%债权%' 是精确匹配关键字。
向量检索是语义匹配——即使查询是"把欠款打包卖掉"，也能匹配到"债权转让"的文档，因为它们的 Embedding 很相似。

这就是 RAG 比传统关键字搜索强大的核心原因！

LeetCode #383 · 赎金信（Easy）

给你两个字符串 ransomNote 和 magazine，判断 ransomNote 能不能由 magazine 里面的字符构成。

示例 1：ransomNote = "a", magazine = "b" → false
示例 2：ransomNote = "aa", magazine = "aab" → true 

def canConstruct(ransomNote: str, magazine: str) -> bool:
    """判断 magazine 是否包含 ransomNote 的所有字符（含重复）"""
    # 方法 1：用 Counter（最 Pythonic）
    from collections import Counter
    note_count = Counter(ransomNote)
    mag_count = Counter(magazine)
    for char, count in note_count.items():
        if mag_count.get(char, 0) < count:
            return False
    return True

# 方法 2：用字典手动计数（面试常问，体现基础）
def canConstruct2(ransomNote: str, magazine: str) -> bool:
    char_count = {}
    for c in magazine:
        char_count[c] = char_count.get(c, 0) + 1
    for c in ransomNote:
        if char_count.get(c, 0) <= 0:
            return False
        char_count[c] -= 1
    return True

# 测试
print(canConstruct("a", "b"))        # False
print(canConstruct("aa", "aab"))     # True
print(canConstruct("abc", "abcc"))    # True

为什么这道题重要？"统计字符出现次数"是字符串处理的经典题型。Counter 和字典手动计数两种写法都要掌握——前者体现 Python 熟练度，后者体现基础能力。面试时建议先写字典版本，再提一句"Python 有 Counter 可以简化"。
