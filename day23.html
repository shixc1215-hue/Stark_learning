🐍 一、什么是设计模式？ 约40min
设计模式是前人总结的、解决特定问题的代码组织方案。它不是语法，而是思路——当你遇到某类问题时，有一套成熟的"套路"可以参考。

你写代码时可能遇到过这些困惑：

  • 🤯 if-elif 写了10个分支，改一个就要动一片 → 策略模式
  • 🤯 创建对象时要写一堆判断逻辑 → 工厂模式
  • 🤯 多个模块都要收到同一事件的通知 → 观察者模式

设计模式帮你把"容易乱的代码"变成"结构清晰的代码"。

⚠️ 设计模式不是万能药。不要为了"炫技"硬套模式，而是当你真的遇到那个问题时，才用对应的模式。
🏭 二、工厂模式（Factory Pattern） 约20min
核心思想：把"创建对象"的逻辑集中到一个地方（工厂），调用者不需要知道具体创建细节，只需要告诉工厂"我要什么"。
调用者：给我一个 "智谱" 模型 → 工厂：判断参数 → 创建 ZhipuModel 对象 → 返回给调用者

❌ 不用工厂模式的代码：

# 每个调用点都要写判断逻辑
if model_name == "zhipu":
    model = ZhipuModel(api_key="xxx")
elif model_name == "openai":
    model = OpenAIModel(api_key="yyy")
elif model_name == "qwen":
    model = QwenModel(api_key="zzz")
# ... 以后加新模型，每个调用点都要改

✅ 用工厂模式：

class ModelFactory:
    """LLM模型工厂 —— 集中管理模型创建逻辑"""

    _registry = {}  # 注册表：模型名 → 创建函数

    @classmethod
    def register(cls, name, creator):
        """注册一个模型的创建函数"""
        cls._registry[name] = creator

    @classmethod
    def create(cls, name, **kwargs):
        """根据名称创建模型对象"""
        if name not in cls._registry:
            raise ValueError(f"未注册的模型：{name}")
        return cls._registry[name](**kwargs)


# 注册各种模型
ModelFactory.register("zhipu", lambda **kw: ZhipuModel(**kw))
ModelFactory.register("openai", lambda **kw: OpenAIModel(**kw))
ModelFactory.register("qwen", lambda **kw: QwenModel(**kw))

# 使用：调用者只需一行
model = ModelFactory.create("zhipu", api_key="xxx")

# 以后加新模型：只需 register 一行，不用改任何调用点
ModelFactory.register("deepseek", lambda **kw: DeepseekModel(**kw))
💡 好处：新增模型时，只需在工厂注册一行，所有调用点自动支持。不用到处改 if-elif。
🎯 三、策略模式（Strategy Pattern）⭐ 今天重点 约30min
核心思想：把"不同策略/算法"封装成独立的类，调用者可以随时切换策略，而不需要修改调用代码。
上下文（Context） → 持有一个策略对象 → 调用策略的 execute() 方法
切换策略 = 更换策略对象，Context 代码不变

❌ 不用策略模式的代码（硬编码分支）：

def generate_prompt(business_type, user_input):
    if business_type == "amc_recycle":
        prompt = f"分析不良资产回收率：{user_input}\n请分步骤计算..."
    elif business_type == "amc_disposal":
        prompt = f"分析资产处置方案：{user_input}\n请评估风险..."
    elif business_type == "amc_report":
        prompt = f"生成监管报告：{user_input}\n请按C表格式..."
    elif business_type == "general":
        prompt = user_input
    else:
        prompt = user_input
    # 每加一种业务，就要改这个函数

✅ 用策略模式重构：

from abc import ABC, abstractmethod

# 1. 定义策略接口（抽象基类）
class PromptStrategy(ABC):
    """Prompt策略的抽象基类"""

    @abstractmethod
    def build_prompt(self, user_input: str) -> str:
        """构建完整Prompt"""
        pass

# 2. 各业务场景实现自己的策略
class AMCRecycleStrategy(PromptStrategy):
    """不良资产回收率分析策略"""

    def build_prompt(self, user_input: str) -> str:
        return f"""你是不良资产回收率分析专家。
请分步骤计算以下资产的回收率：
{user_input}

分析步骤：
1. 确认资产原值和已回收金额
2. 计算回收率 = 已回收金额 / 资产原值
3. 对比行业平均水平给出评价"""


class AMCDisposalStrategy(PromptStrategy):
    """资产处置方案策略"""

    def build_prompt(self, user_input: str) -> str:
        return f"""你是资产处置方案评估专家。
请评估以下处置方案的可行性：
{user_input}

评估维度：
1. 处置方式合规性
2. 预估回收金额 vs 资产原值
3. 处置时效是否满足监管要求"""


class AMCReportStrategy(PromptStrategy):
    """监管报告生成策略"""

    def build_prompt(self, user_input: str) -> str:
        return f"""你是监管报送报告生成专家。
请按C表格式生成以下内容的报告：
{user_input}

格式要求：
1. 严格按照监管报送字段顺序
2. 金额字段保留两位小数
3. 日期格式使用YYYY-MM-DD"""


class GeneralStrategy(PromptStrategy):
    """通用对话策略"""

    def build_prompt(self, user_input: str) -> str:
        return user_input


# 3. 上下文类（Context）—— 持有策略，调用策略
class PromptContext:
    """Prompt上下文 —— 根据业务场景自动选择策略"""

    # 策略映射表
    _strategies = {
        "amc_recycle": AMCRecycleStrategy(),
        "amc_disposal": AMCDisposalStrategy(),
        "amc_report": AMCReportStrategy(),
        "general": GeneralStrategy(),
    }

    def __init__(self, business_type: str):
        if business_type not in self._strategies:
            raise ValueError(f"未知的业务类型：{business_type}")
        self._strategy = self._strategies[business_type]

    def set_strategy(self, strategy: PromptStrategy):
        """动态切换策略"""
        self._strategy = strategy

    def generate(self, user_input: str) -> str:
        """调用当前策略生成Prompt"""
        return self._strategy.build_prompt(user_input)


# 4. 使用
ctx = PromptContext("amc_recycle")
prompt = ctx.generate("资产原值500万，已回收200万")
print(prompt)

# 动态切换策略
ctx.set_strategy(AMCReportStrategy())
prompt2 = ctx.generate("2026年Q1不良资产余额统计")
print(prompt2)
💡 策略模式的好处：
  • 新增业务场景 → 只需新建一个策略类 + 注册到映射表
  • 修改某个场景的Prompt → 只改对应策略类，不影响其他
  • 运行时动态切换策略 → set_strategy() 一行搞定
👁️ 四、观察者模式（Observer Pattern） 约15min
核心思想：一个对象（被观察者）状态变化时，自动通知所有订阅它的观察者。就像订阅公众号——有新文章时，所有粉丝自动收到推送。 
class LLMCallMonitor:
    """LLM调用监控（被观察者）"""

    def __init__(self):
        self._observers = []  # 观察者列表

    def add_observer(self, observer):
        """订阅通知"""
        self._observers.append(observer)

    def remove_observer(self, observer):
        """取消订阅"""
        self._observers.remove(observer)

    def notify(self, event_type, data):
        """通知所有观察者"""
        for observer in self._observers:
            observer.on_event(event_type, data)


class LoggerObserver:
    """日志记录观察者"""
    def on_event(self, event_type, data):
        print(f"[LOG] {event_type}: {data}")


class AlertObserver:
    """告警观察者（如调用失败时发钉钉通知）"""
    def on_event(self, event_type, data):
        if event_type == "error":
            print(f"[ALERT] 🚨 LLM调用异常：{data}")


class MetricsObserver:
    """指标统计观察者（记录调用次数、耗时等）"""
    def __init__(self):
        self.call_count = 0

    def on_event(self, event_type, data):
        if event_type == "success":
            self.call_count += 1
            print(f"[METRICS] 累计成功调用：{self.call_count}次")


# 使用
monitor = LLMCallMonitor()
monitor.add_observer(LoggerObserver())
monitor.add_observer(AlertObserver())
monitor.add_observer(MetricsObserver())

# 模拟LLM调用成功
monitor.notify("success", {"model": "zhipu", "tokens": 150})

# 模拟LLM调用失败
monitor.notify("error", {"model": "zhipu", "error": "API超时"})

输出：

[LOG] success: {'model': 'zhipu', 'tokens': 150}
[METRICS] 累计成功调用：1次
[LOG] error: {'model': 'zhipu', 'error': 'API超时'}
[ALERT] 🚨 LLM调用异常：{'model': 'zhipu', 'error': 'API超时'}
💡 观察者模式让你解耦"事件发生"和"事件处理"。新增一种处理方式（如发邮件通知），只需新增一个观察者类，不用改被观察者代码。
🤖 五、LLM 实操：策略模式 + 智谱 API 完整实战 约45min
今天把策略模式和LLM API调用结合起来，构建一个"根据业务场景自动选择Prompt并调用LLM"的完整系统。

完整代码：策略模式 + 智谱API

from abc import ABC, abstractmethod
from openai import OpenAI

# ============ 1. Prompt策略（与前面相同） ============

class PromptStrategy(ABC):
    @abstractmethod
    def build_prompt(self, user_input: str) -> str:
        pass

class AMCRecycleStrategy(PromptStrategy):
    def build_prompt(self, user_input: str) -> str:
        return f"""你是不良资产回收率分析专家。
请分步骤计算：{user_input}
步骤：1)确认原值和回收额 2)回收率=回收/原值 3)对比行业均值"""

class GeneralStrategy(PromptStrategy):
    def build_prompt(self, user_input: str) -> str:
        return user_input


# ============ 2. LLM调用器（工厂模式创建客户端） ============

class LLMClientFactory:
    """LLM客户端工厂"""

    @staticmethod
    def create(provider: str, api_key: str):
        if provider == "zhipu":
            return OpenAI(
                api_key=api_key,
                base_url="https://open.bigmodel.cn/api/paas/v4/"
            )
        elif provider == "openai":
            return OpenAI(api_key=api_key)
        else:
            raise ValueError(f"不支持的LLM提供商：{provider}")


# ============ 3. 上下文：策略 + LLM调用 ============

class SmartPromptSystem:
    """智能Prompt系统：策略选择 + LLM调用 + 观察者通知"""

    _strategies = {
        "amc_recycle": AMCRecycleStrategy(),
        "general": GeneralStrategy(),
    }

    def __init__(self, llm_client, model_name="glm-4-flash"):
        self._client = llm_client
        self._model = model_name
        self._strategy = self._strategies["general"]
        self._observers = []

    def add_observer(self, observer):
        self._observers.append(observer)

    def set_strategy(self, business_type: str):
        if business_type in self._strategies:
            self._strategy = self._strategies[business_type]
        else:
            raise ValueError(f"未知业务类型：{business_type}")

    def chat(self, user_input: str) -> str:
        """完整流程：选策略 → 构建Prompt → 调用LLM → 返回结果"""

        # 1. 策略构建Prompt
        prompt = self._strategy.build_prompt(user_input)

        # 2. 调用LLM
        try:
            response = self._client.chat.completions.create(
                model=self._model,
                messages=[{"role": "user", "content": prompt}],
                temperature=0.7,
            )
            result = response.choices[0].message.content

            # 3. 通知观察者
            for obs in self._observers:
                obs.on_event("success", {"input": user_input, "tokens": response.usage.total_tokens})

            return result

        except Exception as e:
            for obs in self._observers:
                obs.on_event("error", {"input": user_input, "error": str(e)})
            return f"❌ 调用失败：{e}"


# ============ 4. 观察者 ============

class LoggerObserver:
    def on_event(self, event_type, data):
        if event_type == "success":
            print(f"[LOG] 调用成功，消耗 {data['tokens']} tokens")
        else:
            print(f"[LOG] 调用失败：{data['error']}")


# ============ 5. 运行 ============

# 创建LLM客户端
client = LLMClientFactory.create("zhipu", api_key="your-api-key-here")

# 创建智能系统
system = SmartPromptSystem(client)
system.add_observer(LoggerObserver())

# 通用对话
system.set_strategy("general")
result1 = system.chat("什么是不良资产？")
print(result1)

# 切换到AMC回收率分析策略
system.set_strategy("amc_recycle")
result2 = system.chat("资产原值500万，已回收200万")
print(result2)
💡 这段代码同时运用了3种设计模式：
  • 策略模式 → 不同业务场景的Prompt切换
  • 工厂模式 → LLM客户端的创建
  • 观察者模式 → 调用事件的日志/告警
📊 六、三种模式对比总结
模式 解决的问题 类比 LLM场景举例
工厂模式 创建对象的逻辑分散在各处 去餐厅点菜，不用知道厨房怎么做 根据名称创建不同LLM客户端
策略模式 if-elif分支太多，切换逻辑散落各处 导航软件切换路线策略（最快/最短/避堵） 根据业务场景切换Prompt模板
观察者模式 一个事件需要通知多个处理方 订阅公众号，新文章自动推送 LLM调用成功/失败时自动记录日志、发告警

练习2：给SmartPromptSystem添加费用统计观察者

新增 CostObserver，每次LLM调用成功时计算费用（glm-4-flash约0.1元/千token），输出累计花费。 

class CostObserver:
    """费用统计观察者"""
    def __init__(self, price_per_1k_tokens=0.1):
        self.price = price_per_1k_tokens
        self.total_cost = 0.0

    def on_event(self, event_type, data):
        if event_type == "success":
            tokens = data.get("tokens", 0)
            cost = tokens / 1000 * self.price
            self.total_cost += cost
            print(f"[COST] 本次费用：¥{cost:.4f}，累计：¥{self.total_cost:.4f}")

✅ Day 23 总结

  • 设计模式是解决特定问题的代码组织思路，不是语法糖
  • 工厂模式 → 集中管理对象创建，新增类型只改工厂
  • 策略模式 → 用类封装不同算法，运行时随时切换
  • 观察者模式 → 解耦事件发生和处理，新增处理只加观察者
  • 实战：策略模式 + 智谱API = 根据业务场景自动选择Prompt
