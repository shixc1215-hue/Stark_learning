while 循环 + break / continue（明天重点用这个）

while 循环是交互式程序的核心——程序一直运行，直到用户主动退出。

# 基本 while 循环
count = 0
while count < 3:
    print(f"第 {count+1} 次循环")
    count += 1

# 交互式循环（明天 LLM 项目的骨架）
while True:
    user_input = input("请输入（输入 q 退出）: ")

    if user_input.strip().lower() == "q":
        print("再见！")
        break          # 跳出整个循环

    if not user_input.strip():
        continue       # 跳过空输入，回到循环开头

    print(f"你说了: {user_input}")
💡 break vs continue 记忆法：
break = "我受够了，直接走人"（退出整个循环）
continue = "这次不算，重来"（跳过本次，继续下一次）

🤖 LLM 实操：多轮对话程序实现 ~60-90 分钟
今天的目标：用 Python 写一个交互式多轮对话程序，支持历史消息管理。这是所有 AI 对话产品（ChatGPT、豆包等）的核心机制——把之前的对话历史一起发给模型，它才能理解上下文。
1

理解多轮对话的原理

LLM 本身是"无状态"的——每次调用都是独立的。所谓"多轮对话"，本质是：每次调用时把历史消息一起塞进去。

# OpenAI API 的 messages 参数格式：
# messages 是一个列表，每个元素是一个字典 {"role": "...", "content": "..."}

messages = [
    {"role": "system",    "content": "你是AMC不良资产业务专家"},
    {"role": "user",      "content": "什么是债权转让？"},
    {"role": "assistant", "content": "债权转让是指..."},
    {"role": "user",      "content": "那它和债务重组有什么区别？"}  # 模型能看到上面的历史
]
💡 三种角色：
system — 系统指令，定义模型的人设和行为规则（只发一次）
user — 用户说的话
assistant — 模型的回复（历史对话中需要保留，让模型知道自己说过什么）
2

完整代码：交互式多轮对话程序

把下面的代码保存为 chat_loop.py，直接运行。

from openai import OpenAI
import os

# ====== 配置 ======
# 智谱 API（兼容 OpenAI 格式）
client = OpenAI(
    api_key="你的智谱API Key",
    base_url="https://open.bigmodel.cn/api/paas/v4/"
)
MODEL = "glm-4-flash"

# 系统提示词（定义 AI 的人设）
SYSTEM_PROMPT = """你是宁波AMC的不良资产业务专家。
你的职责：
1. 回答关于不良资产收购、管理、处置的专业问题
2. 用通俗易懂的语言解释专业术语
3. 涉及金额计算时，给出详细的计算步骤
4. 如果不确定，明确告知而不是编造答案"""

# 对话历史列表
messages = [
    {"role": "system", "content": SYSTEM_PROMPT}
]

# ====== 核心函数 ======
def chat(user_input):
    """发送消息给 LLM，返回回复"""
    # 1. 把用户消息加入历史
    messages.append({"role": "user", "content": user_input})

    # 2. 调用 LLM（传入完整历史）
    response = client.chat.completions.create(
        model=MODEL,
        messages=messages,
        temperature=0.7
    )

    # 3. 提取回复内容
    reply = response.choices[0].message.content

    # 4. 把 AI 回复也加入历史（下次对话时模型能看到）
    messages.append({"role": "assistant", "content": reply})

    return reply

# ====== 交互式主循环 ======
print("="*50)
print("  AMC 不良资产智能问答助手")
print("  输入问题开始对话，输入 q 退出")
print("  输入 history 查看对话历史，输入 clear 清除历史")
print("="*50)

while True:
    user_input = input("\n你: ").strip()

    # 退出
    if user_input.lower() == "q":
        print("再见！")
        break

    # 跳过空输入
    if not user_input:
        continue

    # 查看历史
    if user_input == "history":
        print(f"\n当前对话轮数: {len(messages) - 1}（不含system）")
        for msg in messages[1:]:
            role = "你" if msg["role"] == "user" else "AI"
            print(f"  {role}: {msg['content'][:50]}..."
                  if len(msg["content"]) > 50
                  else f"  {role}: {msg['content']}")
        continue

    # 清除历史
    if user_input == "clear":
        messages = [{"role": "system", "content": SYSTEM_PROMPT}]
        print("对话历史已清除，开始新对话。")
        continue

    # 正常对话
    try:
        reply = chat(user_input)
        print(f"\nAI: {reply}")
    except Exception as e:
        print(f"出错了: {e}")
        # 出错时移除刚才加入的 user 消息，避免污染历史
        messages.pop()

进阶实验：对话轮数限制

真实产品不会无限保留历史——太长会超出 token 上限且浪费费用。试试加一个滑动窗口：

# 在 chat() 函数中加入：只保留最近 N 轮对话
MAX_HISTORY = 10  # 保留最近10条消息（5轮对话）

def chat(user_input):
    messages.append({"role": "user", "content": user_input})

    # 滑动窗口：保留 system + 最近 N 条
    trim_messages = [messages[0]] + messages[-MAX_HISTORY:]

    response = client.chat.completions.create(
        model=MODEL,
        messages=trim_messages,
        temperature=0.7
    )
    reply = response.choices[0].message.content
    messages.append({"role": "assistant", "content": reply})
    return reply
💡 实验建议：用多轮对话测试上下文记忆能力——
1. 先问"什么是债权转让？"
2. 再问"它一般能回收多少比例？"
3. 再问"如果我要做这个，需要准备什么材料？"
观察模型是否能记住前面的对话上下文。
⚠️ Token 消耗提醒：每次调用都会把整个 messages 列表发给 API，对话越长，单次调用消耗的 token 越多、费用越高。这就是为什么滑动窗口和上下文管理在生产环境中很重要。
📖 碎片知识：LLM 的幻觉问题（Hallucination） ~15 分钟
核心概念：LLM 会"一本正经地胡说八道"——它生成的文本语法流畅、逻辑看起来合理，但内容完全是编造的。这就是幻觉（Hallucination）。这是 LLM 应用开发中必须面对的核心问题。

用一个 AMC 场景来理解：

用户提问模型幻觉输出（编造）
"宁波市2024年不良资产处置规模是多少？" "根据银保监会数据，2024年宁波市不良资产处置规模达到328.7亿元，同比增长12.3%..."
（数字完全是模型编的，真实数据可能完全不同）
"某某AMC的CEO是谁？" "宁波AMC的现任CEO是张某某..."
（可能张冠李戴，把别的公司的人安过来）

幻觉的 3 大成因：

1

训练数据的噪声与错误

模型从海量互联网文本中学习，这些文本本身就包含错误信息、过时信息、相互矛盾的内容。模型只是学到了"哪些词经常一起出现"，而不是"事实是什么"。

2

生成式架构的本质

LLM 是逐个 token 预测下一个词的，它的目标是"生成流畅合理的文本"，而不是"说出正确的事实"。它会根据概率选择最可能的下一个词，而不是去数据库里查证。

3

知识截止日期

模型的训练数据有截止日期（比如 GPT-4 训练到 2023 年），超出这个时间的事情它完全不知道，但仍然会试图"回答"，导致编造。

3 种缓解策略（RAG 是最核心的）：

策略原理效果你后续会学到
RAG（检索增强生成） 先从知识库检索相关文档，把文档内容塞进 Prompt，让模型"基于材料回答" ★★★★★ Phase 2（W6-W9）
Prompt 工程 在系统提示词中明确要求"如果不确定就说不知道"，限制回答范围 ★★★☆☆ 现在就能用
微调（Fine-tuning） 用高质量领域数据微调，让模型更熟悉领域知识，减少编造 ★★★☆☆ Phase 3（W12）
💡 关键认知：RAG 为什么是解决幻觉的最佳方案？因为它把"记忆"从模型内部（不可控）搬到了外部知识库（可审查、可更新）。模型只需要做"阅读理解"，不需要"凭记忆回答"。

这也是为什么 RAG 是 Phase 2 的核心——它是 LLM 应用工程师最硬的技能。

📋 LeetCode #70 · 爬楼梯（Easy）

假设你正在爬楼梯，需要 n 阶才能到达楼顶。每次你可以爬 1 或 2 个台阶，有多少种不同的方法可以到达楼顶？

示例：n = 3 → 输出 3（1+1+1、1+2、2+1）
提示：这就是斐波那契数列！f(n) = f(n-1) + f(n-2) 

# 提示代码框架
def climbStairs(n):
    if n <= 2:
        return n
    a, b = 1, 2
    for i in range(3, n + 1):
        a, b = b, a + b    # Python 多变量同时赋值！
    return b

# 测试
print(climbStairs(3))  # 3
print(climbStairs(5))  # 8
