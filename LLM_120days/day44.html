🔬 QLoRA 深度解析：4-bit 量化的三个关键技术 ⏱ 12 min
回顾：Day 43 我们学习了 LoRA 的核心原理——冻结原始权重 W，只训练低秩分解矩阵 A 和 B。今天深入 QLoRA（Quantized LoRA），它让消费级显卡（如 RTX 3090/4090）也能微调 7B 甚至 13B 模型。

QLoRA 论文（Dettmers et al., 2023）的核心创新：在4-bit 量化的基础模型上做 LoRA 微调，效果几乎无损。三项关键技术缺一不可：

QLoRA 三大支柱 ┌─────────────────────────────────────────────────┐ │ 1. NF4 量化 — 正态分布权重的最优4-bit编码 │ │ 2. 双重量化 — 量化常数本身再量化，省显存 │ │ 3. 分页优化器 — GPU显存不够时自动用CPU内存 │ └─────────────────────────────────────────────────┘

1️⃣ NF4（NormalFloat4）量化

普通 4-bit 量化（INT4）把浮点数均匀映射到 [-8, 7]，但模型权重呈现正态分布——大部分值集中在 0 附近，两端极少。均匀量化会导致精度损失严重。

NF4 的思路：用正态分布的分位数来划分区间，让每个量化区间包含大致相同数量的权重值。

import numpy as np

# NF4 核心思想演示：对比均匀量化 vs 正态量化
# 假设模型权重服从正态分布 N(0, 0.02)
np.random.seed(42)
weights = np.random.normal(0, 0.02, size=1000)  # 模拟一个权重层

# === 均匀量化 (INT4) ===
# 范围 [-8, 7]，共 16 个等级
int4_levels = np.arange(-8, 8)
w_min, w_max = weights.min(), weights.max()
# 把浮点权重映射到最近的整数等级
uniform_scaled = np.round((weights - w_min) / (w_max - w_min) * 15) - 8
uniform_error = np.mean((weights - uniform_scaled * (w_max - w_min) / 15 - w_min) ** 2)
# 均匀量化的 MSE 较大，因为大部分权重挤在中间几个等级

# === NF4 正态量化 ===
# 用正态分布的分位数作为量化边界
# 16 个等级 → 17 个分位点
nf4_levels = np.array([-1.0, -0.6962, -0.5251, -0.3949, -0.2844, -0.1848,
                       -0.0911, 0.0, 0.0796, 0.1609, 0.2461, 0.3379,
                       0.4407, 0.5626, 0.7230, 1.0])
# NF4 的量化边界在 0 附近更密集，远处更稀疏
# 这样正态分布中间的大量权重获得更精细的表示

# 存储时：每个权重只需 4 bit（1/8 float32 的大小）
# 推理时：查表反量化回 float16 参与计算
print(f"原始权重占用: {weights.nbytes} bytes (float32)")
print(f"NF4 量化后占用: {len(weights) // 2} bytes (4-bit)")
print(f"压缩比: {weights.nbytes / (len(weights) // 2):.0f}x")
数仓类比：NF4 量化就像对数值型指标做直方图分桶。均匀分桶（等宽）在偏态分布上浪费桶位；NF4 用等频分桶（分位数），让每个桶里的值差不多多，量化精度更高。

2️⃣ 双重量化（Double Quantization）

NF4 量化后，每个权重块（通常是 32 个或 64 个一组）需要存一个缩放因子（absmax）和零点偏移，共两个 float32。当模型很大时，这些常量也占不少显存。

双重量化：把第一层量化产生的缩放因子，再量化为 8-bit 整数存起来。相当于"省了显存的显存"。

# 双重量化原理伪代码
# 第一层量化：float32 权重 → NF4 (4-bit)
#   每个block产生 1 个 absmax (float32)
#   假设 7B 模型，block_size=64，约产生 7B/64 = ~109M 个 absmax
#   占用: 109M × 4 bytes = ~436 MB

# 第二层量化：absmax → FP8 (8-bit)
#   每 256 个 absmax 产生 1 个 absmax'
#   占用: 109M × 1 byte = ~109 MB
#   节省: 436 - 109 = ~327 MB

3️⃣ 分页优化器（Paged Optimizers）

训练时，AdamW 优化器需要为每个可训练参数存储 2 份状态（一阶动量 m + 二阶动量 v），LoRA 参数虽少但优化器状态也不小。当 GPU 显存不够时：

  • 普通做法：直接 OOM 崩溃，只能减小 batch size 或模型大小
  • 分页优化器：把优化器状态分页存储，GPU 显存满了自动 spill 到 CPU 内存，需要时再 swap 回来
类比：就像操作系统的虚拟内存——物理内存（GPU 显存）不够时，不常用的页自动换出到硬盘（CPU 内存），用的时候再换入。用户无感知，只是偶尔慢一点。

QLoRA vs 标准 LoRA 显存对比

配置基础模型显存LoRA 参数优化器状态总计 (7B)
标准 LoRA (FP16)~14 GB~0.2 GB~0.8 GB~15 GB
QLoRA (4-bit)~4 GB~0.2 GB~0.8 GB~5 GB

注意：QLoRA 的 "4-bit" 指的是基础模型冻结部分的精度，LoRA 矩阵 A/B 仍然以 FP16/BF16 精度训练。前向传播时，基础层先反量化为 FP16，再与 LoRA 矩阵相加。

微调数据集通常存储为 JSONL（JSON Lines）格式——每行一个 JSON 对象。这种格式天然适合逐行读取大文件、流式处理。作为数据开发工程师，你对"逐行处理"一定很熟悉。

JSONL 读写与校验

import json
from pathlib import Path
from dataclasses import dataclass, field, asdict
from typing import Optional

# ====== 1. 微调样本数据结构 ======
@dataclass
class FineTuneSample:
    """单条微调样本，对应三段式 instruction-input-output"""
    instruction: str          # 系统指令（角色设定）
    input_text: str = ""     # 用户输入（可选）
    output: str = ""         # 期望输出（标准答案）
    category: str = "general"  # 分类标签（用于统计/分层采样）
    difficulty: str = "medium" # easy / medium / hard
    source: str = "manual"    # 数据来源：manual / generated / augmented
    quality_score: float = 1.0  # 质量评分 0~1

    def to_chat_format(self) -> list[dict]:
        """转换为模型训练用的对话格式"""
        messages = [{"role": "system", "content": self.instruction}]
        if self.input_text:
            messages.append({"role": "user", "content": self.input_text})
        messages.append({"role": "assistant", "content": self.output})
        return messages

# ====== 2. JSONL 读写工具 ======
def load_jsonl(path: Path, validate=True) -> list[FineTuneSample]:
    """读取 JSONL 文件，自动校验每行格式"""
    samples = []
    errors = []
    with open(path, "r", encoding="utf-8") as f:
        for line_no, line in enumerate(f, 1):
            line = line.strip()
            if not line:
                continue  # 跳过空行
            try:
                data = json.loads(line)
                # 字段映射：支持多种命名风格
                sample = FineTuneSample(
                    instruction=data.get("instruction", data.get("system", "")),
                    input_text=data.get("input", data.get("question", "")),
                    output=data.get("output", data.get("answer", "")),
                    category=data.get("category", "general"),
                    difficulty=data.get("difficulty", "medium"),
                    source=data.get("source", "manual"),
                    quality_score=data.get("quality_score", 1.0),
                )
                # 基本校验
                if validate and not sample.output:
                    errors.append(fLine {line_no}: output 为空")
                    continue
                samples.append(sample)
            except json.JSONDecodeError as e:
                errors.append(fLine {line_no}: JSON 解析失败 - {e}")
    if errors:
        print(f加载 {len(samples)} 条，失败 {len(errors)} 条：")
        for e in errors[:5]:  # 最多显示 5 条错误
            print(f  ⚠ {e}")
    return samples

def save_jsonl(samples: list[FineTuneSample], path: Path):
    """保存为 JSONL，每个样本一行"""
    path.parent.mkdir(parents=True, exist_ok=True)
    with open(path, "w", encoding="utf-8") as f:
        for sample in samples:
            f.write(json.dumps(asdict(sample), ensure_ascii=False) + "\n")
    print(f已保存 {len(samples)} 条 → {path}")

# ====== 3. 流式读取大文件（不全部加载到内存） ======
def stream_jsonl(path: Path):
    """生成器：逐行读取 JSONL，适合超大文件"""
    with open(path, "r", encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            if line:
                yield json.loads(line)

# 使用示例：逐行统计，不占内存
total_len = 0
count = 0
for record in stream_jsonl(Path("train.jsonl")):
    total_len += len(record.get("output", ""))
    count += 1
print(f平均 output 长度: {total_len / max(count, 1):.0f} 字符")

数据集拆分与统计

import random
from collections import Counter

class DatasetSplitter:
    """数据集拆分与质量统计工具"""

    def __init__(self, samples: list[FineTuneSample], seed=42):
        self.samples = samples
        self.rng = random.Random(seed)

    def split(self, ratio=0.9) -> tuple[list, list]:
        """分层随机拆分（保证各类别比例一致）"""
        # 按类别分组
        groups: dict[str, list] = {}
        for s in self.samples:
            groups.setdefault(s.category, []).append(s)
        # 每组内随机拆分
        train, val = [], []
        for cat, group in groups.items():
            self.rng.shuffle(group)
            n_train = int(len(group) * ratio)
            train.extend(group[:n_train])
            val.extend(group[n_train:])
        self.rng.shuffle(train)
        self.rng.shuffle(val)
        return train, val

    def stats(self) -> dict:
        """数据集质量统计报告"""
        cats = Counter(s.category for s in self.samples)
        diffs = Counter(s.difficulty for s in self.samples)
        sources = Counter(s.source for s in self.samples)
        output_lens = [len(s.output) for s in self.samples]
        return {
            "total": len(self.samples),
            "categories": dict(cats),
            "difficulties": dict(diffs),
            "sources": dict(sources),
            "avg_output_len": sum(output_lens) / len(output_lens),
            "max_output_len": max(output_lens),
            "min_output_len": min(output_lens),
            "quality_avg": sum(s.quality_score for s in self.samples) / len(self.samples),
        }

# 使用
splitter = DatasetSplitter(all_samples)
train_set, val_set = splitter.split(0.9)
report = splitter.stats()
print(f训练集: {len(train_set)}, 验证集: {len(val_set)}")
print(f平均输出长度: {report['avg_output_len']:.0f}")
SQL 思维迁移：JSONL 的一行就是一个"行记录"，load_jsonl 就像 SELECT * FROM table，stream_jsonl 就像游标逐行 fetch。分层拆分就像 PARTITION BY category 后再按比例取样。

Step 1: 数据清洗 Pipeline

import re
from dataclasses import dataclass

@dataclass
class CleaningStats:
    """清洗统计"""
    total: int = 0
    removed_empty: int = 0
    removed_too_short: int = 0
    removed_too_long: int = 0
    removed_duplicate: int = 0
    removed_low_quality: int = 0
    cleaned: int = 0

class DataCleaner:
    """微调数据清洗器"""

    def __init__(
        self,
        min_output_len: int = 20,    # output 最短字符数
        max_output_len: int = 2000,  # output 最长字符数
        min_input_len: int = 5,      # input 最短字符数
        dedup_by: str = "output",  # 去重字段
    ):
        self.min_output_len = min_output_len
        self.max_output_len = max_output_len
        self.min_input_len = min_input_len
        self.dedup_by = dedup_by

    def clean(self, samples: list[FineTuneSample]) -> tuple[list[FineTuneSample], CleaningStats]:
        """执行完整的清洗流程"""
        stats = CleaningStats(total=len(samples))
        result = []
        seen = set()  # 用于去重

        for s in samples:
            # 1) 基础清洗
            s.output = self._normalize_text(s.output)
            s.instruction = self._normalize_text(s.instruction)
            s.input_text = self._normalize_text(s.input_text)

            # 2) 空值过滤
            if not s.output.strip():
                stats.removed_empty += 1; continue

            # 3) 长度过滤
            if len(s.output) < self.min_output_len:
                stats.removed_too_short += 1; continue
            if len(s.output) > self.max_output_len:
                stats.removed_too_long += 1; continue
            if s.input_text and len(s.input_text) < self.min_input_len:
                stats.removed_too_short += 1; continue

            # 4) 去重
            dedup_key = getattr(s, self.dedup_by, "")
            if dedup_key in seen:
                stats.removed_duplicate += 1; continue
            seen.add(dedup_key)

            # 5) 质量检查
            if self._is_low_quality(s):
                stats.removed_low_quality += 1; continue

            result.append(s)
            stats.cleaned += 1

        return result, stats

    def _normalize_text(self, text: str) -> str:
        """文本标准化"""
        # 全角→半角
        text = text.replace("\u3000", " ")  # 全角空格
        text = text.replace("\r\n", "\n").replace("\r", "\n")
        # 合并连续空行（保留最多一个）
        text = re.sub(r"\n{3,}", "\n\n", text)
        return text.strip()

    def _is_low_quality(self, s: FineTuneSample) -> bool:
        """低质量检测启发式规则"""
        bad_patterns = [
            lambda: "我不知道" in s.output and len(s.output) < 50,
            lambda: s.output.count("\n") > 30,  # 空行过多
            lambda: len(re.findall(r[!！]{3,}", s.output)) > 3,  # 过多感叹号
            lambda: s.quality_score < 0.3,
        ]
        return any(rule() for rule in bad_patterns)

# 使用示例
cleaner = DataCleaner(min_output_len=30, max_output_len=1500)
clean_data, stats = cleaner.clean(raw_samples)
print(f清洗前: {stats.total} → 清洗后: {stats.cleaned} (移除: {stats.total - stats.cleaned})")

🔄 数据增强策略：用 LLM 扩充训练数据 ⏱ 10 min
问题：手写样本太慢，100 条可能需要一周。数据增强的核心思路：用现有高质量样本 + LLM 批量生成更多变体，再人工审核。

四种增强策略

策略原理适用场景风险
同义改写 保持 output 不变，改写 input 的表述方式 问答类、翻译类 低
难度分层 基于简单样本生成更难/更简的变体 知识类、推理类 中
反向生成 从 output 反向构造 input NL2SQL、格式转换 中
Self-Instruct 让 LLM 自主生成 instruction+input+output 通用任务 高 
import asyncio

class DataAugmenter:
    """用 LLM 进行数据增强"""

    def __init__(self, llm_call_fn):
        """llm_call_fn: 异步函数，接收 prompt 返回回复"""
        self.llm = llm_call_fn

    async def paraphrase_input(
        self, sample: FineTuneSample, n_variants=3
    ) -> list[FineTuneSample]:
        """同义改写：保持 output 不变，改写 input"""
        prompt = f"""请将以下用户问题改写为{n_variants}个不同的表述方式，
保持原意不变，但用词、句式、详略程度要有变化。
每个改写用"【改写{i+1}】"开头。

原始问题：{sample.input_text}"""

        response = await self.llm(prompt)
        variants = []
        for match in re.finditer(r【改写\d+】(.+?)(?=【改写|$)", response, re.DOTALL):
            new_input = match.group(1).strip()
            if new_input:
                variants.append(FineTuneSample(
                    instruction=sample.instruction,
                    input_text=new_input,
                    output=sample.output,  # output 不变！
                    category=sample.category,
                    difficulty=sample.difficulty,
                    source="augmented",
                    quality_score=0.8,  # 增强数据初始评分略低
                ))
        return variants

    async def augment_dataset(
        self, samples: list[FineTuneSample],
        n_variants=3, concurrency=5
    ) -> list[FineTuneSample]:
        """批量增强整个数据集"""
        semaphore = asyncio.Semaphore(concurrency)
        all_variants = []

        async def _augment_one(sample):
            async with semaphore:
                try:
                    return await self.paraphrase_input(sample, n_variants)
                except Exception:
                    return []  # 失败则跳过

        tasks = [_augment_one(s) for s in samples]
        results = await asyncio.gather(*tasks)

        for variants in results:
            all_variants.extend(variants)

        print(f增强完成: {len(samples)} 条 → 新增 {len(all_variants)} 条")
        return all_variants
关键原则：增强时只改 input，不改 output。output 是"标准答案"，必须保持正确和一致。如果改写了 output，相当于引入了"错误标注"，会让模型学到错误的东西。
数据增强的"黄金比例"：手写样本（高质量种子）占 20-30%，增强样本占 70-80%。手写样本保证方向正确，增强样本扩大覆盖面。千万不要 100% 增强数据——会导致"模式崩塌"（model collapse）。
⚖️ PEFT 方法横向对比：LoRA 不是唯一选择 ⏱ 10 min

PEFT（Parameter-Efficient Fine-Tuning）是一个大家族，LoRA 是其中最流行的成员。不同方法适合不同场景：

五大 PEFT 方法对比

方法可训练参数显存效果推理开销适合场景
LoRA 0.1-1%低★★★★零（可合并） 通用场景首选
QLoRA 0.1-1%极低★★★★零（可合并） 显存受限
Prompt Tuning 0.01%极低★★★极小 多任务快速切换
Prefix Tuning 0.1%低★★★小 生成任务
P-Tuning v2 0.1-1%低★★★★小 小模型/理解任务
DoRA 0.1-1%低★★★★★零（可合并） 追求极限效果

方法原理速览

Prompt Tuning & Prefix Tuning

不再训练模型参数，而是在输入中添加一段可学习的虚拟 token（soft prompt）：

# Prompt Tuning: 只在输入前添加可学习的向量
# 原始: [CLS] 今天天气怎么样？ [SEP]
# Prompt Tuning:
# [虚拟token1][虚拟token2]...[虚拟tokenN][CLS] 今天天气怎么样？ [SEP]
# ↑ 这些虚拟token是可训练的"软提示"，替代了人工写prompt

# Prefix Tuning: 在每一层都添加可学习的前缀
# Layer i: [prefix_i][原始hidden_states]
# 每一层都有自己的可训练前缀，比Prompt Tuning更灵活

# 区别：Prompt Tuning 只在输入层加，Prefix Tuning 每层都加

DoRA（Weight-Decomposed Low-Rank Adaptation）

2024 年的新方法，将权重分解为幅度（magnitude）和方向（direction）两部分分别微调：

# LoRA: W' = W + ΔW = W + B×A
# DoRA: W' = m × (W + B×A) / ||W + B×A||
#        ↑幅度(可学习标量)    ↑方向(LoRA微调后L2归一化)

# 思路：LoRA 改变了幅值也改变了方向，DoRA 让两者独立调整
# 效果：在相同参数量下，DoRA 效果优于 LoRA
# 推理：同样可以合并，零额外开销

如何选择 PEFT 方法？

✅ 推荐选择

  • 显存够（16GB+）→ LoRA (r=8~16)
  • 显存紧（8GB）→ QLoRA (4bit + LoRA)
  • 多任务快速切换→ Prompt Tuning
  • 追求最佳效果→ DoRA

❌ 避免踩坑

  • 小模型（<1B）用 LoRA 效果差 → P-Tuning v2
  • 需要合并部署 → 不要用 Prefix Tuning（无法合并）
  • 推理要求零延迟 → 只选 LoRA/QLoRA/DoRA

⚠️ 常见陷阱 Top 5 ⏱ 5 min
陷阱 1：数据泄露 — 验证集混入训练集
同一问题的不同表述分别出现在训练集和验证集中，导致验证指标虚高，实际效果差。
防御：按 output 做去重（即使 input 不同，只要 output 相似度 > 90% 就要去重）。
陷阱 2：output 质量不均匀 — 混入错误标注
手写样本时标注错误，或 LLM 增强时生成了错误的 output。
防御：每条样本人工审核，至少抽查 30%。建立"黄金测试集"（20 条高质量样本，训练前后都用它测试）。
陷阱 3：过度增强 — 模式崩塌
用 LLM 生成太多变体，导致训练数据过于同质化，模型丧失泛化能力。
防御：增强比例不超过 3:1（每条手写样本最多生成 3 条变体），保持多样性。
陷阱 4：LoRA rank 过大 — 过拟合
r=64 或更大看起来"更强"，但数据量不足时严重过拟合，训练 loss 接近 0 但验证效果很差。
防御：从小开始（r=8），只有在验证集指标不再提升时才增大 r。
陷阱 5：忘记合并推理 — 额外延迟
训练后直接加载 LoRA adapter 推理，每次前向传播都要做 W + B×A 计算。
防御：部署前执行 model.merge_and_unload()，将 LoRA 权重合并进基础模型，推理零额外开销。
