🔍 Function Calling 是什么？为什么要学？ ⏱ 10min
核心定义：Function Calling（函数调用）是 LLM 提供的一种结构化输出能力——模型不再只返回自然语言文本，而是返回 "我想调用 XXX 函数，参数是 YYY" 的 JSON 结构。你的代码解析这个 JSON，执行真正的函数，再把结果喂回模型。

昨天我们用手写 Agent（Day 36）实现了 ReAct 循环，但有一个痛点：解析 LLM 的工具调用依赖正则表达式，脆弱且容易出错。今天学 Function Calling，就是让 LLM 原生支持结构化的工具调用协议。

1.1 回顾：手写 Agent 的痛点
# Day 36 的 SimpleAgent 用正则解析 LLM 输出
import re

def _parse_response(self, text: str) -> dict:
    # 用正则从自由文本中提取 Action 和参数 —— 很脆弱！
    action_pattern = r"Action:\s*(\w+)"
    action = re.search(action_pattern, text)
    if not action:
        return {"type": "final_answer", "content": text}

    # 还要自己解析参数……容易出格式问题
    param_pattern = r"Action Input:\s*(.+?)(?:\n|$)"
    params = re.search(param_pattern, text, re.DOTALL)
    return {"type": "tool_call", "name": action.group(1),
            "input": params.group(1).strip() if params else ""}
痛点总结：① 正则容易匹配失败 ② 参数只能传字符串，无法传结构化数据 ③ 无法区分同名不同参数的函数 ④ LLM 偶尔会"忘记"格式
1.2 Function Calling 的优势
对比维度 手写 ReAct（Day 36） Function Calling（今天）
输出格式 自然语言文本，需正则解析 结构化 JSON，直接反序列化
参数类型 字符串（需手动解析） 强类型（string/int/boolean/array/object）
多函数支持 靠文本匹配区分 模型自动选择正确的函数签名
可靠性 ⚠️ 中等（依赖 prompt 格式） ✅ 高（模型原生能力）
适用场景 不支持 FC 的模型 智谱/OpenAI/DeepSeek 等主流模型
1.3 数仓类比：Function Calling 像什么？
把 Function Calling 想象成ETL 的参数化存储过程：
你定义好存储过程的签名（函数名 + 参数 + 类型），调用方不需要知道内部逻辑，只需按签名传入参数就能执行。
LLM 就是那个"智能调度器"——根据用户意图，自动选择调用哪个存储过程、传什么参数。
用户提问
→
LLM 思考
→
返回 tool_calls
→
本地执行
→
结果回传
→
LLM 总结

class ToolResultEncoder(JSONEncoder):

        if isinstance(obj, datetime):
            return obj.isoformat()
        return super().default(obj)

2.2 Pydantic：结构化数据验证（FC 参数定义利器）

Pydantic 在 Day 25/26（FastAPI）已经用过，今天复习它在 Function Calling 中的核心用法：

from pydantic import BaseModel, Field
from typing import Optional, Literal

# 定义工具参数的数据模型 —— 既是验证器，又是文档
class QueryParams(BaseModel):
    table_name: str = Field(..., description="要查询的表名")
    columns: list[str] = Field(default=["*"], description="查询的列名列表")
    limit: int = Field(default=10, ge=1, le=100, description="返回行数（1-100）")
    where: Optional[str] = Field(None, description="WHERE 过滤条件")
    order_by: Optional[str] = Field(None, description="排序字段，如 'amount DESC'")

# 参数验证 —— 自动检查类型和约束
try:
    params = QueryParams(table_name="amc_loan", limit=200)  # limit 超过 100！
except Exception as e:
    print(f"验证失败: {e}")  # limit must be less than or equal to 100

# 从字典直接构建（API 返回的参数直接喂进来）
raw_args = {"table_name": "amc_loan", "where": "status='不良'"}
params = QueryParams(**raw_args)  # ✅ 自动验证

# 导出为 JSON Schema（LLM 需要的格式）
schema = QueryParams.model_json_schema()
print(json.dumps(schema, indent=2, ensure_ascii=False))
# {
#   "type": "object",
#   "properties": {
#     "table_name": {"type": "string", "description": "要查询的表名"},
#     "columns": {"type": "array", "items": {"type": "string"}, ...},
#     "limit": {"type": "integer", "minimum": 1, "maximum": 100, ...},
#     ...
#   },
#   "required": ["table_name"]
# }
关键洞察：Pydantic 的 model_json_schema() 方法可以自动生成 JSON Schema，而 Function Calling 的工具定义本质上就是 JSON Schema！这让参数定义既有人类可读的验证逻辑，又有机器可读的 Schema。

3.1 工具定义（Tools Schema）

使用 Function Calling 前要先"注册"你的工具——告诉 LLM 有哪些函数可用、每个函数的参数和类型：

# 标准工具定义格式（几乎所有 LLM API 都兼容）
tools = [
    {
        "type": "function",
        "function": {
            "name": "query_amc_database",          # 函数名（模型用来选择）
            "description": "查询AMC不良资产管理数据库，支持SQL查询",  # 功能描述（模型用来决策）
            "parameters": {                    # JSON Schema 格式的参数定义
                "type": "object",
                "properties": {
                    "table": {
                        "type": "string",
                        "enum": ["amc_loan", "amc_collateral", "amc_debtor"],
                        "description": "要查询的AMC业务表"
                    },
                    "condition": {
                        "type": "string",
                        "description": "查询条件，如 status='不良' AND amount > 10000"
                    },
                    "limit": {
                        "type": integer,
                        "description": "返回行数",
                        "default": 10
                    }
                },
                "required": ["table"]    # 必填参数列表
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "calculate_statistics",
            "description": "对查询结果做统计分析（求和/均值/计数/分组统计）",
            "parameters": {
                "type": "object",
                "properties": {
                    "data": {
                        "type": "array",
                        "items": {"type": "object"},
                        "description": "待统计的数据列表"
                    },
                    "metric": {
                        "type": "string",
                        "enum": ["sum", "avg", "count", "max", "min", "group_by"],
                        "description": "统计指标"
                    }
                },
                "required": ["data", "metric"]
            }
        }
    }
]
工具描述心法：description 是模型决策的核心依据！写得越清晰，模型选择越准确。用自然语言说明：
① 这个函数做什么 ② 什么时候该用它 ③ 参数怎么填（举例子）

# 智谱 Function Calling 基础示例
# ====================
import requests
import json

API_KEY = "your_zhipu_api_key"
API_URL = "https://open.bigmodel.cn/api/paas/v4/chat/completions"

# ---- Step 1: 定义工具 ----
tools = [
    {
        "type": "function",
        "function": {
            "name": "query_amc_loan",
            "description": (
                "查询 AMC 不良贷款信息。"
                "当用户问关于贷款、借款人、不良率、金额等问题时使用此工具。"
            ),
            "parameters": {
                "type": "object",
                "properties": {
                    "borrower_name": {
                        "type": "string",
                        "description": "借款人姓名，模糊匹配"
                    },
                    "min_amount": {
                        "type": number,
                        "description": "最低贷款金额（万元）"
                    },
                    "status": {
                        "type": "string",
                        "enum": ["正常", "关注", "次级", "可疑", "损失"],
                        "description": "五级分类状态"
                    }
                },
                "required": []  # 全部可选，模型根据用户意图填充
            }
        }
    }
]

# ---- Step 2: 发送请求（带 tools 参数）----
def chat_with_tools(user_msg: str) -> dict:
    """发送带工具定义的请求"""
    response = requests.post(
        API_URL,
        headers={"Authorization": f"Bearer {API_KEY}"},
        json={
            "model": "glm-4-flash",
            "messages": [{"role": "user", "content": user_msg}],
            "tools": tools  # 关键：传入工具定义
        }
    )
    result = response.json()
    return result["choices"][0]["message"]

# ---- Step 3: 解析模型返回 ----
msg = chat_with_tools("帮我查一下张三的不良贷款，金额大于50万的")

if "tool_calls" in msg:
    for tc in msg["tool_calls"]:
        func_name = tc["function"]["name"]
        func_args = json.loads(tc["function"]["arguments"])
        print(f"模型想调用: {func_name}")
        print(f"参数: {json.dumps(func_args, ensure_ascii=False, indent=2)}")
        # 输出:
        # 模型想调用: query_amc_loan
        # 参数: {"borrower_name": "张三", "min_amount": 50, "status": "可疑"}
else:
    print("模型直接回答（未调用工具）:", msg["content"])
4.2 执行工具 + 回传结果
# ====================
# 模拟工具函数（实际项目中替换为真实的数据库查询）
# ====================

# 模拟 AMC 贷款数据
MOCK_LOANS = [
    {"id": "L001", "borrower": "张三", "amount": 120, "status": "可疑",
     "bank": "A银行", "date": "2024-03-15"},
    {"id": "L002", "borrower": "张三", "amount": 35, "status": "次级",
     "bank": "B银行", "date": "2024-06-20"},
    {"id": "L003", "borrower": "李四", "amount": 200, "status": "损失",
     "bank": "A银行", "date": "2023-12-01"},
]

def execute_tool(name: str, args: dict) -> str:
    """工具路由：根据函数名分发到实际处理逻辑"""
    if name == "query_amc_loan":
        results = []
        for loan in MOCK_LOANS:
            # 逐个条件匹配
            if "borrower_name" in args and args["borrower_name"] not in loan["borrower"]:
                continue
            if "min_amount" in args and loan["amount"] < args["min_amount"]:
                continue
            if "status" in args and loan["status"] != args["status"]:
                continue
            results.append(loan)

        if not results:
            return json.dumps({"count": 0, "data": []}, ensure_ascii=False)
        return json.dumps({"count": len(results), "data": results}, ensure_ascii=False)

    return json.dumps({"error": f"未知工具: {name}"})

# ---- Step 4: 把执行结果回传给 LLM ----
def full_function_calling(user_msg: str) -> str:
    """完整的 Function Calling 流程：调用工具 → 回传结果 → 获取总结"""

    # 第一次请求：用户提问
    messages = [{"role": "user", "content": user_msg}]

    response = requests.post(
        API_URL,
        headers={"Authorization": f"Bearer {API_KEY}"},
        json={"model": "glm-4-flash", "messages": messages, "tools": tools}
    )
    assistant_msg = response.json()["choices"][0]["message"]

    # 如果模型没有调用工具，直接返回文本回答
    if "tool_calls" not in assistant_msg:
        return assistant_msg.get("content", "(无回答)")

    # 记录 assistant 的 tool_calls 消息
    messages.append(assistant_msg)

    # 逐个执行工具调用
    for tc in assistant_msg["tool_calls"]:
        func_name = tc["function"]["name"]
        func_args = json.loads(tc["function"]["arguments"])
        tool_call_id = tc["id"]

        print(f"🔧 调用工具: {func_name}({json.dumps(func_args, ensure_ascii=False)})")

        # 执行真实函数
        result_str = execute_tool(func_name, func_args)
        print(f"   结果: {result_str[:100]}...")

        # 添加 tool 消息（注意 role="tool"，必须有 tool_call_id）
        messages.append({
            "role": "tool",
            "content": result_str,
            "tool_call_id": tool_call_id  # 关键！绑定到对应的 tool_call
        })

    # 第二次请求：让模型根据工具结果生成回答
    response2 = requests.post(
        API_URL,
        headers={"Authorization": f"Bearer {API_KEY}"},
        json={"model": "glm-4-flash", "messages": messages, "tools": tools}
    )
    final_answer = response2.json()["choices"][0]["message"]["content"]
    return final_answer

# 测试
answer = full_function_calling("查一下张三的不良贷款，金额超过50万的")
print(f"\n💬 LLM 回答: {answer}")
消息角色三要素：
① user — 用户提问
② assistant（含 tool_calls）— 模型决定调用工具
③ tool（含 tool_call_id）— 工具执行结果回传
这三者构成一次完整的工具调用闭环。

4.4 通用 Function Calling 循环引擎
# ====================
# 通用 FC 循环引擎（支持多轮工具调用）
# ====================

def fc_loop(
    user_msg: str,
    tools: list,
    tool_registry: dict,
    system_prompt: str = "你是AMC不良资产管理助手，请根据用户需求调用合适的工具。",
    max_rounds: int = 5
) -> str:
    """
    通用 Function Calling 循环引擎
    支持：多轮工具调用 + 自动终止 + 错误处理

    Args:
        user_msg: 用户原始问题
        tools: 工具定义列表
        tool_registry: 工具名 → 执行函数的映射
        system_prompt: 系统提示词
        max_rounds: 最大工具调用轮次（防死循环）
    """
    messages = [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": user_msg}
    ]

    for round_num in range(1, max_rounds + 1):
        print(f"\n--- 第 {round_num} 轮 ---")

        response = requests.post(
            API_URL,
            headers={"Authorization": f"Bearer {API_KEY}"},
            json={"model": "glm-4-flash", "messages": messages, "tools": tools}
        ).json()

        assistant_msg = response["choices"][0]["message"]
        messages.append(assistant_msg)

        # 情况1：模型直接给出文本回答（不调用工具）
        if "tool_calls" not in assistant_msg:
            print("✅ 模型给出最终回答")
            return assistant_msg.get("content", "")

        # 情况2：模型要调用工具
        for tc in assistant_msg["tool_calls"]:
            name = tc["function"]["name"]
            try:
                args = json.loads(tc["function"]["arguments"])
            except JSONDecodeError:
                args = {}

            print(f"🔧 [{name}] 参数: {args}")

            # 执行工具（带错误兜底）
            if name in tool_registry:
                try:
                    result = tool_registry[name](args)
                    print(f"   ✅ 成功")
                except Exception as e:
                    result = json.dumps({"error": str(e)})
                    print(f"   ❌ 错误: {e}")
            else:
                result = json.dumps({"error": f"未知工具: {name}"})
                print(f"   ⚠️ 未知工具")

            messages.append({
                "role": "tool",
                "content": result,
                "tool_call_id": tc["id"]
            })

    return "⚠️ 达到最大工具调用轮次，请简化问题"

# ---- 测试：需要多轮调用的复杂问题 ----
answer = fc_loop(
    "查询所有可疑类贷款的金额，然后帮我算一下平均值",
    tools=ALL_TOOLS,
    tool_registry=TOOL_REGISTRY
)

🤖 LLM 实战：基于 FC 的 AMC 智能查询 Agent ⏱ 20min

把 Day 36 的 SimpleAgent 升级为 FCAgent——用 Function Calling 替代正则解析，更可靠、更强大。

# ====================
# FCAgent：基于 Function Calling 的 AMC 智能查询 Agent
# ====================
import json
import requests
from dataclasses import dataclass, field
from typing import Callable, Optional
from datetime import datetime

API_KEY = "your_zhipu_api_key"
API_URL = "https://open.bigmodel.cn/api/paas/v4/chat/completions"

# ---- 数据模型 ----
@dataclass
class ToolCall:
    """记录一次工具调用"""
    call_id: str
    name: str
    args: dict
    result: str = ""
    error: Optional[str] = None
    timestamp: str = field(default_factory=lambda: datetime.now().isoformat())

@dataclass
class FCAgentConfig:
    """Agent 配置"""
    model: str = "glm-4-flash"
    system_prompt: str = ""
    max_tool_rounds: int = 5
    temperature: float = 0.1  # 工具调用用低温度，更精确

class FCAgent:
    """
    基于 Function Calling 的 Agent
    对比 Day 36 的 SimpleAgent：
    - 不需要正则解析
    - 参数有类型约束
    - 支持多工具并行调用
    - 工具调用记录完整可追溯
    """

    def __init(
        self,
        config: FCAgentConfig = None,
        tools: list = None,
        tool_registry: dict = None
    ):
        self.config = config or FCAgentConfig()
        self.tools = tools or []
        self.tool_registry = tool_registry or {}
        self.history: list[dict] = []
        self.call_log: list[ToolCall] = []  # 工具调用记录

    def register_tool(self, name: str, schema: dict, executor: Callable):
        """注册一个工具（定义 + 执行函数）"""
        self.tools.append({
            "type": "function",
            "function": schema
        })
        self.tool_registry[name] = executor

    def _call_llm(self, messages: list) -> dict:
        """调用 LLM API"""
        resp = requests.post(
            API_URL,
            headers={"Authorization": f"Bearer {API_KEY}"},
            json={
                "model": self.config.model,
                "messages": messages,
                "tools": self.tools,
                "temperature": self.config.temperature,
            }
        )
        return resp.json()["choices"][0]["message"]

    def _execute_tool(self, call_id: str, name: str, raw_args: str) -> str:
        """执行单个工具调用，带完整日志"""
        try:
            args = json.loads(raw_args)
        except json.JSONDecodeError as e:
            error_msg = f"参数 JSON 解析失败: {e.msg}"
            log = ToolCall(call_id=call_id, name=name, args={}, error=error_msg)
            self.call_log.append(log)
            return json.dumps({"error": error_msg})

        if name not in self.tool_registry:
            error_msg = f"未知工具: {name}"
            log = ToolCall(call_id=call_id, name=name, args=args, error=error_msg)
            self.call_log.append(log)
            return json.dumps({"error": error_msg})

        try:
            result = self.tool_registry[name](args)
            log = ToolCall(call_id=call_id, name=name, args=args, result=result)
            self.call_log.append(log)
            return result
        except Exception as e:
            error_msg = str(e)
            log = ToolCall(call_id=call_id, name=name, args=args, error=error_msg)
            self.call_log.append(log)
            return json.dumps({"error": error_msg})

    def run(self, user_msg: str) -> str:
        """执行一次完整的 FC Agent 对话"""
        self.call_log.clear()

        messages = [
            {"role": "system", "content": self.config.system_prompt},
            {"role": "user", "content": user_msg}
        ]

        for round_num in range(1, self.config.max_tool_rounds + 1):
            assistant_msg = self._call_llm(messages)
            messages.append(assistant_msg)

            # 不需要工具 → 直接返回
            if "tool_calls" not in assistant_msg:
                return assistant_msg.get("content", "")

            # 执行所有工具调用
            for tc in assistant_msg["tool_calls"]:
                result = self._execute_tool(
                    tc["id"],
                    tc["function"]["name"],
                    tc["function"]["arguments"]
                )
                messages.append({
                    "role": "tool",
                    "content": result,
                    "tool_call_id": tc["id"]
                })

        return f"⚠️ 达到最大轮次 {self.config.max_tool_rounds}"

    def show_log(self):
        """打印工具调用日志"""
        for i, log in enumerate(self.call_log, 1):
            status = "❌" if log.error else "✅"
            print(f"  [{i}] {status} {log.name}({json.dumps(log.args, ensure_ascii=False)})")
            if log.error:
                print(f"      错误: {log.error}")

# ---- 使用示例 ----

    config=FCAgentConfig(
        system_prompt="你是AMC不良资产数据分析助手。准确调用工具，给出专业回答。"
    ),
    tools=ALL_TOOLS,

🔧 进阶技巧：用 Pydantic 自动生成工具 Schema ⏱ 10min

手动写 JSON Schema 容易出错且重复。用 Pydantic 模型自动生成：

from pydantic import BaseModel, Field
from typing import Optional

# ---- 用 Pydantic 定义参数模型 ----
class QueryDBParams(BaseModel):
    """查询AMC数据库的参数"""
    table: str = Field(..., description="表名: loan/collateral/debtor")
    condition: Optional[str] = Field(None, description="WHERE条件")
    columns: str = Field("*", description="列名，逗号分隔")
    limit: int = Field(10, ge=1, le=100, description="返回行数")

class StatsParams(BaseModel):
    """统计分析参数"""
    values: list[float] = Field(..., description="数值列表")
    metric: str = Field(
        ...,
        description="统计方法",
        pattern=r"^(sum|avg|count|max|min)$"
    )

class KBSearchParams(BaseModel):
    """知识库搜索参数"""
    query: str = Field(..., min_length=1, description="搜索关键词")
    top_k: int = Field(3, ge=1, le=10, description="返回结果数")

# ---- 自动转成 tools schema ----
def pydantic_to_tool(
    name: str,
    description: str,
    param_model: type[BaseModel]
) -> dict:
    """把 Pydantic 模型转换为 LLM tools 定义"""
    schema = param_model.model_json_schema()
    return {
        "type": "function",
        "function": {
            "name": name,
            "description": description,
            "parameters": {
                "type": schema["type"],
                "properties": schema.get("properties", {}),
                "required": schema.get("required", [])
            }
        }
    }

# 一行生成工具定义！
auto_tools = [
    pydantic_to_tool("query_amc_database", "查询AMC数据库", QueryDBParams),
    pydantic_to_tool("calculate_stats", "数值统计分析", StatsParams),
    pydantic_to_tool("search_knowledge", "搜索知识库", KBSearchParams),
]

print(json.dumps(auto_tools, indent=2, ensure_ascii=False))
# ✅ 完美生成标准 tools schema，含 type/enum/minimum/maximum 等约束
双层验证策略：Pydantic 模型做第一层（参数类型 + 约束），LLM 返回参数后用 Pydantic 实例化做第二层校验。这样即使 LLM 返回了不合规的参数，也能在代码层兜住。
⚠️ 常见陷阱 Top 5 ⏱ 5min
# 陷阱 症状 解决方案
1 忘传 tool_call_id API 报错：tool message 缺少 tool_call_id tool 消息的 role="tool"，必须绑定 assistant 消息中的 id
2 参数 JSON 解析失败 json.loads 抛异常 始终 try/except 包裹，给模型返回错误提示让它重试
3 工具描述太简短 模型选错工具或不用工具 描述包含：功能说明 + 使用场景 + 参数示例
4 死循环调用 模型反复调用同一工具 设 max_rounds（通常 5 轮足够）+ 检测重复调用
5 工具结果太长 Token 超限或模型丢失关键信息 结果截断到合理长度（如 2000 字），摘要后返回
安全红线：Function Calling 中模型只是"建议"调用工具，实际执行完全由你的代码控制。对于高风险操作（删除数据、执行 SQL），务必在 execute_tool 中加权限校验和确认机制！

📌 练习3：LeetCode #49 字母异位词分组（关联 json 字典操作）

给你一个字符串数组，将字母异位词组合在一起。

# 示例: strs = ["eat","tea","tan","ate","nat","bat"]
# 输出: [["bat"],["nat","tan"],["ate","eat","tea"]]

def group_anagrams(strs: list[str]) -> list[list[str]]:
    # 思路：sorted(s) 作为 key，用 dict 分组
    groups = {}
    for s in strs:
        key = tuple(sorted(s))  # sorted 返回 list，要转 tuple 才能做 key
        groups.setdefault(key, []).append(s)
    return list(groups.values())
提示：核心用 sorted + dict.setdefault 分组。和 Function Calling 中的 JSON 字典操作思路一致。
