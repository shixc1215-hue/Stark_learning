📦 Docker 核心概念 ⏱ 10min
Docker = 把「应用 + 依赖 + 环境」打包成一个轻量级容器，在任何机器上都能一致运行。 就像你用 ETL 管道把源数据加工成标准格式 —— Docker 把软件环境加工成标准格式。

三大核心概念

概念类比（数仓）说明
镜像 ImageETL 模板 / 建表 DDL只读模板，定义容器内容（OS + Python + 代码 + 模型）
容器 ContainerDDL 执行后的一张实例表镜像的可运行实例，有独立文件系统和网络
Dockerfile建表 SQL 脚本定义「如何构建镜像」的步骤清单

为什么 LLM 需要 Docker？

  • 环境一致性：vLLM 在你电脑能跑，在服务器也能跑 —— 不再「在我机器上是好的」
  • 依赖隔离：Python 3.11 + CUDA 12.1 + vLLM 0.5，全封闭在容器里，不污染宿主机
  • 快速部署：一行 docker run 拉起完整 LLM 服务，替代 30 分钟的手动安装
  • 可复现性：版本锁定，队友拉同一镜像，保证一致性
Dockerfile → docker build → Image 镜像 → docker run → Container 容器
数仓人秒懂：Image ≈ 数仓表模板，Container ≈ 表实例，Dockerfile ≈ CREATE TABLE 语句。同一模板可以创建多个实例，每个实例独立运行互不干扰。

2. os.environ 环境变量管理

Docker 容器通过环境变量传递配置（模型名、端口、API Key 等）。

import os
from dataclasses import dataclass, field

@dataclass
class DeployConfig:
    """Docker 部署配置 —— 从环境变量读取，提供默认值"""
    model_name: str = field(
        default_factory=lambda: os.getenv("MODEL_NAME", "Qwen/Qwen2.5-7B-Instruct")
    )
    host: str = field(
        default_factory=lambda: os.getenv("HOST", "0.0.0.0")
    )
    port: int = field(
        default_factory=lambda: int(os.getenv("PORT", "8000"))
    )
    gpu_count: int = field(
        default_factory=lambda: int(os.getenv("GPU_COUNT", "1"))
    )
    api_key: str = field(
        default_factory=lambda: os.getenv("API_KEY", "")
    )

    def validate(self) -> list[str]:
        """校验配置合法性，返回错误列表"""
        errors = []
        if self.gpu_count < 1:
            errors.append(f"GPU_COUNT 必须 >= 1，当前: {self.gpu_count}")
        if self.port < 1024 or self.port > 65535:
            errors.append(f"PORT 必须在 1024-65535 之间，当前: {self.port}")
        if not self.model_name:
            errors.append("MODEL_NAME 不能为空")
        return errors

# 使用
cfg = DeployConfig()
print(cfg)
# DeployConfig(model_name='Qwen/Qwen2.5-7B-Instruct', host='0.0.0.0', port=8000, gpu_count=1, api_key='')

🏗️ 编写 Dockerfile —— 构建 LLM 服务镜像 ⏱ 15min

Dockerfile 语法精讲

指令作用类比
FROM基础镜像（必填第一条）CREATE TABLE ... AS SELECT ... 继承模板
RUN构建时执行命令建表时的 DEFAULT / 约束处理
COPY复制文件到镜像INSERT 数据到表中
WORKDIR设置工作目录USE database 切换库
ENV设置环境变量SET @variable = value
EXPOSE声明端口（文档性质）注释说明对外接口
CMD容器启动命令（可被覆盖）程序入口 main()
ENTRYPOINT容器启动命令（不可覆盖）程序核心逻辑（固定）

实战：AMC 智能分析服务 Dockerfile

# ---- Dockerfile ----
# 选择带 CUDA 的 Python 基础镜像（约 2GB）
FROM nvidia/cuda:12.1.1-runtime-ubuntu22.04

# 避免交互式安装弹窗
ENV DEBIAN_FRONTEND=noninteractive

# 安装 Python 3.11 + pip
RUN apt-get update && apt-get install -y \
    python3.11 python3.11-venv python3-pip \
    curl wget git \
    && rm -rf /var/lib/apt/lists/*    # 清理缓存，减小镜像体积

# 设置工作目录
WORKDIR /app

# 先复制 requirements.txt（利用 Docker 缓存层）
COPY requirements.txt .
RUN pip3 install --no-cache-dir -r requirements.txt

# 复制应用代码
COPY app/ ./app/
COPY config/ ./config/
COPY entrypoint.sh .

# 声明端口
EXPOSE 8000

# 设置启动命令
ENTRYPOINT ["bash", "entrypoint.sh"]

启动脚本 entrypoint.sh

#!/bin/bash
# entrypoint.sh —— 容器启动入口

set -e  # 任何命令失败立即退出

# 打印配置信息（便于排查问题）
echo "========================================"
echo "  AMC 智能分析服务"
echo "  模型: ${MODEL_NAME:-Qwen/Qwen2.5-7B-Instruct}"
echo "  端口: ${PORT:-8000}"
echo "  GPU:  ${GPU_COUNT:-1}"
echo "========================================"

# 健康检查：等待模型加载就绪
check_health() {
    local max_retries=30
    local retry=0
    while [ $retry -lt $max_retries ]; do
        if curl -sf http://localhost:${PORT:-8000}/health > /dev/null 2>&1; then
            echo "✅ 服务启动成功！"
            return 0
        fi
        echo "⏳ 等待服务就绪... ($((retry+1))/$max_retries)"
        sleep 5
        retry=$((retry+1))
    done
    echo "❌ 服务启动超时"
    exit 1
}

# 启动 FastAPI 应用
cd /app
python3 -m uvicorn app.main:app \
    --host 0.0.0.0 \
    --port ${PORT:-8000} \
    --workers 1 &  # 后台运行

# 执行健康检查
check_health

# 阻塞主进程（保持容器运行）
wait %1
分层缓存优化：Docker 按指令逐层构建镜像。把不常变的层（如 pip install）放前面，常变的层（如 COPY app/）放后面。这样改代码时不用重新安装依赖，构建速度快 10 倍以上。

构建与运行

🎵 Docker Compose 编排多服务 ⏱ 15min

真实场景需要多个服务协作。Docker Compose 用一个 YAML 文件定义、一键启动。

Docker Compose = 用 YAML 描述「哪些容器 + 它们怎么连接」，一条命令全部拉起。 就像数仓里一个 Airflow DAG 编排多个 Task —— Compose 编排多个容器。

AMC 智能分析平台 — 完整 docker-compose.yaml

# ---- docker-compose.yaml ----
version: "3.9"

services:
  # ========== 1. LLM 推理服务（vLLM）==========
  llm:
    image: vllm/vllm-openai:latest
    container_name: amc-llm
    restart: unless-stopped
    ports:
      - "8000:8000"
    environment:
      - MODEL_NAME=Qwen/Qwen2.5-7B-Instruct
      - MAX_MODEL_LEN=4096
      - GPU_MEMORY_UTILIZATION=0.85
    volumes:
      - model_cache:/root/.cache/huggingface   # 模型缓存持久化
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 10s
      retries: 5

  # ========== 2. AMC 业务 API（FastAPI）==========
  api:
    build: .
    container_name: amc-api
    restart: unless-stopped
    ports:
      - "9000:8000"    # 宿主机 9000 → 容器 8000
    environment:
      - LLM_BASE_URL=http://llm:8000/v1   # 用服务名访问！
      - REDIS_URL=redis://redis:6379
      - MODEL_NAME=Qwen/Qwen2.5-7B-Instruct
    depends_on:
      llm:
        condition: service_healthy    # 等 LLM 健康后再启动
      redis:
        condition: service_started

  # ========== 3. Redis 缓存 ==========
  redis:
    image: redis:7-alpine
    container_name: amc-redis
    restart: unless-stopped
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data

  # ========== 4. Nginx 反向代理（可选）==========
  nginx:
    image: nginx:alpine
    container_name: amc-nginx
    restart: unless-stopped
    ports:
      - "80:80"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
    depends_on:
      - api

# ========== 持久化存储卷 ==========
volumes:
  model_cache:
  redis_data:

GPU 参数详解

# 使用所有 GPU
docker run --gpus all ...

# 指定 GPU 编号（服务器有多张卡时）
docker run --gpus '"device=0,1"' ...

# 限制 GPU 显存（避免一个容器吃光所有显存）

🔧 Python + Docker：自动化部署工具 ⏱ 12min

用 Python 脚本封装 Docker 操作，实现「一键检测 → 一键部署 → 一键验证」。

# deploy_manager.py —— Docker 部署管理器
import subprocess
import time
from dataclasses import dataclass, field
from pathlib import Path
from enum import Enum, auto


class DeployStatus(Enum):
    PENDING = auto()
    BUILDING = auto()
    RUNNING = auto()
    HEALTHY = auto()
    FAILED = auto()
    STOPPED = auto()


@dataclass
class ServiceHealth:
    """单个服务的健康状态"""
    name: str
    status: DeployStatus = DeployStatus.PENDING
    response_time_ms: float = 0.0
    error: str = ""

    def __str__(self) -> str:
        icon = {
            DeployStatus.PENDING: "⚪", DeployStatus.BUILDING: "🔨",
            DeployStatus.RUNNING: "🔵", DeployStatus.HEALTHY: "🟢",
            DeployStatus.FAILED: "🔴", DeployStatus.STOPPED: "⚫",
        }
        return f"{icon[self.status]} {self.name}: {self.status.name}" \
               + (f" ({self.response_time_ms:.0f}ms)" if self.response_time_ms else "") \
               + (f" [{self.error}]" if self.error else "")


class DockerDeployer:
    """Docker Compose 部署管理器"""

    def __init__(self, compose_file: str = "docker-compose.yaml"):
        self.compose_file = Path(compose_file)
        self.project_dir = self.compose_file.parent
        self.services: list[ServiceHealth] = []

    # ---- 私有方法：执行 docker 命令 ----
    def _run_cmd(self, cmd: str, timeout: int = 60) -> str:
        """执行 shell 命令并返回输出"""
        result = subprocess.run(
            cmd, shell=True, capture_output=True,
            text=True, timeout=timeout, cwd=self.project_dir
        )
        if result.returncode != 0:
            raise RuntimeError(f"命令失败: {cmd}\n{result.stderr}")
        return result.stdout.strip()

    def _parse_compose_services(self) -> list[str]:
        """从 docker-compose.yaml 解析服务名列表"""
        import yaml
        config = yaml.safe_load(self.compose_file.read_text(encoding="utf-8"))
        return list(config.get("services", {}).keys())

    # ---- 公共方法：部署流程 ----
    def check_prerequisites(self) -> list[str]:
        """检查前置条件"""
        checks = []
        try:
            version = self._run_cmd("docker --version")
            checks.append(f"✅ Docker: {version}")
        except RuntimeError:
            checks.append("❌ Docker 未安装或未启动")
        try:
            self._run_cmd("docker compose version")
            checks.append("✅ Docker Compose 可用")
        except RuntimeError:
            checks.append("❌ Docker Compose 不可用")
        try:
            output = self._run_cmd("docker run --rm --gpus all nvidia/cuda:12.1.1-base-ubuntu22.04 nvidia-smi", timeout=30)
            if "GPU" in output:
                checks.append("✅ GPU 可用")
        except (RuntimeError, subprocess.TimeoutExpired):
            checks.append("⚠️ GPU 不可用（将使用 CPU 模式）")
        return checks

    def deploy(self, build: bool = True) -> list[ServiceHealth]:
        """一键部署所有服务"""
        print(f"🚀 开始部署 AMC 智能分析平台...")
        print(f"   Compose 文件: {self.compose_file}")

        # 构建
        if build:
            print("🔨 构建镜像...")
            self._run_cmd("docker compose build", timeout=300)

        # 启动
        print("🐳 启动服务...")
        self._run_cmd("docker compose up -d", timeout=120)

        # 等待并检查健康状态
        service_names = self._parse_compose_services()
        self.services = [ServiceHealth(name=name) for name in service_names]

        for svc in self.services:
            svc.status = DeployStatus.RUNNING
            print(f"  ⏳ {svc}")

        # 健康检查（轮询）
        print("🏥 健康检查...")
        self._wait_healthy(max_wait=120)

        return self.services

    def _wait_healthy(self, max_wait: int = 120):
        """轮询等待所有服务健康"""
        start = time.time()
        while time.time() - start < max_wait:
            try:
                output = self._run_cmd("docker compose ps --format json")
                for svc in self.services:
                    if svc.name in output and "running" in output:
                        svc.status = DeployStatus.HEALTHY
            except RuntimeError:
                pass

            if all(s.status == DeployStatus.HEALTHY for s in self.services):
                print("  🎉 所有服务已就绪！")
                return

            time.sleep(5)

        for svc in self.services:
            if svc.status != DeployStatus.HEALTHY:
                svc.status = DeployStatus.FAILED
                svc.error = "启动超时"

    def stop(self):
        """停止所有服务"""
        self._run_cmd("docker compose down")
        for svc in self.services:
            svc.status = DeployStatus.STOPPED
        print("⏹️  所有服务已停止")

    def get_logs(self, service: str = "", tail: int = 50) -> str:
        """获取服务日志"""
        cmd = f"docker compose logs --tail {tail}"
        if service:
            cmd += f" {service}"
        return self._run_cmd(cmd)

    def show_status(self):
        """打印所有服务状态"""
        print("\n📊 服务状态:")
        for svc in self.services:
            print(f"  {svc}")

    # 1. 检查前置条件
    print("🔍 前置检查:")
    for check in deployer.check_prerequisites():
        print(f"  {check}")

    # 2. 一键部署

    deployer.show_status()

    # 3. 查看日志

    print(deployer.get_logs("llm", tail=20))

2. 安全加固

  • 不用 root 运行：RUN useradd -m appuser && USER appuser
  • Secrets 管理：用 Docker Secrets 或外部密钥管理（不写 .env）
  • 最小基础镜像：用 -slim 或 -alpine 减少攻击面
  • 固定版本：镜像标签用具体版本号，不用 latest

⚠️ 常见陷阱 Top 5 ⏱ 5min
陷阱 1：模型打包进镜像
7B 模型约 15GB，每次构建都上传一次，构建 10 分钟。用 -v 挂载模型目录，镜像只装代码。
陷阱 2：容器内网络不通
Compose 中容器间用服务名通信（http://llm:8000），不用 localhost。localhost 在容器内只指向容器自己。
陷阱 3：GPU 不可用
忘装 NVIDIA Container Toolkit，或者 docker run 忘加 --gpus all。容器内 nvidia-smi 能验证。
陷阱 4：.env 泄露密钥
.env 文件包含 API Key，必须加入 .gitignore 和 .dockerignore。用 .env.example 做模板提交。
陷阱 5：数据卷丢失
docker compose down -v 会删除数据卷（Redis 缓存、模型缓存全丢）。普通停止用 docker compose down（不带 -v）。

练习 1：多阶段构建优化 Dockerfile

改造下面臃肿的 Dockerfile，使用多阶段构建（multi-stage build）将镜像体积减少 50%+：

# 优化前的 Dockerfile（镜像约 8GB）
FROM python:3.11
RUN apt-get update && apt-get install -y gcc g++  # 编译依赖
RUN pip install torch transformers fastapi uvicorn pandas
COPY . /app
WORKDIR /app
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]

提示：builder 阶段装编译工具 + pip install，runtime 阶段只 COPY 产物，不装 gcc。
