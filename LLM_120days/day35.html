RAG 系统搭好了，但怎么知道好不好？用数据说话——从检索指标到生成指标，建立可量化的质量评估体系

🎯 为什么需要 RAG 评估？ ~8 min
类比数仓：就像你建了一张宽表，上线前要跑数据质量检查（行数突变、空值率、主键重复）一样，RAG 系统上线前也需要一套质量指标来证明"它能用且好用"。

RAG 管线有两个独立的质量环节：

  1. 检索质量—— 找回来的文档是否相关？有没有漏掉关键文档？
  2. 生成质量—— LLM 基于这些文档给出的回答是否准确、完整、有用？

两个环节都可能出错：

  • 检索错了→ LLM 基于错误的上下文，回答必然跑偏（Garbage In, Garbage Out）
  • 检索对了但生成错了→ 上下文里有答案，但 LLM 没用好、编造了信息
  • 都对了→ 才是真正可用的 RAG 系统
RAG 评估的两层拆解 Query（用户问题） │ ▼ ┌─────────────┐ ┌──────────────────────────────────┐ │ 检索环节 │ │ 生成环节 │ │ ───────── │ │ ────────── │ │ · Precision │───→│ · Faithfulness（忠实度） │ │ · Recall │ │ · Answer Relevancy（答案相关性） │ │ · MRR │ │ · Context Utilization（利用率） │ │ · Hit Rate │ │ │ └─────────────┘ └──────────────────────────────────┘ │ │ └──────────┬───────────────┘ ▼ 综合质量评分

评估的三种方式

方式怎么做优点缺点
人工标注 人工判断检索结果/答案是否正确 最准确，能发现细微问题 慢、贵、主观、难扩展
LLM-as-Judge 用另一个 LLM 来打分评判 自动、可扩展、性价比高 评判模型本身可能有偏差
自动指标 用数学公式/程序自动计算 完全客观、零成本、可 CI 集成 不能判断语义质量，只能做辅助
实战策略：先搭建自动指标做日常监控（CI 集成），再用 LLM-as-Judge 做定期深度评估，关键问题辅以人工抽检。三层结合，既高效又可靠。

2.1 itertools：组合与排列

评估时经常需要生成"所有可能的组合"来做交叉验证、A/B 测试矩阵等。

from itertools import product, combinations, permutations

# === product: 笛卡尔积（所有组合，含重复） ===
# 类比数仓：CROSS JOIN
chunk_sizes = [256, 512, 1024]
overlap_ratios = [0.1, 0.2]
top_ks = [3, 5, 10]

configs = product(chunk_sizes, overlap_ratios, top_ks)
# product 返回迭代器，用 list 查看所有组合
print(f"共 {len(list(configs))} 种参数组合")
# 共 2×3×3 = 18 种参数组合

# 用解包直接遍历，方便起名字
for chunk, overlap, k in product(chunk_sizes, overlap_ratios, top_ks):

# 对比: 催收 vs 处置

检索评估回答一个核心问题：给定的查询，系统返回的 Top-K 文档中有多少是真正相关的？

3.1 前置概念：标注集（Ground Truth）

评估的前提是有一个"标准答案"——人工标注哪些文档与哪些 Query 相关。

# 构建评估用的标注集
# 格式：query_id → 该query相关的所有文档ID集合
ground_truth = {

    "Q2": {"doc_002", "doc_005"},              # 2篇相关文档
    "Q3": {"doc_001", "doc_004", "doc_008", "doc_009"},  # 4篇相关文档
}

# 模拟检索系统返回的Top-K结果
# 格式：query_id → [按相关性排序的文档ID列表]
retrieved = {
    "Q1": ["doc_001", "doc_005", "doc_003"],  # 前2个命中，第2个不相关
    "Q2": ["doc_002", "doc_005", "doc_011"],  # 全部命中

}

3.2 Precision@K：精确率

Precision@K
= |检索结果中相关文档| / K
Top-K 结果里有多少比例是相关的？回答"准不准"
def precision_at_k(retrieved_docs, relevant_docs, k):
    """计算 Precision@K：Top-K 结果中相关文档的比例"""
    top_k = retrieved_docs[:k]
    relevant_in_topk = set(top_k) & relevant_docs  # 集合交集
    return len(relevant_in_topk) / k

# 评估 Q1
p3 = precision_at_k(retrieved["Q1"], ground_truth["Q1"], k=3)
print(f"Q1 Precision@3 = {p3:.2f}")  # 2/3 = 0.67
# 解释：返回3篇，其中doc_001和doc_003相关，precision=2/3

p5 = precision_at_k(retrieved["Q1"], ground_truth["Q1"], k=5)
print(f"Q1 Precision@5 = {p5:.2f}")  # 如果只返回3篇，补0 = 2/5 = 0.40

3.3 Recall@K：召回率

Recall@K
= |检索结果中相关文档| / |所有相关文档|
所有相关文档中，有多少被找回来了？回答"全不全"
def recall_at_k(retrieved_docs, relevant_docs, k):
    """计算 Recall@K：所有相关文档被找回的比例"""
    top_k = retrieved_docs[:k]
    relevant_in_topk = set(top_k) & relevant_docs
    # 注意：分母是所有相关文档数，不是K
    return len(relevant_in_topk) / len(relevant_docs)

# 评估 Q1
r3 = recall_at_k(retrieved["Q1"], ground_truth["Q1"], k=3)
print(f"Q1 Recall@3 = {r3:.2f}")  # 2/3 = 0.67

# Q3 的例子更能说明 recall 的意义
r3_q3 = recall_at_k(retrieved["Q3"], ground_truth["Q3"], k=3)
print(f"Q3 Recall@3 = {r3_q3:.2f}")
# Q3有4篇相关文档，Top-3只找回2篇 → recall = 2/4 = 0.50
# 即使precision不低，recall也可能很低（漏了很多）

3.4 MRR：平均倒数排名

MRR (Mean Reciprocal Rank)
MRR = mean(1/rank)，rank 是第一个相关结果的排名
第一个相关结果出现在第几位？排越前越好
def reciprocal_rank(retrieved_docs, relevant_docs):
    """计算 RR：第一个相关文档出现在第几位的倒数"""
    for i, doc in enumerate(retrieved_docs, start=1):
        if doc in relevant_docs:
            return 1.0 / i  # 第1位=1.0, 第2位=0.5, 第3位=0.33...
    return 0.0  # 没找到任何相关文档

# 评估多个query的 MRR
rrs = [
    reciprocal_rank(retrieved[q], ground_truth[q])
    for q in retrieved
]
mrr = sum(rrs) / len(rrs)
print(f"各query的RR: {rrs}")
print(f"MRR = {mrr:.3f}")
# Q1: 第1位命中 → RR=1.0
# Q2: 第1位命中 → RR=1.0
# Q3: 第1位命中 → RR=1.0

3.5 Hit Rate：命中率

def hit_rate(retrieved_docs, relevant_docs, k):
    """Top-K 中是否至少命中一篇相关文档（0 或 1）"""
    top_k = set(retrieved_docs[:k])
    return 1.0 if top_k & relevant_docs else 0.0

# 批量计算平均 Hit Rate
hits = [
    hit_rate(retrieved[q], ground_truth[q], k=5)
    for q in retrieved
]
print(f"平均 Hit Rate@5 = {mean(hits):.2f}")

3.6 指标对比总结

指标衡量什么公式适用场景
Precision@K Top-K 中相关比例 命中的 / K 关注结果质量（准不准）
Recall@K 所有相关中被找回的比例 命中的 / 总相关数 关注覆盖度（全不全）
MRR 首个相关结果的排名 mean(1/rank) 关注排序质量（排在前面吗）
Hit Rate Top-K 是否至少命中一篇 有命中=1, 无=0 关注"能不能找到"（粗粒度）
Precision vs Recall 的权衡：类似数仓中"精确去重"vs"尽量保留"的权衡。K 越大，Precision 通常下降（混入了不相关文档），Recall 通常上升（找到更多相关文档）。评估时要同时看两个指标。
✨ 生成评估指标：回答得准不准、答得好不好？ ~15 min

生成评估回答三个问题：答案是否忠实于上下文？是否与问题相关？是否利用了全部检索到的上下文？

4.1 三大核心指标

指标定义问题模板范围
Faithfulness
忠实度		 答案中的所有声明是否都能从检索上下文中找到依据 "答案的每个要点是否都能在上下文中找到？" "是否有编造的内容？" 0-1
Answer Relevancy
答案相关性		 答案与用户问题是否相关 "根据问题，这个回答是否切题？" "有没有答非所问？" 0-1
Context Utilization
上下文利用率		 检索到的上下文被利用了多少 "上下文中的关键信息是否被用到了？" "有没有被忽略的重要内容？" 0-1

4.3 RAGEvaluator 完整类

from dataclasses import dataclass, field
from statistics import mean
import json, re

@dataclass
class EvalResult:
    """单条评估结果"""
    query: str
    answer: str
    context: str
    faithfulness: float = 0.0      # 忠实度 0-1
    relevancy: float = 0.0          # 答案相关性 0-1
    context_util: float = 0.0       # 上下文利用率 0-1
    reason_faith: str = ""
    reason_rel: str = ""

    @property
    def composite_score(self):
        # 加权综合分：忠实度权重最高（防幻觉最重要）
        return (
            self.faithfulness * 0.45 +
            self.relevancy * 0.35 +
            self.context_util * 0.20
        )

@dataclass
class RAGEvaluator:
    """RAG 评估器：支持 LLM-as-Judge 和规则检测"""

    def evaluate_with_llm(
        self,
        query: str,
        answer: str,
        context: str,
        call_llm_fn=None  # 注入LLM调用函数，解耦具体API
    ) -> EvalResult:
        """用 LLM-as-Judge 评估一条 RAG 结果"""
        result = EvalResult(query=query, answer=answer, context=context)

        if call_llm_fn is None:
            # 无LLM时，使用规则做简单评估
            return self._rule_based_eval(result)

        # 调用LLM评估忠实度
        faith_resp = call_llm_fn(
            FAITHFULNESS_PROMPT.format(
                context=context, question=query, answer=answer
            )
        )
        faith_data = self._parse_llm_score(faith_resp)
        result.faithfulness = faith_data["score"] / 10.0
        result.reason_faith = faith_data.get("reason", "")

        # 调用LLM评估答案相关性
        rel_resp = call_llm_fn(
            RELEVANCY_PROMPT.format(question=query, answer=answer)
        )
        rel_data = self._parse_llm_score(rel_resp)
        result.relevancy = rel_data["score"] / 10.0
        result.reason_rel = rel_data.get("reason", "")

        # 上下文利用率：简单统计答案中引用了上下文多少关键句
        result.context_util = self._calc_context_util(context, answer)

        return result

    def _rule_based_eval(self, result: EvalResult) -> EvalResult:
        """无LLM时的规则评估（粗略但有用）"""
        # 简单启发式：答案越长越可能不忠实，越短越可能不完整
        context_len = len(result.context)
        answer_len = len(result.answer)
        # 利用率：答案长度/上下文长度的比例（越接近越好）
        ratio = min(answer_len / max(context_len, 1), 1.0)
        result.context_util = round(ratio, 2)
        # 忠实度和相关性在没有LLM时无法真正评估，标记为N/A
        result.faithfulness = -1.0
        result.relevancy = -1.0
        result.reason_faith = "需要LLM评估"
        result.reason_rel = "需要LLM评估"
        return result

    def _calc_context_util(self, context: str, answer: str) -> float:
        """计算上下文利用率：答案中出现了多少上下文关键词"""
        # 分句
        context_sentences = [s.strip() for s in context.split("。") if len(s.strip()) > 5]
        if not context_sentences:
            return 0.0
        # 统计有多少上下文句子中的关键信息出现在答案中
        used = 0
        for sent in context_sentences:
            # 提取句中的关键短语（2-4字）
            phrases = [sent[i:i+j] for j in range(2, 5)
                       for i in range(len(sent)-j+1)]
            # 如果答案中包含该句30%以上的短语，认为该句被利用
            match_count = sum(1 for p in phrases if p in answer)
            if match_count > len(phrases) * 0.3:
                used += 1
        return used / len(context_sentences)

    @staticmethod
    def _parse_llm_score(response: str) -> dict:
        """从LLM响应中解析JSON评分"""
        try:
            # 尝试直接解析
            return json.loads(response)
        except json.JSONDecodeError:
            # 尝试从文本中提取JSON块
            match = re.search(r"\{[^}]+\}", response)
            if match:
                return json.loads(match.group())
            return {"score": 5, "reason": "解析失败，默认给5分"}

    def batch_evaluate(
        self,
        eval_data: list[dict],
        call_llm_fn=None
    ) -> dict:
        """批量评估并汇总统计"""
        results = []
        for item in eval_data:
            r = self.evaluate_with_llm(
                query=item["question"],
                answer=item["answer"],
                context=item["context"],
                call_llm_fn=call_llm_fn,
            )
            results.append(r)

        # 汇总统计
        valid = [r for r in results if r.faithfulness >= 0]
        summary = {
            "total": len(results),
            "avg_faithfulness": mean(r.faithfulness for r in valid) if valid else -1,
            "avg_relevancy": mean(r.relevancy for r in valid) if valid else -1,
            "avg_context_util": mean(r.context_util for r in valid) if valid else -1,
            "avg_composite": mean(r.composite_score for r in valid) if valid else -1,
            "details": results,  # 保留明细
        }
        return summary

from dataclasses import dataclass, field, asdict
from statistics import mean
import json

@dataclass
class RetrievalEval:
    """检索评估结果"""
    query_id: str
    precision_at_3: float
    precision_at_5: float
    recall_at_3: float
    recall_at_5: float
    reciprocal_rank: float
    hit_rate_at_5: float

@dataclass
class FullRAGEval:
    """完整RAG评估（检索+生成）"""
    retrieval: RetrievalEval
    faithfulness: float
    relevancy: float
    context_util: float

    @property
    def total_score(self):
        # 检索占30%，生成占70%
        retrieval_avg = mean([
            self.retrieval.precision_at_5,
            self.retrieval.recall_at_5,
            self.retrieval.reciprocal_rank,
        ])
        generation_avg = mean([
            self.faithfulness,
            self.relevancy,
            self.context_util,
        ])
        return retrieval_avg * 0.30 + generation_avg * 0.70

def run_full_evaluation(
    test_set: list[dict],
    retriever_fn=None,      # 检索函数: (query) -> list[doc_ids]
    generator_fn=None,      # 生成函数: (query, docs) -> answer
    llm_judge_fn=None,      # LLM评判函数: (prompt) -> str
) -> dict:
    """运行完整的RAG评估流水线"""

    all_results = []

    for item in test_set:
        qid = item["query_id"]
        question = item["question"]
        relevant = set(item["relevant_docs"])

        # 1. 检索评估
        if retriever_fn:
            retrieved_docs = retriever_fn(question)
        else:
            # 模拟检索结果

            }.get(qid, [])

        ret_eval = RetrievalEval(
            query_id=qid,

            precision_at_5=precision_at_k(retrieved_docs, relevant, 5),
            recall_at_3=recall_at_k(retrieved_docs, relevant, 3),
            recall_at_5=recall_at_k(retrieved_docs, relevant, 5),
            reciprocal_rank=reciprocal_rank(retrieved_docs, relevant),
            hit_rate_at_5=hit_rate(retrieved_docs, relevant, 5),
        )

        # 2. 生成评估
        if generator_fn:
            context = "...\n".join(retrieved_docs)
            answer = generator_fn(question, context)
        else:
            answer = item.get("expected_answer", "模拟答案")
            context = "模拟上下文文档内容..."

        if llm_judge_fn:
            # 用LLM打分
            evaluator = RAGEvaluator()
            gen_result = evaluator.evaluate_with_llm(

                    "P@3": round(r.retrieval.precision_at_3, 3),
                    "P@5": round(r.retrieval.precision_at_5, 3),

                },
                "generation": {

                },

            }

    return report

⚠️ 常见陷阱 Top 5 + 最佳实践 ~6 min

常见陷阱

#陷阱症状解决方案
1 用评估集当训练集 分数虚高，换个问题就崩 严格分离训练集/验证集/测试集
2 只用一个指标 Precision 高但 Recall 低，或者反过来 至少同时看 Precision + Recall + Faithfulness
3 LLM-as-Judge 的评判模型选太弱 评分不准，波动大 用能力较强的模型做 Judge（如 GPT-4 / GLM-4）
4 标注集太小或有偏 评估结果不具代表性 至少 20+ 样本，覆盖多种题型和难度
5 只做一次性评估 改动后不知道质量是否退化 建立持续评估流程，每次改动后重新跑

最佳实践速查

RAG 评估最佳实践：
  1. 分层评估：检索（自动指标）→ 生成（LLM-as-Judge）→ 端到端（人工抽检）
  2. 持续监控：把自动指标集成到 CI/CD，每次代码变更自动跑评估
  3. 基线对比：每次改动前后都记录分数，方便回溯和对比
  4. 多维度：不要只看平均分，看分布、看分位数、看最差 case
  5. 反馈闭环：根据评估结果定位问题 → 改进 → 重新评估 → 迭代
