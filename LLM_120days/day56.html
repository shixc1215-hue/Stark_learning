1. ast.literal_eval — 安全地解析 Python 字面量

LLM 返回的 SQL 可能包含在 JSON 里，有时也可能返回 Python 字面量。ast.literal_eval 比 eval() 安全得多，它只解析字面量（字符串、数字、列表、字典等），不会执行任意代码。

import ast

# LLM 返回的数据（字符串形式的 Python 对象）
llm_output = "['SELECT * FROM assets WHERE balance > 100000', '资产余额查询']"

# ✅ 安全：literal_eval 只解析字面量
result = ast.literal_eval(llm_output)
print(type(result))  # <class 'list'>
print(result[0])      # SELECT * FROM assets WHERE balance > 100000

# ❌ 危险：eval() 会执行任意代码，千万别用！
# eval("__import__('os').system('rm -rf /')")  # 灾难性后果
💡 何时使用：当 LLM 返回的 JSON 解析失败（格式不标准），但内容是 Python 字面量时，ast.literal_eval 是安全的 fallback 方案。

2. 正则进阶 — SQL 关键词精准提取

NL2SQL 系统需要从 LLM 输出中提取 SQL 语句。正则是核心工具：

import re

# 提取 SQL 语句（处理 LLM 可能包裹的 markdown 代码块）
text = """
以下是查询 SQL：
```sql
SELECT debtor_name, SUM(balance) AS total_balance
FROM dwd.amc_asset_info
WHERE status = '不良' AND balance > 50000
GROUP BY debtor_name
ORDER BY total_balance DESC
LIMIT 10
```
"""

# 方法 1：提取 ```sql ... ``` 代码块
pattern_block = r"```sql\s*\n([\s\S]*?)\n\s*```"
match = re.search(pattern_block, text, re.IGNORECASE)
if match:
    sql = match.group(1).strip()
    print("代码块提取:", sql[:50])

# 方法 2：提取 SELECT ... FROM ... 开头的语句
pattern_select = r"(SELECT\s[\s\S]+?)(?:;|$)"
match2 = re.search(pattern_select, text, re.IGNORECASE)
if match2:
    sql2 = match2.group(1).strip()
    print("SELECT提取:", sql2[:50])

# 方法 3：识别 SQL 操作类型
def detect_sql_type(sql: str) -> str:
    """检测 SQL 语句类型"""
    sql_upper = sql.strip().upper()
    if sql_upper.startswith("SELECT"):
        return "query"
    elif sql_upper.startswith("INSERT"):
        return "insert"
    elif sql_upper.startswith("UPDATE"):
        return "update"
    elif sql_upper.startswith("DELETE"):
        return "delete"
    return "unknown"

print(detect_sql_type("SELECT * FROM table"))  # query

3. Pydantic 结构化验证 — SQL 结果模型

用 Pydantic 定义 NL2SQL 的输入/输出模型，确保类型安全和自动校验：

from pydantic import BaseModel, Field, field_validator
from typing import Optional
from enum import Enum

class SQLType(str, Enum):
    QUERY = "select"
    INSERT = "insert"
    UPDATE = "update"
    DELETE = "delete"

class NL2SQLRequest(BaseModel):
    """NL2SQL 输入模型"""
    question: str = Field(..., description="用户的自然语言问题", min_length=2)
    database: str = Field(default="amc", description="目标数据库名称")
    max_rows: int = Field(default=100, ge=1, le=10000, description="最大返回行数")

class SQLResult(BaseModel):
    """SQL 执行结果"""
    sql: str = Field(..., description="生成的 SQL 语句")
    sql_type: SQLType = Field(..., description="SQL 类型")
    columns: list[str] = Field(default_factory=list, description="列名列表")
    rows: list[dict] = Field(default_factory=list, description="查询结果行")
    row_count: int = Field(default=0, ge=0)
    error: Optional[str] = Field(default=None, description="错误信息（如有）")
    execution_time_ms: float = Field(default=0, ge=0)

    @field_validator("sql")
    @classmethod
    def sql_must_be_valid(cls, v: str) -> str:
        """校验 SQL 不为空且以合法关键字开头"""
        v = v.strip().rstrip(";")
        if not v:
            raise ValueError("SQL 不能为空")
        first_word = v.split()[0].upper()
        valid_starts = {"SELECT", "INSERT", "UPDATE", "DELETE",
                        "WITH", "CREATE", "DROP"}
        if first_word not in valid_starts:
            raise ValueError(f"SQL 必须以合法关键字开头，得到: {first_word}")
        return v

# 测试
req = NL2SQLRequest(question="查一下上月不良资产余额 TOP 10")
print(req.model_dump())

result = SQLResult(
    sql="SELECT * FROM assets LIMIT 10",
    sql_type=SQLType.QUERY,
    columns=["id", "name", "balance"],
    rows=[{"id": 1, "name": "张三", "balance": 100000}],
    row_count=1,
    execution_time_ms=45.2
)
print(result.model_dump_json(indent=2))
💡 Pydantic 校验的优势：在 NL2SQL 场景中，LLM 输出不可控。Pydantic 的 field_validator 能在数据进入下游之前拦截非法 SQL，是安全防线的关键一环。
🧠 NL2SQL 核心原理 约 15 分钟

NL2SQL 是什么？

Natural Language to SQL（NL2SQL）：把用户的自然语言问题翻译成可执行的 SQL 查询。

🗣️ "上月不良资产
余额 TOP 10 是哪些？" → 🤖 LLM + Schema
理解意图+映射字段 → 📝 SQL 输出 → ✅ 验证 + 执行

核心三要素

要素说明数仓类比
Schema 描述 告诉 LLM 有哪些表、字段、关系、业务含义 元数据字典 / 数据字典
示例问题-SQL 对 Few-shot 示例，教 LLM 你的 SQL 风格 ETL 开发规范文档
输出约束 限制 LLM 只返回 SQL，不要废话 接口规范 / SLA

Schema 描述设计 — 关键的一步

LLM 不知道你的表结构，你必须把元数据用结构化的方式喂给它。对于 AMC 业务：

# AMC 业务 Schema 描述（这就是喂给 LLM 的"数据字典"）
AMC_SCHEMA = """
## 数据库: amc_dw（AMC 资产管理公司数据仓库）

### 表: dwd.amc_asset_info（不良资产明细宽表）
| 字段名 | 类型 | 业务含义 | 示例值 |
|--------|------|----------|--------|
| asset_id | BIGINT | 资产唯一标识 | 10001 |
| debtor_name | VARCHAR(100) | 债务人名称 | '某某公司' |
| asset_type | VARCHAR(20) | 资产类型(贷款/债券/应收款) | '贷款' |
| asset_amount | DECIMAL(18,2) | 原始资产金额(元) | 500000.00 |
| balance | DECIMAL(18,2) | 当前余额(元) | 350000.00 |
| status | VARCHAR(20) | 资产状态(不良/关注/正常) | '不良' |
| province | VARCHAR(20) | 所在省份 | '浙江' |
| industry | VARCHAR(50) | 所属行业 | '制造业' |
| collect_date | DATE | 入库日期 | '2026-01-15' |
| manager_name | VARCHAR(50) | 客户经理 | '王五' |

### 表: dim.amc_debtor_dim（债务人维度表）
| 字段名 | 类型 | 业务含义 |
|--------|------|----------|
| debtor_id | BIGINT | 债务人ID |
| debtor_name | VARCHAR(100) | 债务人名称 |
| credit_rating | VARCHAR(10) | 信用评级(A/B/C/D) |
| registration_capital | DECIMAL(18,2) | 注册资本(元) |
| establish_date | DATE | 成立日期 |

### 表: dws.amc_province_summary（省份汇总表）
| 字段名 | 类型 | 业务含义 |
|--------|------|----------|
| province | VARCHAR(20) | 省份 |
| total_balance | DECIMAL(18,2) | 总余额 |
| bad_asset_count | INT | 不良资产数量 |
| avg_balance | DECIMAL(18,2) | 平均余额 |

## 业务规则:
1. '不良'状态的资产需要特别关注
2. 余额 = 尚未清偿的金额
3. TOP N 查询使用 ORDER BY ... DESC LIMIT N
4. 日期比较使用 collect_date BETWEEN 'YYYY-MM-DD' AND 'YYYY-MM-DD'
5. 金额单位默认为元，如需万元请除以10000并标注
"""
🔑 Schema 描述的黄金法则：
① 字段业务含义比字段名更重要（LLM 看不懂 zjye 但懂"不良余额"）
② 示例值帮助 LLM 理解数据格式
③ 业务规则减少 LLM 犯低级错误（比如日期格式）

Step 1: SQL 安全验证器

在任何 SQL 执行之前，必须先做安全检查——防止 LLM 生成危险 SQL：

import re
from enum import Enum
from dataclasses import dataclass

class SQLSafetyLevel(str, Enum):
    SAFE = "safe"        # 纯 SELECT，安全
    WARNING = "warning"   # 有聚合但无 LIMIT
    DANGEROUS = "dangerous" # 含写操作

@dataclass
class SQLCheckResult:
    """SQL 安全检查结果"""
    is_safe: bool
    level: SQLSafetyLevel
    issues: list[str]
    cleaned_sql: str  # 清理后的 SQL

class SQLSafetyChecker:
    """SQL 安全验证器"""

    # 禁止的操作（防止 LLM 生成破坏性 SQL）
    FORBIDDEN_KEYWORDS = {
        "DROP", "TRUNCATE", "ALTER", "GRANT",
        "REVOKE", "CREATE", "EXEC", "EXECUTE"
    }

    # 允许的表前缀（限制查询范围）
    ALLOWED_PREFIXES = ("dwd.", "dws.", "dim.", "ods.", "ads.")

    def check(self, sql: str) -> SQLCheckResult:
        """执行安全检查"""
        issues = []
        sql_upper = sql.upper().strip()

        # 1. 检查禁止操作
        for keyword in self.FORBIDDEN_KEYWORDS:
            if keyword in sql_upper:
                issues.append(f"禁止操作: {keyword}")

        # 2. 检查是否只允许 SELECT
        if not sql_upper.startswith("SELECT") and not sql_upper.startswith("WITH"):
            issues.append("仅允许 SELECT / WITH 查询")

        # 3. 检查是否缺少 LIMIT（防止全表扫描）
        if "LIMIT" not in sql_upper:
            if "COUNT(" not in sql_upper and "SUM(" not in sql_upper:
                issues.append("缺少 LIMIT，可能导致全表扫描")

        # 4. 检查子查询深度（防止过深嵌套）
        depth = sql_upper.count("SELECT")
        if depth > 3:
            issues.append(f"子查询深度 {depth} 层，建议不超过 3 层")

        # 5. 清理 SQL（去掉多余的分号和空白）
        cleaned = sql.strip().rstrip(";").strip()

        # 判断安全级别
        if not issues:
            level = SQLSafetyLevel.SAFE
        elif any("禁止" in i for i in issues):
            level = SQLSafetyLevel.DANGEROUS
        else:
            level = SQLSafetyLevel.WARNING

        return SQLCheckResult(
            is_safe=(level == SQLSafetyLevel.SAFE),
            level=level,
            issues=issues,
            cleaned_sql=cleaned
        )

# 测试安全检查器
checker = SQLSafetyChecker()

# 安全的 SQL
r1 = checker.check("SELECT debtor_name, balance FROM dwd.amc_asset_info WHERE status = '不良' LIMIT 10")
print(f"安全: {r1.is_safe}, 问题: {r1.issues}")  # 安全: True, 问题: []

# 危险的 SQL
r2 = checker.check("DROP TABLE dwd.amc_asset_info")
print(f"安全: {r2.is_safe}, 问题: {r2.issues}")  # 安全: False, 问题: ['禁止操作: DROP']

Step 2: NL2SQL Prompt 模板

高质量的 Prompt 是 NL2SQL 成功的核心。使用"Schema + Few-shot + 约束"三段式结构：

from dataclasses import dataclass, field

@dataclass
class FewShotExample:
    """Few-shot 示例对"""
    question: str
    sql: str
    explanation: str = ""  # 可选：解释 SQL 思路

@dataclass
class NL2SQLPromptBuilder:
    """NL2SQL Prompt 构建器"""

    schema_desc: str = AMC_SCHEMA  # 从上面定义的 Schema
    examples: list[FewShotExample] = field(default_factory=list)
    dialect: str = "MySQL"  # 目标 SQL 方言

    def build(self, question: str) -> str:
        """构建完整的 Prompt"""

        # 1. System 部分：角色 + 规则
        system = f"""你是一位资深的 {self.dialect} 数据库工程师，精通 AMC（资产管理公司）业务。
你的任务是将用户的自然语言问题翻译成准确的 {self.dialect} SQL 查询。

## 规则:
1. 只返回 SQL 语句，不要任何解释
2. SQL 必须语法正确，可直接执行
3. 日期格式使用 'YYYY-MM-DD'
4. 金额字段保留两位小数
5. 所有查询必须包含 LIMIT（除非是 COUNT/SUM 等聚合查询）
6. 使用别名(AS)让列名可读
7. WHERE 条件中字符串使用单引号

## 数据库 Schema:
{self.schema_desc}
"""

        # 2. Few-shot 部分：示例
        few_shot = ""
        if self.examples:
            few_shot = "\n## 示例:\n"
            for i, ex in enumerate(self.examples, 1):
                few_shot += f"\n### 示例 {i}\n"
                few_shot += f"问题: {ex.question}\n"
                few_shot += f"SQL:\n```sql\n{ex.sql}\n```\n"
                if ex.explanation:
                    few_shot += f"解析: {ex.explanation}\n"

        # 3. 用户问题
        user = f"问题: {question}\n\n请直接返回 SQL 语句（用 ```sql ``` 包裹）:"

        return system + few_shot + "\n" + user

# 构建 Few-shot 示例（这些示例决定了 LLM 生成 SQL 的风格）
examples = [
    FewShotExample(
        question="不良资产余额 TOP 10",
        sql="SELECT debtor_name AS 债务人, balance AS 余额 FROM dwd.amc_asset_info WHERE status = '不良' ORDER BY balance DESC LIMIT 10",
        explanation="筛选不良状态，按余额降序，取前10"
    ),
    FewShotExample(
        question="各省不良资产数量统计",
        sql="SELECT province AS 省份, COUNT(*) AS 不良数量, SUM(balance) AS 总余额 FROM dwd.amc_asset_info WHERE status = '不良' GROUP BY province ORDER BY 总余额 DESC",
        explanation="按省份分组，统计数量和总余额"
    ),
    FewShotExample(
        question="2026年7月新入库的制造业不良资产有哪些？",
        sql="SELECT debtor_name, asset_type, balance, collect_date FROM dwd.amc_asset_info WHERE status = '不良' AND industry = '制造业' AND collect_date BETWEEN '2026-07-01' AND '2026-07-31' ORDER BY balance DESC LIMIT 20",
        explanation="日期范围筛选 + 行业筛选"
    ),
]

# 测试 Prompt 构建
builder = NL2SQLPromptBuilder(examples=examples)
prompt = builder.build("上月客户经理王五负责的不良资产有多少？")

Step 3: NL2SQL 完整引擎

把上面的组件组装成完整引擎：

import re
import json
import ast
from dataclasses import dataclass, field
from typing import Optional

@dataclass
class NL2SQLEngine:
    """NL2SQL 引擎 — 自然语言转 SQL"""

    prompt_builder: NL2SQLPromptBuilder
    safety_checker: SQLSafetyChecker = field(default_factory=SQLSafetyChecker)

    # ---- 内部方法：调用 LLM ----
    def _call_llm(self, prompt: str) -> str:
        """调用 LLM（这里用模拟返回，实际替换为 API 调用）"""
        # 实际使用时替换为:
        # import zhipuai
        # response = zhipuai.ZhipuAI().chat.completions.create(...)

        # ====== 模拟 LLM 返回（用于演示） ======
        mock_responses = {
            "王五": """```sql
SELECT COUNT(*) AS 不良资产数量,
       SUM(balance) AS 总余额
FROM dwd.amc_asset_info
WHERE status = '不良'
  AND manager_name = '王五'
  AND collect_date BETWEEN '2026-07-01' AND '2026-07-31'
```""",
            "TOP": """```sql
SELECT debtor_name AS 债务人,
       asset_type AS 类型,
       balance AS 余额
FROM dwd.amc_asset_info
WHERE status = '不良'
ORDER BY balance DESC
LIMIT 10
```""",
        }
        for key, resp in mock_responses.items():
            if key in prompt:
                return resp
        return """```sql
SELECT * FROM dwd.amc_asset_info WHERE status = '不良' LIMIT 10
```"""

    # ---- 内部方法：从 LLM 输出中提取 SQL ----
    def _extract_sql(self, llm_output: str) -> Optional[str]:
        """从 LLM 输出中提取 SQL（三层 fallback）"""

        # 策略 1：提取 ```sql ... ``` 代码块
        pattern = r"```(?:sql)?\s*\n([\s\S]*?)\n\s*```"
        match = re.search(pattern, llm_output)
        if match:
            return match.group(1).strip()

        # 策略 2：提取 SELECT/WITH 开头的语句
        pattern2 = r"(SELECT\s[\s\S]+?)(?:;|\n\n|$)"
        match2 = re.search(pattern2, llm_output, re.IGNORECASE)
        if match2:
            return match2.group(1).strip()

        # 策略 3：尝试 ast.literal_eval（处理 Python 字面量）
        try:
            parsed = ast.literal_eval(llm_output.strip())
            if isinstance(parsed, str) and parsed.upper().startswith("SELECT"):
                return parsed
        except (ValueError, SyntaxError):
            pass

        return None

    # ---- 核心方法：query ----
    def query(self, question: str) -> SQLResult:
        """完整 NL2SQL 流水线: 问题 → Prompt → LLM → 提取 → 验证 → 执行"""

        # 1. 构建 Prompt
        prompt = self.prompt_builder.build(question)

        # 2. 调用 LLM
        # import time; start = time.perf_counter()
        llm_output = self._call_llm(prompt)

        # 3. 提取 SQL
        sql = self._extract_sql(llm_output)
        if not sql:
            return SQLResult(
                sql="", sql_type=SQLType.QUERY,
                error=f"无法从 LLM 输出中提取 SQL。原始输出: {llm_output[:200]}"
            )

        # 4. 安全检查
        check = self.safety_checker.check(sql)
        if not check.is_safe:
            return SQLResult(
                sql=sql, sql_type=SQLType.QUERY,
                error=f"SQL 安全检查未通过: {check.issues}"
            )

        # 5. 判断 SQL 类型
        first_word = check.cleaned_sql.split()[0].upper()
        sql_type = SQLType(first_word.lower())

        # 6. 执行 SQL（这里用模拟结果，实际连接数据库）
        # import time; exec_time = (time.perf_counter() - start) * 1000
        mock_columns = ["debtor_name", "balance"]
        mock_rows = [
            {"debtor_name": "某某公司A", "balance": 850000},
            {"debtor_name": "某某公司B", "balance": 620000},
        ]

        return SQLResult(
            sql=check.cleaned_sql,
            sql_type=sql_type,
            columns=mock_columns,
            rows=mock_rows,
            row_count=len(mock_rows),
            execution_time_ms=128.5
        )

# ====== 完整测试 ======
engine = NL2SQLEngine(
    prompt_builder=NL2SQLPromptBuilder(examples=examples)
)

# 测试 1

print("=== 生成 SQL ===")
print(result.sql)
print("=== 执行结果 ===")
print(f"行数: {result.row_count}, 耗时: {result.execution_time_ms}ms")
for row in result.rows:
    print(f"  {row}")

练习 3：LeetCode #49 — 字母异位词分组

用 Python 实现 LeetCode 49 题，这道题练习了 字典分组 + 排序，是 NL2SQL 中"把相似的查询归类"的思路基础：

from collections import defaultdict

def group_anagrams(strs: list[str]) -> list[list[str]]:
    """字母异位词分组"""
    groups = defaultdict(list)
    for s in strs:
        # 排序后的字符串作为 key（异位词排序后相同）
        key = "".join(sorted(s))
        groups[key].append(s)
    return list(groups.values())

# 测试
print(group_anagrams(["eat", "tea", "tan", "ate", "nat", "bat"]))
# [["eat", "tea", "ate"], ["tan", "nat"], ["bat"]]
⚠️ 常见陷阱 Top 5
#陷阱说明解法
1 Schema 描述不够详细 LLM 不知道字段含义，生成错误 SQL 每个字段都要有业务含义+示例值+业务规则
2 没有安全检查就执行 LLM 可能生成 DROP/DELETE 等危险 SQL 必须先过 SQLSafetyChecker，禁止写操作
3 Few-shot 示例太少 LLM 不了解你的 SQL 风格，生成不规范的 SQL 至少 5-10 个覆盖不同场景的示例
4 日期/金额格式不一致 LLM 返回的日期格式与数据库不匹配 在 Schema 和规则中明确指定格式
5 信任 LLM 的 SQL 直接执行 LLM 的 SQL 可能有语法错误或逻辑错误 先用 EXPLAIN 验证，再用只读账号执行
