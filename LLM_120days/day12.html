Week 2 你已经学了for 循环 + 列表 + 字典。今天学 4 个"遍历增强工具"——它们都是让 for 循环变得更强大的语法糖。在 LLM 开发中，你会频繁用到它们来处理 Prompt 列表、API 返回结果、文档数据等。

📦 1. enumerate —— 给循环加编号

一句话理解：for 循环遍历列表时，如果你需要同时知道"第几个"，就用 enumerate。

为什么需要它？看这个对比：

❌ 不用 enumerate（手写计数器，丑）
# 手动维护一个计数器变量
for i in range(len(names)):
    print(f"第{i}个人: {names[i]}")

# 麻烦！而且容易出错
✅ 用 enumerate（Pythonic 写法）
# 自动给你编号，从0开始
for i, name in enumerate(names):
    print(f"第{i}个人: {name}")

# 简洁！还支持从任意数字开始

语法拆解

# enumerate 接收一个"可迭代对象"，返回 (索引, 元素) 的配对
enumerate(可迭代对象, start=起始编号)

# 基础用法
fruits = ["苹果", "香蕉", "橙子"]

for index, fruit in enumerate(fruits):
    print(f"{index}: {fruit}")
0: 苹果 1: 香蕉 2: 橙子
# start 参数：让编号从 1 开始（更符合人类习惯）
for i, fruit in enumerate(fruits, start=1):
    print(f"第{i}种水果: {fruit}")
第1种水果: 苹果 第2种水果: 香蕉 第3种水果: 橙子

类比 SQL：enumerate 就像 SQL 的 ROW_NUMBER() OVER() 窗口函数——给每行数据自动编号。

💡 LLM 场景应用：处理 LLM 返回的候选结果列表时，经常需要编号展示给用户选择： 
# LLM 返回了 3 个备选答案，给用户标号展示
answers = ["方案A：直接出售", "方案B：债转股", "方案C：重组盘活"]

for i, ans in enumerate(answers, start=1):
    print(f"  {i}. {ans}")
1. 方案A：直接出售 2. 方案B：债转股 3. 方案C：重组盘活

📦 2. zip —— 把两个列表"拉链"到一起

一句话理解：你有两个（或多个）列表，想按位置一一对应同时遍历，就用 zip。

直觉类比：zip 就像衣服的拉链——左边一个齿、右边一个齿，一一咬合。

# 两个列表：项目名称 + 金额
names  = ["项目A", "项目B", "项目C"]
amounts = [1000, 2500, 800]

# zip 把两个列表按位置配对
for name, amount in zip(names, amounts):
    print(f"{name}: {amount}万元")
项目A: 1000万元 项目B: 2500万元 项目C: 800万元

核心规则：

  • zip 会把多个列表相同位置的元素配成一组
  • 如果两个列表长度不同，以最短的那个为准（多出来的元素被丢弃）
  • 可以 zip 两个以上的列表
# 长度不同时，以最短为准
a = [1, 2, 3]
b = ["x", "y"]      # 只有 2 个元素

for num, ch in zip(a, b):
    print(num, ch)

# 输出：1 x
#       2 y
# （3 被丢弃了，因为 b 只有 2 个）
# zip 三个列表
dates   = ["2024-01", "2024-02", "2024-03"]
regions = ["华东", "华南", "华北"]
amounts = [500, 300, 200]

for date, region, amount in zip(dates, regions, amounts):
    print(f"{date} {region}: {amount}万")
2024-01 华东: 500万 2024-02 华南: 300万 2024-03 华北: 200万

类比 SQL：zip 类似 SQL 中没有 JOIN 条件的全列一一对应（行号对行号），或者 Hive 的 LATERAL VIEW posexplode 配合行列转换。

💡 LLM 场景应用：对比不同模型的输出结果时非常有用： 
# 同一个 Prompt，发给 3 个模型
models  = ["GPT-4", "Qwen", "智谱"]
results = ["净回收率 52%", "净回收率 48%", "净回收率 51%"]

for model, result in zip(models, results):
    print(f"🤖 {model}: {result}")
🤖 GPT-4: 净回收率 52% 🤖 Qwen: 净回收率 48% 🤖 智谱: 净回收率 51%

📦 3. sorted(key=...) —— 按自定义规则排序

一句话理解：sorted() 对列表排序，key 参数告诉它"按什么规则排序"。

基础用法（你已经知道 .sort() 了，sorted() 的区别是返回新列表，不修改原列表）：

# .sort() —— 原地排序（修改原列表，不返回新值）
nums = [3, 1, 4, 1, 5]
nums.sort()            # nums 变成 [1, 1, 3, 4, 5]

# sorted() —— 返回新列表（原列表不变）
nums = [3, 1, 4, 1, 5]
new_nums = sorted(nums)   # new_nums = [1, 1, 3, 4, 5]，nums 不变

key 参数 —— 排序的核心

key 接收一个函数，这个函数作用于每个元素，返回一个"排序依据"。排序时按这个返回值排。

# === 场景 1：按字符串长度排序 ===
words = ["banana", "pie", "Washington", "book"]

# key=len：用 len() 函数计算每个元素的长度，按长度排序
by_length = sorted(words, key=len)
print(by_length)
# ['pie', 'book', 'banana', 'Washington']
#  3字符  4字符    6字符      10字符
# === 场景 2：按字典的某个字段排序（最常用！） ===
projects = [
    {"name": "项目C", "amount": 500},
    {"name": "项目A", "amount": 2000},
    {"name": "项目B", "amount": 1200},
]

# key=lambda x: x["amount"]
# 解释：lambda 是匿名函数，x 代表每个字典元素
#       x["amount"] 取出字典的 amount 字段值
#       sorted 就按这个值来排序

by_amount = sorted(projects, key=lambda x: x["amount"])

for p in by_amount:
    print(f"{p['name']}: {p['amount']}万")
项目C: 500万 项目B: 1200万 项目A: 2000万
# === 场景 3：降序排列（从大到小） ===
by_amount_desc = sorted(projects, key=lambda x: x["amount"], reverse=True)

# === 场景 4：按多个字段排序 ===
# 先按地区排，地区相同再按金额排
projects2 = [
    {"region": "华东", "amount": 500},
    {"region": "华南", "amount": 1200},
    {"region": "华东", "amount": 2000},
]

result = sorted(projects2, key=lambda x: (x["region"], x["amount"]))
# key 返回一个元组 (region, amount)
# Python 先按元组第1个元素排，相同再按第2个排
💡 LLM 场景应用：对 LLM 返回的候选答案按"置信度"或"相关性"排序： 
# LLM 返回多个候选答案，每个带一个 score
candidates = [
    {"answer": "净回收率52%", "score": 0.85},
    {"answer": "净回收率48%", "score": 0.72},
    {"answer": "净回收率55%", "score": 0.91},
]

# 按分数从高到低排
top_answer = sorted(candidates, key=lambda x: x["score"], reverse=True)
print(top_answer[0]["answer"])   # 取分数最高的
净回收率55%

📦 4. map 和 filter —— 批量转换 & 批量过滤

这两个函数是从"函数式编程"借来的，核心思想是"对列表中的每个元素做同样的操作"，而不需要写 for 循环。

map —— 批量转换

一句话：把一个函数应用到列表的每个元素，返回一个新列表。

for 循环写法
# 每个金额乘以 1.05（加 5%）
amounts = [100, 200, 300]
new_amounts = []
for a in amounts:
    new_amounts.append(a * 1.05)
map 写法（一行搞定）
# 同样的效果，一行搞定
amounts = [100, 200, 300]
new_amounts = list(map(lambda x: x * 1.05, amounts))

# [105.0, 210.0, 315.0]

语法：map(函数, 可迭代对象)。注意 map 返回的是迭代器，需要用 list() 转成列表。

# 更多 map 例子

# 例1：把字符串列表转大写
names = ["alice", "bob", "charlie"]
upper_names = list(map(str.upper, names))
# ['ALICE', 'BOB', 'CHARLIE']
# 注意：str.upper 是字符串自带的函数，不需要 lambda

# 例2：把字符串列表转整数
str_nums = ["1", "2", "3"]
int_nums = list(map(int, str_nums))
# [1, 2, 3]
# int() 是 Python 内置函数，直接传给 map

# 例3：用 lambda 自定义转换
texts = ["hello world", "foo bar"]
first_words = list(map(lambda t: t.split()[0], texts))
# ['hello', 'foo']
# 取每个字符串的第一个单词

filter —— 批量过滤

一句话：保留列表中满足条件的元素，丢弃不满足的。

for 循环写法
# 筛选金额 > 500 的项目
projects = [
    {"name": "A", "amount": 300},
    {"name": "B", "amount": 800},
    {"name": "C", "amount": 600},
]
big = []
for p in projects:
    if p["amount"] > 500:
        big.append(p)
filter 写法
# 同样的效果
big = list(filter(
    lambda p: p["amount"] > 500,
    projects
))

# filter 的函数返回 True 就保留
#           返回 False 就丢弃
💡 实际开发中的选择：
  • 列表推导式通常比 map/filter 更 Pythonic（上周学过：[x*2 for x in nums]）
  • 但 map/filter 在链式操作时更方便：先 map 转换 → 再 filter 过滤 → 再 sorted 排序，一行搞定
  • 面试可能考，实际开发中列表推导式更常用——两种都要会
# 链式操作：转换 → 过滤 → 排序，一行搞定
results = sorted(
    filter(
        lambda x: x["score"] > 0.5,    # 过滤：保留 score > 0.5 的
        map(
            lambda x: {"answer": x["text"].strip(), "score": x["score"]},  # 转换：去掉空格
            raw_results                      # 原始数据
        )
    ),
    key=lambda x: x["score"],          # 排序：按分数从低到高
    reverse=True                     # 降序
)
⚠️ 常见坑：
  • map/filter 返回的是迭代器（不是列表），只能遍历一次。如果需要多次使用，必须 list() 转换
  • list(map(...)) —— 加 list() 才能看到结果
  • lambda 里的变量名不要和外部变量重名，容易混淆

🤖 第二部分：CoT Prompt 实战 —— 让 LLM 分步推理 ⏱ 约 1.5 小时

Week 2 Day 2 你已经写过 CoT（Chain-of-Thought）Prompt 了。今天是实战深化——设计一个完整的 CoT Prompt，让 LLM 解决 AMC 业务中的多步计算问题。

🎯 今日目标：理解 CoT 为什么有效，能用 Python 编写一个完整的 CoT Prompt 程序，让 LLM 分步骤算出 AMC 净回收率。

📚 回顾：CoT 是什么？

Chain-of-Thought（思维链）：在 Prompt 中要求 LLM "一步一步想"，而不是直接给答案。

❌ Zero-shot（直接问）
# Prompt
"某AMC项目收购成本1000万，
已回收600万，处置费用80万，
净回收率是多少？"
✅ CoT（要求分步思考）
# Prompt
"某AMC项目收购成本1000万，
已回收600万，处置费用80万。
请一步一步计算净回收率。
先列出公式，再代入数据，
最后给出结果。"

为什么 CoT 有效？

  • 把一个复杂问题拆成多个简单子问题，每步都更不容易出错
  • LLM 生成中间过程时，每一步的输出都会成为下一步的"上下文"，相当于自带草稿纸
  • 对于数学计算、逻辑推理类问题，CoT 的准确率显著高于直接回答

💻 实战：用 Python 写 CoT 程序

1

定义 AMC 回收率计算的 CoT Prompt

净回收率的公式：净回收率 = (回收金额 - 处置费用) / 收购成本

# cot_amc.py —— AMC 回收率 CoT Prompt 实战

import json
from openai import OpenAI

# 初始化客户端（替换成你自己的 API Key）
client = OpenAI(api_key="your-api-key-here")

# === AMC 净回收率计算公式 ===
# 净回收金额 = 实际回收金额 - 处置费用
# 净回收率   = 净回收金额 / 收购成本
#
# 注意：这个公式是 AMC 行业的标准口径
# 对应到 SQL 就是：
# SELECT (recovery_amount - disposal_fee) / purchase_cost AS net_recovery_rate

def build_cot_prompt(purchase_cost, recovery_amount, disposal_fee):
    """
    构建 CoT Prompt，让 LLM 分步计算净回收率

    参数：
      purchase_cost  : 收购成本（万元）
      recovery_amount: 实际回收金额（万元）
      disposal_fee   : 处置费用（万元）
    """
    prompt = f"""你是一个AMC（资产管理公司）的不良资产分析专家。

请根据以下数据，一步一步计算净回收率。

## 已知数据
- 收购成本：{purchase_cost} 万元
- 实际回收金额：{recovery_amount} 万元
- 处置费用：{disposal_fee} 万元

## 计算要求
请严格按照以下步骤进行计算：

**第一步**：列出净回收率的计算公式
**第二步**：代入具体数据
**第三步**：计算净回收金额（回收金额 - 处置费用）
**第四步**：计算净回收率（净回收金额 / 收购成本）
**第五步**：给出最终结果，保留2位小数，以百分比形式呈现
**第六步**：判断回收情况（优秀 >50% / 良好 30-50% / 一般 <30%）

请按照上述步骤，逐步给出推理过程和最终答案。"""
    return prompt
💡 Prompt 设计要点：
  • 角色设定："你是一个AMC分析专家"——给 LLM 一个专业身份，输出更专业
  • 数据分块：用 ## 标题 + 列表形式组织数据，LLM 解析更准确
  • 步骤拆解：明确告诉 LLM "第一步做什么、第二步做什么"，引导推理路径
  • 格式要求：指定输出格式（保留2位小数、百分比形式），避免格式混乱
  • 业务判断：加了回收情况评级，这是你作为领域专家能加的"业务价值"

调用 LLM 并解析结果

def analyze_recovery(purchase_cost, recovery_amount, disposal_fee):
    """
    调用 LLM 进行 CoT 分析
    """
    prompt = build_cot_prompt(purchase_cost, recovery_amount, disposal_fee)

    print(f"\n{'='*60}")
    print(f"📊 AMC 项目分析")
    print(f"  收购成本: {purchase_cost}万 | 回收: {recovery_amount}万 | 费用: {disposal_fee}万")
    print(f"{'='*60}")
    print("\n🤖 LLM CoT 推理过程：\n")

    # 调用 LLM
    response = client.chat.completions.create(
        model="gpt-4o-mini",      # 或 "qwen-plus" / "glm-4-flash"
        messages=[
            {"role": "system", "content": "你是AMC行业分析专家，擅长不良资产处置和回收率分析。"},
            {"role": "user",   "content": prompt},
        ],
        temperature=0.3,             # 低温度：减少随机性，数学计算更稳定
    )

    result = response.choices[0].message.content
    print(result)

    # 统计 token 消耗
    print(f"\n📊 Token 消耗：输入 {response.usage.prompt_tokens} / 输出 {response.usage.completion_tokens}")

    return result


# === 批量分析多个项目 ===
def batch_analyze(projects):
    """批量分析多个 AMC 项目"""
    results = []

    for i, proj in enumerate(projects, start=1):  # 用 enumerate 加编号
        print(f"\n🎯 正在分析第 {i}/{len(projects)} 个项目...")
        result = analyze_recovery(
            proj["purchase_cost",
            proj["recovery_amount"],
            proj["disposal_fee"],
        )
        results.append({
            "name": proj["name"],
            "result": result,
        })

    return results


# === 运行 ===
if __name__ == "__main__":
    # 测试数据：3 个 AMC 项目
    test_projects = [
        {"name": "华东资产包A", "purchase_cost": 1000, "recovery_amount": 600, "disposal_fee": 80},
        {"name": "华南抵债资产", "purchase_cost": 2000, "recovery_amount": 900, "disposal_fee": 150},
        {"name": "华北不良包",  "purchase_cost": 5000, "recovery_amount": 1800, "disposal_fee": 300},
    ]

    results = batch_analyze(test_projects)

    # 保存结果到 JSON
    with open("cot_results.json", "w", encoding="utf-8") as f:
        json.dump(results, f, ensure_ascii=False, indent=2)
    print("\n💾 分析结果已保存到 cot_results.json")

对比实验：CoT vs Zero-shot

同一个问题，分别用 CoT 和 Zero-shot 让 LLM 回答，对比准确性和输出质量。

def compare_cot_vs_zeroshot(purchase_cost, recovery_amount, disposal_fee):
    """对比 CoT 和 Zero-shot 的输出效果"""

    # --- Zero-shot Prompt（直接问） ---
    zeroshot_prompt = f"""AMC项目收购成本{purchase_cost}万，
已回收{recovery_amount}万，处置费用{disposal_fee}万。
净回收率是多少？只给数字结果。"""

    # --- CoT Prompt（分步引导） ---
    cot_prompt = build_cot_prompt(purchase_cost, recovery_amount, disposal_fee)

💡 实验结论（你会发现的规律）：
  • CoT 准确率更高：分步计算不容易出错，特别是数字较大的复杂计算
  • CoT token 消耗更多：因为 LLM 要输出推理过程，输出 token 可能是 Zero-shot 的 3-5 倍

Week 3 的碎片知识主题是 Prompt Engineering 进阶。今天是第一个进阶技巧：Self-consistency。

💡 Self-consistency 是什么？

核心思想：让 LLM 对同一个问题生成多次答案，然后投票取多数。

为什么需要它？LLM 生成是随机的（由 temperature 控制），同一个问题每次回答可能不同。对于有唯一正确答案的问题（数学计算、逻辑推理、分类判断），多次采样取多数能显著提高准确率。

📌 图解原理

# Self-consistency 流程：
#
#  同一个问题 ──→ 第1次生成 ──→ 答案 A  ──┐
#               第2次生成 ──→ 答案 A  ──┤
#               第3次生成 ──→ 答案 B  ──┼──→ 统计：A 出现2次，B 出现1次
#               第4次生成 ──→ 答案 A  ──┤     → 最终答案：A（多数票）
#               第5次生成 ──→ 答案 B  ──┘
#
#  关键：temperature 要设高一点（0.7-1.0），让每次生成的答案有差异
🎯 CoT + Self-consistency = 黄金组合：
  • CoT：让 LLM 一步一步思考（提高单次回答的质量）
  • Self-consistency：多次思考后取多数（提高多次回答的一致性）
  • 两者结合：让 LLM 每次都分步思考，但允许路径不同，最终答案投票
  • 研究表明，CoT + Self-consistency 在数学推理任务上能再提升 5-15% 的准确率

# Self-consistency 的伪代码（理解思路）

import collections

def self_consistency(question, n_samples=5):
    """对同一个问题生成多次，取多数答案"""

    answers = []
    for i in range(n_samples):
        # 每次调用 LLM，temperature 设高一点
        response = call_llm(question, temperature=0.7)
        answer = extract_final_answer(response)  # 提取最终答案
        answers.append(answer)

    # 统计每个答案出现的次数
    counter = collections.Counter(answers)

    # 返回出现次数最多的答案
    most_common = counter.most_common(1)[0]
    return most_common

# 输出示例：
# [('52%', 3)]  →  5次中3次回答52%，最终答案52%

🟢 LeetCode #349：两个数组的交集（简单）

题目：给定两个数组 nums1 和 nums2，返回它们的交集。结果中的每个元素唯一。

示例 1：
  输入：nums1 = [1, 2, 2, 1], nums2 = [2, 2]
  输出：[2]

示例 2：
  输入：nums1 = [4, 9, 5], nums2 = [9, 4, 9, 8, 4]
  输出：[9, 4]  或 [4, 9]  （顺序不重要）

思路：把 nums1 转成集合（去重），然后遍历集合，检查每个元素是否在 nums2 的集合中。

def intersection(nums1: list[int], nums2: list[int]) -> list[int]:
    """求两个数组的交集"""
    set1 = set(nums1)    # nums1 去重：{1, 2}
    set2 = set(nums2)    # nums2 去重：{2, 8, 9, 4}

    # 两个集合取交集
    result = set1 & set2   # Python 的集合交集运算符

    return list(result)   # 转回列表：[2]

# 测试
print(intersection([1, 2, 2, 1], [2, 2]))            # [2]
print(intersection([4, 9, 5], [9, 4, 9, 8, 4]))        # [9, 4] 或 [4, 9]
💡 知识点：
  • & 是 Python 集合的交集运算符：{1,2} & {2,3} = {2}
  • 还有 | 并集、- 差集、^ 对称差集——和数学集合运算完全一样
  • 这题的另一种写法：list(set(nums1) & set(nums2))，一行搞定
  • 类比 SQL：SELECT DISTINCT a FROM t1 INTERSECT SELECT DISTINCT b FROM t2
