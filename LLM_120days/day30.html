📖 一、为什么需要 Embedding？ ⏱ 10 min

昨天我们学会了把长文档分块。分块后的问题是：用户提了一个问题，怎么从几十个 chunk 里找出最相关的？

核心矛盾：计算机只能做数学运算（加减乘除），不理解"这句话和那句话意思差不多"。我们需要一个翻译层，把文本变成数字，然后用数学算"相似度"。这个翻译层就是 Embedding。

1.1 用你的经验类比

作为数据开发工程师，你一定做过这类需求：给用户打标签，算用户相似度。传统做法：

  • 关键词匹配：用户搜"不良资产"，文档必须包含"不良资产"这四个字 —— 太死板
  • TF-IDF + 余弦相似度：按词频建向量 —— 不考虑词序和语义
  • Embedding：AI 模型理解语义后输出向量 —— "不良资产" 和 "NPL" 会很近，"资产" 和 "负债" 会很远

1.2 Embedding 是什么

Embedding 模型接收一段文本，输出一个浮点数数组（向量）。比如：

# 智谱 embedding-3 模型输出 2048 维向量
"不良资产处置方案" → [0.0231, -0.0452, 0.0873, ..., 0.0112]  # 2048个数字
"不良贷款清收流程" → [0.0228, -0.0431, 0.0856, ..., 0.0109]  # 很接近！
"红烧肉做法大全"   → [-0.156, 0.0892, -0.031, ..., 0.0734]   # 差很远！
直觉理解：你可以把这 2048 个数字想象成 2048 个"语义维度"。每个维度衡量文本的某一方面特征。语义相近的文本，在这些维度上的值会很接近。

1.3 RAG 管线中的位置

①
离线阶段（建索引）：文档 → 分块（Day29）→ 每个 chunk 调 Embedding → 存向量（Day30-31）
②
在线阶段（检索）：用户问题 → 调 Embedding → 算相似度 → Top-K（Day32）→ 拼上下文 → LLM 生成回答

💻 二、Python 基础：numpy 数组入门 ⏱ 12 min

Embedding 输出的就是 numpy 数组。先花几分钟掌握核心操作，后面算相似度会非常顺畅。

为什么用 numpy 而不是 list？numpy 数组在底层用 C 实现，支持向量化运算（不用写 for 循环），处理千维向量时速度比纯 Python 快 100 倍以上。在数据开发领域，你可以把它理解为"Python 版的 SQL 聚合"——批量操作，一条语句搞定。

🔧 三、相似度计算：余弦相似度 ⏱ 10 min

拿到两个 embedding 向量后，怎么判断它们"像不像"？最常用的是余弦相似度（Cosine Similarity）。

3.1 公式

cos(A, B) = (A · B) / (|A| × |B|)

其中：

  • A · B = 点积 = np.dot(A, B)
  • |A| = 向量 A 的模（长度）= np.linalg.norm(A)
  • 结果范围 [-1, 1]，越接近 1 越相似

3.2 直觉理解

✅ 余弦相似度

只看方向，不看长度。

向量 [1,2] 和 [10,20] 方向相同 → 相似度 = 1.0

Embedding 场景首选，因为不同长度的文本其 embedding 长度可能不同，但语义方向一致。

❌ 欧氏距离

看绝对位置差异。

[1,2] 和 [10,20] 距离很大 → 认为不相似

在推荐系统、聚类中常用，但 Embedding 场景不如余弦。

用 SQL 类比：余弦相似度就像 JOIN 条件上的模糊匹配 —— 不要求完全相等，只要求"方向一致"。欧氏距离则是要求"位置完全相同"。

3.3 代码实现

import numpy as np

def cosine_similarity(a: np.ndarray, b: np.ndarray) -> float:
    """
    计算两个向量的余弦相似度
    a, b: 一维 numpy 数组
    返回: [0, 1] 之间的浮点数，1 表示完全相同
    """
    dot_product = np.dot(a, b)                     # 点积
    norm_a = np.linalg.norm(a)                     # a 的模
    norm_b = np.linalg.norm(b)                     # b 的模

    if norm_a == 0 or norm_b == 0:                 # 防止除零
        return 0.0

    return dot_product / (norm_a * norm_b)


# --- 测试 ---
v1 = np.array([1.0, 2.0, 3.0])
v2 = np.array([1.0, 2.0, 3.0])         # 完全相同
v3 = np.array([2.0, 4.0, 6.0])         # 方向相同（2倍缩放）
v4 = np.array([-1.0, -2.0, -3.0])      # 方向相反
v5 = np.array([3.0, 2.0, 1.0])         # 不同方向

print(f"v1 vs v2（相同）: {cosine_similarity(v1, v2):.4f}")   # 1.0000
print(f"v1 vs v3（同向）: {cosine_similarity(v1, v3):.4f}")   # 1.0000
print(f"v1 vs v4（反向）: {cosine_similarity(v1, v4):.4f}")   # -1.0000
print(f"v1 vs v5（不同）: {cosine_similarity(v1, v5):.4f}")   # 0.7143

3.4 批量计算：一个查询 vs 多个文档

def batch_cosine_similarity(query: np.ndarray, docs: np.ndarray) -> list[float]:
    """
    一个查询向量 vs 多个文档向量，返回相似度列表
    query: shape (dim,)
    docs:   shape (n_docs, dim)
    """
    # docs @ query 等价于对每个 doc 做 np.dot(doc, query)
    dot_products = docs @ query

    # 归一化
    query_norm = np.linalg.norm(query)
    doc_norms = np.linalg.norm(docs, axis=1)       # 每行的模

    # 防除零
    doc_norms = np.where(doc_norms == 0, 1e-10, doc_norms)
    if query_norm == 0:
        return [0.0] * len(docs)

    return (dot_products / (doc_norms * query_norm)).tolist()


# --- 测试：从 5 个候选中找最相似的 ---
query_vec = np.array([0.8, 0.5, 0.3])          # 查询向量

doc_vectors = np.array([
    [0.9, 0.4, 0.2],     # 候选1：和查询很接近
    [0.1, 0.9, 0.3],     # 候选2：不同方向
    [0.7, 0.6, 0.4],     # 候选3：也比较接近
    [0.2, 0.1, 0.9],     # 候选4：完全不同
    [0.8, 0.5, 0.3],     # 候选5：和查询一模一样
])

similarities = batch_cosine_similarity(query_vec, doc_vectors)

# 找到 Top-3
indexed = list(enumerate(similarities))
indexed.sort(key=lambda x: x[1], reverse=True)   # 按相似度降序

print("Top-3 最相似的文档：")
for rank, (idx, sim) in enumerate(indexed[:3], 1):
    print(f"  #{rank}  文档{idx}  相似度={sim:.4f}")

# 输出：
# Top-3 最相似的文档：
#   #1  文档4  相似度=1.0000
#   #2  文档0  相似度=0.9979
#   #3  文档2  相似度=0.9868
关键点：docs @ query 用矩阵乘法一次算出所有点积，这就是 numpy 向量化的威力 —— 没有循环，底层用 BLAS 库并行计算。类比 SQL：SELECT doc_id, dot_product FROM docs ORDER BY dot_product DESC LIMIT 3。
🤖 四、LLM 实战：调用智谱 Embedding API ⏱ 15 min

理论够多了，直接上真实 API。我们用智谱的 embedding-3 模型，它输出 2048 维向量。

4.1 最简调用

import os
import requests
import numpy as np

# ============================================================
# 智谱 Embedding API 调用
# ============================================================
ZHIPU_API_KEY = os.getenv("ZHIPU_API_KEY", "your-api-key-here")
EMBEDDING_URL = "https://open.bigmodel.cn/api/paas/v4/embeddings"

def get_embedding(text: str, model: str = "embedding-3") -> np.ndarray:
    """
    调用智谱 Embedding API，返回 numpy 向量

    Args:
        text:  要嵌入的文本
        model: 模型名，embedding-3 输出 2048 维

    Returns:
        np.ndarray: shape=(2048,) 的浮点向量
    """
    resp = requests.post(
        EMBEDDING_URL,
        headers={"Authorization": f"Bearer {ZHIPU_API_KEY}"},
        json={
            "model": model,
            "input": text,          # 直接传字符串即可（也支持 list 批量）
        },
        timeout=30,
    )
    resp.raise_for_status()
    data = resp.json()

    # 响应结构：{"data": [{"embedding": [0.023, -0.045, ...], "index": 0}]}
    vector = data["data"][0]["embedding"]
    return np.array(vector, dtype=np.float32)


# --- 测试 ---
vec = get_embedding("不良资产处置方案")
print(f"维度: {vec.shape}")         # (2048,)
print(f"类型: {vec.dtype}")         # float32
print(f"前5个值: {vec[:5]}")        # 看看长什么样
print(f"模长: {np.linalg.norm(vec):.4f}")  # embedding-3 输出已归一化，模≈1
embedding-3 模型的特点：输出向量已经归一化（模长 ≈ 1.0），所以计算余弦相似度时，分母的模可以省略，点积 ≈ 余弦相似度。这大大简化了计算！

4.2 批量调用（一次传多段文本）

def get_embeddings_batch(texts: list[str], model: str = "embedding-3") -> np.ndarray:
    """
    批量调用 Embedding API（一次请求最多 2048 条）

    Args:
        texts: 文本列表
        model: 模型名

    Returns:
        np.ndarray: shape=(n, 2048) 的二维数组
    """
    resp = requests.post(
        EMBEDDING_URL,
        headers={"Authorization": f"Bearer {ZHIPU_API_KEY}"},
        json={
            "model": model,
            "input": texts,          # 传列表！
        },
        timeout=60,
    )
    resp.raise_for_status()
    data = resp.json()

    # 按原始顺序排列（API 返回的 index 可能乱序）
    results = sorted(data["data"], key=lambda x: x["index"])
    vectors = [item["embedding"] for item in results]
    return np.array(vectors, dtype=np.float32)


# --- 一次获取 4 个文本的 embedding ---
texts = [
    "不良资产处置方案",
    "不良贷款清收流程",
    "资产管理公司年度报告",
    "红烧肉做法大全",
]

vectors = get_embeddings_batch(texts)
print(f"批量结果 shape: {vectors.shape}")   # (4, 2048)

4.3 完整示例：语义搜索

def semantic_search(
    query: str,
    documents: list[str],
    top_k: int = 3,
) -> list[dict]:
    """
    语义搜索：给一个查询，从文档列表中找到最相似的 Top-K

    Args:
        query:     用户查询
        documents: 候选文档列表
        top_k:     返回前几个

    Returns:
        [{"index": int, "text": str, "score": float}, ...]
    """
    # 1. 获取查询向量和文档向量
    query_vec = get_embedding(query)                  # (2048,)
    doc_vecs  = get_embeddings_batch(documents)        # (n, 2048)

    # 2. 因为 embedding-3 已归一化，点积 = 余弦相似度
    scores = doc_vecs @ query_vec                      # (n,)

    # 3. 排序取 Top-K
    ranked = sorted(
        range(len(documents)),
        key=lambda i: scores[i],
        reverse=True,
    )[:top_k]

    return [
        {
            "rank":   rank + 1,
            "index":  idx,
            "text":   documents[idx],
            "score":  float(scores[idx]),
        }
        for rank, idx in enumerate(ranked)
    ]


# ====== 运行 ======
docs = [
    "不良资产包批量收购流程及风险控制要点",
    "2024年一季度AMC行业不良资产处置情况统计",
    "债务人资产保全与诉讼执行操作指南",
    "金融不良资产评估定价方法与实务",
    "公司食堂菜单更新通知",
    "年度员工体检安排",
]

results = semantic_search("怎么评估不良资产的价值？", docs, top_k=3)

print("🔍 语义搜索结果：\n")
for r in results:
    print(f"  #{r['rank']}  相似度={r['score']:.4f}")
    print(f"       {r['text']}")
    print()

# 预期输出：第1名应该是"金融不良资产评估定价方法与实务"
#          第2名可能是"不良资产包批量收购流程"或"AMC行业统计"

模型 维度 特点 适用场景

OpenAI text-embedding-3-small 1536（可裁剪） 英文强，支持维度裁剪 英文/多语言场景

  • 中文为主 → 智谱 embedding-3 或 bge-large-zh
  • 需要本地部署（数据不能出内网）→ bge 系列开源模型
  • 多语言 → bge-m3 或 OpenAI
  • 快速原型 → 用你已有 API Key 的那个

5.1 维度与性能的 Trade-off

# 维度越高 → 表达能力越强 → 占用存储越大 → 计算越慢
# 智谱 embedding-3 的维度裁剪（不推荐，但了解原理）

# 假设你想降低存储，可以把 2048 维截断到 1024 维
full_vec = get_embedding("测试文本")          # 2048 维
truncated = full_vec[:1024]                   # 截取前 1024 维

# 但这会损失信息！更好的方式是用支持维度裁剪的模型
# OpenAI text-embedding-3-small 支持在 API 参数中指定 dimensions：
# {"model": "text-embedding-3-small", "input": "text", "dimensions": 512}
成本估算：智谱 embedding-3 的定价是 0.5 元 / 百万 token。1000 条 200 字的 chunk ≈ 20 万字 ≈ 40 万 token ≈ 0.2 元。对数仓开发来说，embedding 成本几乎可以忽略。主要成本在 LLM 生成阶段。
⚡ 六、LLM 实战进阶：Embedding 缓存 + 可视化 ⏱ 10 min

6.1 用字典做简易 Embedding 缓存

开发调试时，同一段文本会被反复 embed。加缓存可以省 API 调用 + 省钱 + 加速。

from functools import lru_cache

# --- 方案1：lru_cache（最简单，进程内缓存）---
@lru_cache(maxsize=1024)
def get_embedding_cached(text: str) -> tuple:
    """
    带缓存的 Embedding 调用
    注意：lru_cache 要求参数可 hash，返回值也要可 hash
    所以返回 tuple 而不是 np.ndarray
    """
    resp = requests.post(
        EMBEDDING_URL,
        headers={"Authorization": f"Bearer {ZHIPU_API_KEY}"},
        json={"model": "embedding-3", "input": text},
        timeout=30,
    )
    resp.raise_for_status()
    vec = resp.json()["data"][0]["embedding"]
    return tuple(vec)     # 转 tuple 才能 cache

# 使用时转回 numpy
vec = np.array(get_embedding_cached("不良资产处置"))

# 第二次调用同一文本 → 直接命中缓存，不发请求！
vec2 = np.array(get_embedding_cached("不良资产处置"))

print(f"缓存命中: {get_embedding_cached.cache_info()}")
生产环境进阶：进程重启后 lru_cache 会丢失。生产中通常用 Redis 或 SQLite 持久化缓存。你的数仓经验在这里直接复用 —— 把 embedding 结果存一张表 embedding_cache(text_hash, vector_bytes, model, created_at)，查之前先 SELECT。

6.2 相似度矩阵可视化（纯文本版）

def similarity_matrix(texts: list[str]) -> np.ndarray:
    """计算 N 个文本两两之间的相似度矩阵"""
    vecs = get_embeddings_batch(texts)          # (n, 2048)
    # 矩阵乘法：每对文档的点积（因为已归一化 = 余弦相似度）
    sim_matrix = vecs @ vecs.T                  # (n, n)
    return sim_matrix


def print_similarity_matrix(texts: list[str], matrix: np.ndarray):
    """打印美化的相似度矩阵"""
    n = len(texts)
    # 表头
    header = f"{'':>20}" + "".join(f"  {texts[i][:6]:>6}" for i in range(n))
    print(header)

    for i in range(n):
        row = f"{texts[i][:20]:>20}"
        for j in range(n):
            row += f"  {matrix[i][j]:6.3f}"
        print(row)

7.1 陷阱 Top 5

#陷阱后果解法
1 每次查询都重新 embed 所有文档 慢到不可用（1000 文档 × 0.5s = 8 分钟） 离线预计算，文档变动时才重新 embed
2 不分块直接 embed 整篇长文档 超过 token 限制 + 语义被稀释 先分块（Day29），再逐块 embed
3 用欧氏距离代替余弦相似度 结果偏差大（向量长度干扰） Embedding 场景一律用余弦相似度
4 忽略中文分词对短文本的影响 短文本信息少，embedding 质量差 短查询加前缀提示（见下方）
5 混合不同模型的 embedding 向量空间不一致，相似度无意义 同一系统只用一个 embedding 模型

实现欧氏距离函数 euclidean_distance(a, b)，然后对同一组文本分别用余弦相似度和欧氏距离排序，观察结果差异。思考：为什么 Embedding 场景余弦更好？

# 提示
def euclidean_distance(a: np.ndarray, b: np.ndarray) -> float:
    """欧氏距离：sqrt(sum((a_i - b_i)^2))"""
    return np.sqrt(np.sum((a - b) ** 2))

# 欧氏距离越小越相似，余弦相似度越大越相似
# 注意排序方向相反！

💡 练习 3：LeetCode #268 重复 — 两个数组的交集 II

给定两个数组 nums1 和 nums2，返回它们的交集（每个元素出现次数等于在两个数组中出现的最小次数）。

# 提示：用 collections.Counter
from collections import Counter

def intersect(nums1, nums2):
    c1, c2 = Counter(nums1), Counter(nums2)
    result = []
    for num, count in c1.items():
        result.extend([num] * min(count, c2.get(num, 0)))
    return result
