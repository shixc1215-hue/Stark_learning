⏱ 一、为什么需要异步？~20 min

到目前为止，我们调用 LLM API 都是用 requests —— 同步方式。每次调用都要等服务器返回，才能继续下一步。

同步 vs 异步：想象你去餐厅点餐
• 同步：点一道菜，等菜做好了再点下一道 —— 一道一道等
• 异步：把三道菜一起下单，哪道先做好就先端上来 —— 同时等着，总时间更短

🔴 同步调用（requests）

调用API_A → 等3秒 → 拿结果A
调用API_B → 等3秒 → 拿结果B
调用API_C → 等3秒 → 拿结果C
总耗时 ≈ 9秒

🟢 异步调用（aiohttp）

同时调用 A, B, C
     A 等3秒 → 拿结果A
     B 等3秒 → 拿结果B
     C 等3秒 → 拿结果C
总耗时 ≈ 3秒

当你要对比多个 LLM 的回答、或批量处理大量文本时，异步能把速度提升好几倍。

⚡ 二、asyncio 基础：async / await~25 min
核心规则：
• async def 定义一个异步函数（又叫"协程"）
• await 表示"这里要等，但等的时候我可以去做别的事"
• asyncio.run() 启动异步程序的总入口 
# ---- 最简异步示例 ----
import asyncio

async def say_hello(name, delay):
    """模拟一个需要等待的操作"""
    print(f"开始向 {name} 问好...")
    await asyncio.sleep(delay)   # await：等 delay 秒，期间可做别的事
    print(f"向 {name} 问好完毕！")

# 启动异步程序
asyncio.run(say_hello("小明", 2))

运行结果：等待 2 秒后打印。看起来和普通函数没区别？别急，关键在并发。

# ---- 并发运行多个异步函数 ----
import asyncio

async def say_hello(name, delay):
    print(f"开始向 {name} 问好...")
    await asyncio.sleep(delay)
    print(f"{name}：问好完毕！")

async def main():
    # gather：同时启动 3 个协程，哪个先完成就先返回
    results = await asyncio.gather(
        say_hello("小明", 2),
        say_hello("小红", 1),
        say_hello("小刚", 3),
    )
    print("全部完成！")

asyncio.run(main())

输出顺序：

开始向 小明 问好...
开始向 小红 问好...    # 1秒后
开始向 小刚 问好...
小红：问好完毕！       # 1秒后最先完成
小明：问好完毕！       # 2秒后
小刚：问好完毕！       # 3秒后
全部完成！             # 总耗时≈3秒（不是6秒！）
关键理解：asyncio.gather() 的作用是同时启动多个异步任务，让它们"并行等待"。总耗时 = 最慢的那个，而不是所有加起来。
🌐 三、aiohttp：异步 HTTP 客户端~20 min
requests = 同步HTTP库，aiohttp = 异步HTTP库
aiohttp 的用法和 requests 类似，但所有操作都是 async/await 的。 
# ---- 安装 ----
# pip install aiohttp

# ---- aiohttp 基本用法 ----
import aiohttp
import asyncio

async def fetch_url(url):
    """异步获取网页内容"""
    async with aiohttp.ClientSession() as session:      # 创建会话（类似 requests.Session）
        async with session.get(url) as response:         # 异步 GET 请求
            status = response.status                     # 状态码
            text = await response.text()                 # 异步读取正文
            print(f"状态码: {status}, 内容长度: {len(text)}")
            return text

asyncio.run(fetch_url("https://httpbin.org/get"))
requests（同步）aiohttp（异步）
requests.get(url)await session.get(url)
response.textawait response.text()
response.json()await response.json()
不需要 Session 管理需要 ClientSession
注意：async with 是异步版本的 with，确保资源正确释放。每个 ClientSession 应该在整个程序中只创建一次，复用即可。
🤖 四、实战：并发调用 3 个 LLM API~30 min

现在把学到的异步知识用在 LLM 上 —— 同时调用智谱、OpenAI兼容接口，对比同一问题的回答。

# ---- 并发调用多个 LLM API ----
import aiohttp
import asyncio
import json
import time

# 配置 3 个 LLM 的 API（这里用智谱不同模型做演示）
LLM_CONFIGS = [
    {
        "name": "GLM-4-Flash",
        "url": "https://open.bigmodel.cn/api/paas/v4/chat/completions",
        "model": "glm-4-flash",
        "key": "YOUR_ZHIPU_KEY"  # 替换为你的智谱API Key
    },
    {
        "name": "GLM-4-Air",
        "url": "https://open.bigmodel.cn/api/paas/v4/chat/completions",
        "model": "glm-4-air",
        "key": "YOUR_ZHIPU_KEY"
    },
    {
        "name": "GLM-4-Long",
        "url": "https://open.bigmodel.cn/api/paas/v4/chat/completions",
        "model": "glm-4-long",
        "key": "YOUR_ZHIPU_KEY"
    },
]

PROMPT = "请用3句话解释：什么是数据仓库的ODS层？"

async def call_llm(session, config, prompt):
    """异步调用单个 LLM API"""
    headers = {
        "Authorization": f"Bearer {config['key']}",
        "Content-Type": "application/json"
    }
    payload = {
        "model": config["model"],
        "messages": [{"role": "user", "content": prompt}],
        "temperature": 0.7,
    }
    
    start = time.time()
    async with session.post(config["url"], headers=headers, json=payload) as resp:
        data = await resp.json()
        elapsed = time.time() - start
        
        # 提取回答文本
        answer = data["choices"][0]["message"]["content"]
        tokens = data.get("usage", {}).get("total_tokens", "N/A")
        
        return {
            "model": config["name"],
            "answer": answer,
            "tokens": tokens,
            "time": round(elapsed, 2),
        }

async def compare_llms(prompt):
    """并发调用3个LLM，收集结果"""
    async with aiohttp.ClientSession() as session:
        # gather 同时调用所有模型
        results = await asyncio.gather(
            call_llm(session, LLM_CONFIGS[0], prompt),
            call_llm(session, LLM_CONFIGS[1], prompt),
            call_llm(session, LLM_CONFIGS[2], prompt),
        )
    
    # 打印对比结果
    print(f"问题: {prompt}\n")
    for r in results:
        print(f"--- {r['model']} ---")
        print(f"回答: {r['answer']}")
        print(f"Token数: {r['tokens']}, 耗时: {r['time']}秒\n")
    
    return results

# 运行
asyncio.run(compare_llms(PROMPT))
运行效果：3 个模型同时接收请求，总耗时 ≈ 最慢的那个（比如 3 秒），而不是 3+2+4=9 秒。
实际应用：你可以对比不同模型对 AMC 不良资产处置方案的分析质量，选出最适合的模型。
🔒 五、异步超时与错误处理~15 min
# ---- 加超时和异常处理的并发调用 ----
import aiohttp
import asyncio

async def call_llm_safe(session, config, prompt, timeout=10):
    """带超时和异常处理的LLM调用"""
    try:
        # asyncio.wait_for：给单次调用设超时
        result = await asyncio.wait_for(
            call_llm(session, config, prompt),
            timeout=timeout  # 超过10秒就放弃这个模型
        )
        return result
    except asyncio.TimeoutError:
        return {"model": config["name"], "error": "超时", "answer": None}
    except Exception as e:
        return {"model": config["name"], "error": str(e), "answer": None}

async def compare_llms_safe(prompt):
    async with aiohttp.ClientSession() as session:
        results = await asyncio.gather(
            call_llm_safe(session, LLM_CONFIGS[0], prompt),
            call_llm_safe(session, LLM_CONFIGS[1], prompt),
            call_llm_safe(session, LLM_CONFIGS[2], prompt),
            return_exceptions=False  # 即使某个出错，其他继续
        )
    
    for r in results:
        if r.get("error"):
            print(f"⚠ {r['model']}: {r['error']}")
        else:
            print(f"✅ {r['model']}: 耗时{r['time']}秒")
    
    return results
生产环境必做：
• asyncio.wait_for() — 单个任务超时控制
• try/except — 单个任务的异常隔离
• return_exceptions=False — gather 不会因为一个失败而全部中断

❓ 自测题

Q1：await asyncio.sleep(2) 和 time.sleep(2) 的区别是什么？

提示：前者在等待时可以让其他协程运行，后者会阻塞整个线程

Q2：为什么 aiohttp 需要 ClientSession，而 requests 不需要？

提示：Session 可以复用连接池，减少重复建立 TCP 连接的开销

Q3：asyncio.gather 和 asyncio.wait_for 分别解决什么问题？

提示：gather 负责并发，wait_for 负责超时

💬 常见问题
Q：asyncio 能加速 CPU 密集型计算吗？
不能。asyncio 只能加速IO密集型任务（网络请求、文件读写等）。CPU计算还是同步执行的。如果需要并行计算，应该用 multiprocessing。
Q：能在同步函数里调用异步函数吗？
不能直接调用。异步函数必须用 asyncio.run() 或在已有的异步上下文中 await。反过来，异步函数里可以调用同步函数，但会阻塞 —— 可以用 asyncio.to_thread() 把同步函数放到线程里执行。
Q：gather 里某个任务失败了怎么办？
设置 return_exceptions=True，失败的任务会返回异常对象而不是抛出。这样其他任务不受影响。或者给每个任务加 try/except，返回统一格式的结果。
