核心问题：Day 17 学了 requests 调 LLM API，每次调用要等 3~5 秒。如果要调 10 次，串行就是 30~50 秒。能不能让它们同时跑？

生活中的类比：做饭

🍳同步（串行）做法：烧水 → 等 10 分钟 → 水开了 → 切菜 → 炒菜 → 等 15 分钟。每步等上一步完成，总耗时 25+ 分钟。

⚡异步（并发）做法：点火烧水 → 同时切菜 → 水开了开始煮面 → 面煮着的同时炒菜。总耗时可能只要 15 分钟。

关键区分：
• 并发(concurrency)：多个任务交替推进，看起来同时在做（单核也能做到）
• 并行(parallelism)：多个任务真正同时执行（需要多核 CPU）
• asyncio 是 并发，适合 I/O 密集型任务（网络请求、文件读写、数据库查询）
• 多线程/多进程适合 CPU 密集型任务（数值计算、模型推理）

代码对比：同步 vs 异步

import time
import asyncio

# ====== 同步版本：一个一个等 ======
def fetch_data_sync(name, seconds):
    """模拟一个耗时的 API 请求"""
    print(f"  [{name}] 开始请求...")
    time.sleep(seconds)          # 💀 线程阻塞在这里，什么都不做
    print(f"  [{name}] 返回结果")
    return f"{name}的结果"

def sync_main():
    start = time.time()
    r1 = fetch_data_sync("用户画像", 3)  # 等 3 秒
    r2 = fetch_data_sync("风险评估", 2)  # 再等 2 秒
    r3 = fetch_data_sync("报表摘要", 4)  # 再等 4 秒
    print(f"同步总耗时: {time.time()-start:.1f}s  结果: {[r1,r2,r3]}")
# 输出: 同步总耗时: 9.0s

# ====== 异步版本：同时跑 ======
async def fetch_data_async(name, seconds):
    """async def 定义协程函数，await 等待 I/O"""
    print(f"  [{name}] 开始请求...")
    await asyncio.sleep(seconds)    # ✅ 协程挂起，让出控制权，不阻塞线程
    print(f"  [{name}] 返回结果")
    return f"{name}的结果"

async def async_main():
    start = time.time()
    # 三件事同时开始，总耗时 ≈ 最慢的那个(4秒)
    results = await asyncio.gather(
        fetch_data_async("用户画像", 3),
        fetch_data_async("风险评估", 2),
        fetch_data_async("报表摘要", 4),
    )
    print(f"异步总耗时: {time.time()-start:.1f}s  结果: {results}")
# 输出: 异步总耗时: 4.0s  ⚡ 快了 2.25 倍！
💡 数据开发视角：你写 ETL 时，从 Hive 拉数据（等 30s）、调 LLM 生成摘要（等 5s）、写入 MySQL（等 2s）——这些全是 I/O 等待，用异步可以让拉数据和生成摘要同时进行。
🧩 ② asyncio 基础四件套 12 min

1. Event Loop（事件循环）——异步的"大脑"

Event Loop 是 asyncio 的调度中心。它不断检查：哪些协程准备好了？哪些在等 I/O？安排谁先执行。 
import asyncio

async def say_hello():
    print("Hello!")
    await asyncio.sleep(1)
    print("World!")

# 运行异步代码的两种方式：
# 方式1: asyncio.run() —— 最常用，自动创建和管理 event loop
asyncio.run(say_hello())

# 方式2: 手动管理（在 Jupyter / FastAPI 中常用）
loop = asyncio.new_event_loop()
asyncio.set_event_loop(loop)
try:
    loop.run_until_complete(say_hello())
finally:
    loop.close()

2. Coroutine（协程）——异步函数

# 定义协程：async def
async def my_coroutine():
    """这就是一个协程函数"""
    return "协程的结果"

# ⚠️ 注意：直接调用协程函数不会执行！
coro = my_coroutine()       # 返回一个协程对象，但还没执行
print(type(coro))            # <class 'coroutine'>
print(coro)                   # <coroutine object my_coroutine at 0x...>

# 必须用 await 或 asyncio.run() 来执行
result = asyncio.run(my_coroutine())   # "协程的结果"
⚠️ 新手必踩的坑：写了 async def 但忘记 await，结果协程根本没执行。记住：async 定义，await 驱动。

3. await —— 挂起与恢复

import asyncio
import random

async def fetch_llm_response(prompt):
    """模拟 LLM API 调用"""
    # await 后面必须是"可等待对象"(awaitable)：协程 / Task / Future
    delay = random.uniform(1, 3)
    await asyncio.sleep(delay)       # 挂起，让 event loop 去跑别的协程
    return f"对'{prompt[:10]}...'的回答(耗时{delay:.1f}s)"

async def main():
    # 串行 await：一个接一个
    r1 = await fetch_llm_response("分析这笔不良资产的风险")
    r2 = await fetch_llm_response("生成本月AMC报表摘要")
    # r2 必须等 r1 完成才开始 → 串行，没利用并发优势

asyncio.run(main())

4. Task —— 把协程"发射"出去

import asyncio

async def process_report(report_id):
    await asyncio.sleep(2)
    return f"报表{report_id}处理完成"

async def main():
    # asyncio.create_task() 立即调度协程，返回 Task 对象
    # 不等它完成，继续往下走
    task1 = asyncio.create_task(process_report("R001"))  # 立刻开始跑
    task2 = asyncio.create_task(process_report("R002"))  # 立刻开始跑
    task3 = asyncio.create_task(process_report("R003"))  # 立刻开始跑

    # 等它们全部完成
    result1 = await task1
    result2 = await task2
    result3 = await task3
    print(result1, result2, result3)

asyncio.run(main())

⚡ ③ 并发执行实战：gather / create_task / Semaphore 15 min

方式一：asyncio.gather() —— 最常用

import asyncio
import time

async def call_llm(prompt, model):
    """模拟不同模型的 API 调用"""
    delay = {"gpt": 3, "deepseek": 2, "glm": 1.5}[model]
    await asyncio.sleep(delay)
    return f"[{model}] {prompt[:15]}... → 回答"

async def batch_compare():
    """并发调用 3 个模型对比回答"""
    prompts = ["解释不良资产处置流程", "SQL优化建议"]
    models = ["gpt", "deepseek", "glm"]

    start = time.time()
    tasks = []
    for p in prompts:
        for m in models:
            tasks.append(call_llm(p, m))    # 创建协程（注意：不是 create_task）

    # gather 自动并发执行所有协程，按顺序返回结果
    results = await asyncio.gather(*tasks)
    elapsed = time.time() - start

    print(f"共 {len(results)} 次调用，总耗时 {elapsed:.1f}s")
    for r in results:
        print(f"  {r}")
    # 6次调用，串行需要 6+3+3+3+1.5+1.5 = 18s
    # 并发只需 ≈ max(3,2,1.5,3,2,1.5) ≈ 3s  ⚡

asyncio.run(batch_compare())

方式二：asyncio.create_task() —— 需要中途处理的场景

import asyncio

async def analyze_report(report_id):
    """模拟报表分析"""
    await asyncio.sleep(1)
    if report_id % 3 == 0:
        raise ValueError(f"报表{report_id}数据异常")
    return f"报表{report_id}分析完成"

async def main():
    report_ids = [1, 2, 3, 4, 5]
    tasks = [asyncio.create_task(analyze_report(rid)) for rid in report_ids]

    # 可以逐个 await，哪个先完成就先拿结果
    for i, task in enumerate(tasks):
        try:
            result = await task
            print(f"✅ {result}")
        except ValueError as e:
            print(f"❌ 任务失败: {e}")

asyncio.run(main())

方式三：Semaphore —— 限制并发数（防过载）

为什么需要限流？大多数 API 有并发限制（如 5 QPS）。如果同时发 100 个请求，会被限流甚至封禁。asyncio.Semaphore 就像"限行令牌"，控制同时运行的协程数量。 
import asyncio

async def call_api_with_semaphore(prompt, semaphore, index):
    """带限流的 API 调用"""
    async with semaphore:                  # 获取信号量，超过限制就排队
        print(f"[{index}] 开始: {prompt[:12]}...")
        await asyncio.sleep(2)             # 模拟 API 延迟
        return f"结果{index}"

async def main():
    prompts = [f"问题{i}" for i in range(20)]  # 20 个请求
    semaphore = asyncio.Semaphore(5)           # 最多同时 5 个

    # 所有任务一起创建，但信号量控制同时只有 5 个在跑
    tasks = [
        asyncio.create_task(call_api_with_semaphore(p, semaphore, i))
        for i, p in enumerate(prompts)
    ]
    results = await asyncio.gather(*tasks)
    print(f"完成 {len(results)} 个请求")

asyncio.run(main())
# 20个请求，每个2秒，但5个并发 → 总耗时 ≈ 20/5 * 2 = 8秒（而非串行的40秒）
💡 gather vs create_task 选择指南：
• gather：适合"一批任务一起发，全部完成后统一处理"（最常用）
• create_task：适合"先发出去，中途需要单独处理每个结果"
• 两者可以混合使用：先 create_task，最后 gather 等全部完成

Step 1: aiohttp 基础用法

import asyncio
import aiohttp
import json

async def call_zhipu_api(prompt, api_key):
    """用 aiohttp 异步调用智谱 API"""
    url = "https://open.bigmodel.cn/api/paas/v4/chat/completions"
    headers = {"Authorization": f"Bearer {api_key}"}
    payload = {
        "model": "glm-4-flash",       # 免费模型
        "messages": [{"role": "user", "content": prompt}],
        "temperature": 0.3,
    }

    # ✅ 用 async with 创建 ClientSession（复用连接池）
    async with aiohttp.ClientSession() as session:
        async with session.post(url, headers=headers, json=payload) as resp:
            if resp.status == 200:
                data = await resp.json()          # await 读取响应体
                return data["choices"][0]["message"]["content"]
            else:
                error_text = await resp.text()
                raise Exception(f"API 错误 {resp.status}: {error_text}")

asyncio.run(call_zhipu_api("你好", "your-api-key"))

Step 2: 批量并发 —— 批量生成 AMC 报表摘要

import asyncio
import aiohttp
import time
import os

API_KEY = os.getenv("ZHIPU_API_KEY", "your-key-here")
MAX_CONCURRENT = 3  # 控制并发数，避免触发限流

async def generate_summary(session, report_name, semaphore):
    """为单个报表生成 LLM 摘要"""
    async with semaphore:
        url = "https://open.bigmodel.cn/api/paas/v4/chat/completions"
        headers = {"Authorization": f"Bearer {API_KEY}"}
        payload = {
            "model": "glm-4-flash",
            "messages": [{
                "role": "user",
                "content": f"请用2句话总结以下AMC报表的核心指标和风险点：{report_name}"
            }],
            "temperature": 0.2,
        }
        try:
            async with session.post(url, headers=headers, json=payload) as resp:
                data = await resp.json()
                summary = data["choices"][0]["message"]["content"]
                print(f"  ✅ {report_name}: {summary[:50]}...")
                return {"report": report_name, "summary": summary, "status": "ok"}
        except Exception as e:
            print(f"  ❌ {report_name}: {e}")
            return {"report": report_name, "error": str(e), "status": "error"}

async def batch_summarize_reports():
    """批量处理所有报表"""
    reports = [
        "2026Q1_不良资产处置报表",
        "2026Q1_风险分类变动表",
        "2026Q1_抵债资产明细表",
        "2026Q1_拨备覆盖率分析",
        "2026Q1_债务人集中度分析",
        "2026Q1_诉讼进展跟踪表",
    ]
    semaphore = asyncio.Semaphore(MAX_CONCURRENT)

    start = time.time()
    async with aiohttp.ClientSession() as session:
        tasks = [
            asyncio.create_task(generate_summary(session, r, semaphore))
            for r in reports
        ]
        results = await asyncio.gather(*tasks)

    elapsed = time.time() - start
    print(f"\n📊 处理完成: {len(results)} 份报表，总耗时 {elapsed:.1f}s")

    # 统计成功/失败
    ok = sum(1 for r in results if r["status"] == "ok")
    fail = sum(1 for r in results if r["status"] == "error")
    print(f"   成功: {ok}  失败: {fail}")

asyncio.run(batch_summarize_reports())

Step 3: 超时控制 + 重试机制

import asyncio
import aiohttp

async def call_llm_with_retry(session, prompt, max_retries=3, timeout=10):
    """带超时和重试的 LLM 调用"""
    url = "https://open.bigmodel.cn/api/paas/v4/chat/completions"
    headers = {"Authorization": f"Bearer {API_KEY}"}
    payload = {
        "model": "glm-4-flash",
        "messages": [{"role": "user", "content": prompt}],
    }

    for attempt in range(1, max_retries + 1):
        try:
            # aiohttp.ClientTimeout 设置超时
            timeout_obj = aiohttp.ClientTimeout(total=timeout)
            async with session.post(
                url, headers=headers, json=payload,
                timeout=timeout_obj
            ) as resp:
                data = await resp.json()
                return data["choices"][0]["message"]["content"]

        except asyncio.TimeoutError:
            print(f"  ⏰ 第{attempt}次超时，{timeout}s 内无响应")
            if attempt < max_retries:
                wait = 2 ** attempt  # 指数退避: 2s, 4s, 8s
                print(f"     等待 {wait}s 后重试...")
                await asyncio.sleep(wait)

        except aiohttp.ClientError as e:
            print(f"  🌐 网络错误: {e}")
            if attempt < max_retries:
                await asyncio.sleep(2 ** attempt)

    return None  # 全部重试失败
💡 生产环境关键参数：
• 并发数：免费 API 建议 ≤ 3，付费 API 看文档（通常 5~20）
• 超时：LLM 生成通常 10~30s，建议设 60s
• 重试：指数退避（1s, 2s, 4s...），最多 3 次
• Session：整个批次共用一个 ClientSession，复用 TCP 连接
🚨 ⑤ 异步陷阱与最佳实践 5 min

陷阱 1：在 async 函数里写阻塞操作

import asyncio
import time

async def bad_example():
    """❌ 错误：time.sleep() 会阻塞整个 event loop"""
    time.sleep(5)          # 💀 整个程序卡住 5 秒，其他协程也无法运行
    return "done"

async def good_example():
    """✅ 正确：asyncio.sleep() 只挂起当前协程"""
    await asyncio.sleep(5)  # ✅ 让出控制权，其他协程继续运行
    return "done"
⚠️ 哪些操作会阻塞？time.sleep() / requests.get() / open().read() / input() / os.system()。
如果必须用阻塞库，用 asyncio.to_thread(sync_func, args) 把它扔到线程池里。

陷阱 2：忘记 await

async def wrong():
    """❌ 协程被创建了但没有被执行"""
    task = asyncio.create_task(some_async_work())  # 创建了
    # 💀 忘记 await task，main 函数结束时 task 被取消
    print("done")

async def right():
    """✅ 必须等待结果"""
    task = asyncio.create_task(some_async_work())
    result = await task   # 等它完成
    print(f"done: {result}")

陷阱 3：混用同步和异步

import asyncio

# ❌ 错误：在 async 函数里直接调用同步的 requests
async def fetch():
    import requests
    resp = requests.get("https://api.example.com")  # 💀 阻塞！

# ✅ 正确方式 1：换成 aiohttp
async def fetch():
    import aiohttp
    async with aiohttp.ClientSession() as s:
        async with s.get("https://api.example.com") as resp:
            return await resp.text()

# ✅ 正确方式 2：实在没法换库时，用 to_thread
async def fetch():
    import requests
    resp = await asyncio.to_thread(requests.get, "https://api.example.com")
    return resp.text

练习 2：LeetCode #1114 — 按序打印（asyncio 版）

用三个协程分别打印 "first"、"second"、"third"，必须按序执行。提示：asyncio.Event

import asyncio

async def first(event2):
    print("first")
    event2.set()             # 通知 second 可以开始了

async def second(event2, event3):
    await event2.wait()      # 等 first 完成
    print("second")
    event3.set()             # 通知 third 可以开始了

async def third(event3):
    await event3.wait()      # 等 second 完成
    print("third")

async def main():
    event2 = asyncio.Event()
    event3 = asyncio.Event()
    # 三个协程同时启动，但 Event 控制执行顺序
    await asyncio.gather(
        first(event2),
        second(event2, event3),
        third(event3),
    )
    print("done")

asyncio.run(main())

📋 Day 24 要点回顾

  • 异步 vs 同步：异步通过协程挂起/恢复实现并发，适合 I/O 密集型任务（网络请求、数据库、文件）
  • 四件套：Event Loop（调度中心）+ Coroutine（async def）+ await（挂起）+ Task（并发载体）
  • asyncio.gather() 是最常用的并发方式，"一起发，一起收"
  • Semaphore 限制并发数，防止 API 限流
  • aiohttp 是异步 HTTP 客户端，替代同步的 requests
  • 三大陷阱：阻塞操作(time.sleep)、忘记 await、混用同步库
  • 生产必备：超时控制 + 指数退避重试 + 共享 Session
