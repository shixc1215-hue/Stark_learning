🧠 为什么需要微调？ ⏱ 10 min
核心问题：通用大模型（如 Qwen、ChatGLM）什么都懂一点，但在你的专业领域（AMC不良资产管理、招标数据）可能经常"瞎说"。微调就是让模型在你的业务数据上"专项训练"，学会你的行话、规范和推理方式。

回忆一下我们之前的 RAG 系统——它通过检索外部知识来回答问题。但 RAG 有局限：

场景RAG 能力微调 能力
查询外部知识库中的事实✅ 擅长⚠️ 不适合（无法记忆新事实）
学会特定领域的术语和表达⚠️ 靠Prompt引导✅ 擅长（内化到模型参数）
掌握特定格式输出（JSON/报表）⚠️ 不稳定✅ 擅长（形成稳定的输出模式）
理解特定推理逻辑（风控评估）⚠️ 需要Few-Shot✅ 擅长（学会推理链路）
降低API成本（小模型替代大模型）❌ 无法✅ 可以（微调小模型→性能接近大模型）
数仓类比：微调就像在数仓中建立 ADS 层——将 DWD/DWS 的原始数据聚合、沉淀为业务直接可用的指标。微调把通用的模型"原始参数"沉淀为"业务专用参数"，让你的领域知识直接内嵌到模型里。

全量微调 vs LoRA

❌ 全量微调 (Full Fine-Tuning)

  • 更新模型所有参数
  • 7B 模型 ≈ 140亿参数
  • 显存需求：~28GB（FP32）
  • 训练数据：数千到数万条
  • 容易灾难性遗忘（忘了通用能力）
  • 存储：每套数据一个完整模型副本

✅ LoRA (Low-Rank Adaptation)

  • 只训练少量附加参数
  • 7B 模型 LoRA ≈ 几百万参数
  • 显存需求：~8-12GB（Consumer GPU）
  • 训练数据：几百到几千条即可
  • 不易遗忘（原始参数冻结）
  • 存储：几十MB 的 adapter 文件
📐 LoRA 原理：低秩分解 ⏱ 15 min
直觉理解：一个 7B 模型有几十层，每层都有巨大的权重矩阵 W（比如 4096×4096）。LoRA 的核心洞察是：微调时权重的变化量 ΔW 其实可以用一个低秩矩阵来近似——不需要满秩的 4096×4096 变化，rank=8 的 4096×8 + 8×4096 就够了。

数学直觉（不需要推导，理解思想即可）

原始权重矩阵 W：shape = (d_out, d_in) = (4096, 4096) = 1677万参数 全量微调：直接修改 W → 需要更新 1677万个参数 LoRA 微调：冻结 W，新增两个小矩阵 W_new = W + ΔW ΔW = B × A 其中 A: (r, d_in), B: (d_out, r) 当 r(rank) = 8 时： A = (8, 4096) = 32,768 参数 B = (4096, 8) = 32,768 参数 总计 = 65,536 参数（仅为原来的 0.39%！） 前向传播：y = W·x + B·A·x 原始推理 LoRA适配 训练时：W 冻结 ❄️，只更新 A 和 B ✏️ 推理时：可以合并 W' = W + B×A，零额外延迟

Python 知识：矩阵运算回顾 (numpy)

理解 LoRA 需要基本的矩阵运算。我们用 numpy 验证上面的思路：

import numpy as np

# 模拟一个"注意力权重矩阵"
# 真实场景中 d_model=4096，这里用小维度演示
d_in, d_out = 64, 64
rank = 8  # LoRA rank

# 原始权重（预训练好的，冻结不动）
W = np.random.randn(d_out, d_in).astype(np.float32)
print(f"原始权重 W: {W.shape}, 参数量: {W.size}")
# 原始权重 W: (64, 64), 参数量: 4096

# LoRA 的两个低秩矩阵
# A 用高斯初始化（很小的值），B 初始化为 0
A = np.random.randn(rank, d_in).astype(np.float32) * 0.01  # (8, 64)
B = np.zeros((d_out, rank), dtype=np.float32)           # (64, 8)

print(f"LoRA A: {A.shape}, LoRA B: {B.shape}")
print(f"LoRA 总参数量: {A.size + B.size} (原始的 {(A.size+B.size)/W.size:.1%})")
# LoRA A: (8, 64), LoRA B: (64, 8)
# LoRA 总参数量: 1024 (原始的 25.0%)
# 注：真实 4096 维度下比例是 0.39%，这里维度小所以比例高

# 模拟输入
x = np.random.randn(d_in, 1).astype(np.float32)

# 原始输出
y_original = W @ x

# LoRA 输出
y_lora = B @ (A @ x)

# 合并输出
y_new = W @ x + B @ (A @ x)

print(f"原始输出形状: {y_original.shape}")
print(f"LoRA 调整量幅度: {np.abs(y_lora).mean():.6f}")
# B 初始化为0，所以初期 LoRA 输出为0，训练后才有变化
关键初始化：B 初始化为全零矩阵，A 用小的随机值。这意味着训练开始时 LoRA 的贡献是 0，模型行为和原始预训练模型完全一样。随着训练推进，B 和 A 逐渐学到有用的变化量。

Python 知识：dataclass 进阶 + type hint 复用

from dataclasses import dataclass, field
from typing import Optional

@dataclass
class LoRAConfig:
    """LoRA 超参数配置"""
    rank: int = 8              # 低秩维度，越大表达能力越强但参数越多
    alpha: float = 16.0         # 缩放因子，通常设为 rank 的 2 倍
    dropout: float = 0.05        # LoRA 层的 dropout，防止过拟合
    target_modules: list[str] = field(default_factory=list)
    # 要应用 LoRA 的模块名，如 ["q_proj", "v_proj"]
    bias: str = "none"          # "none"/"all"/"lora_only"
    task_type: Optional[str] = None  # "CAUSAL_LM" 等

    # 计算缩放因子（只读属性）
    @property
    def scaling(self) -> float:
        return self.alpha / self.rank

# 使用
cfg = LoRAConfig(rank=8, target_modules=["q_proj", "v_proj"])
print(f"LoRA 缩放因子: {cfg.scaling}")  # 2.0
alpha 参数的含义：实际 LoRA 输出 = (alpha/rank) × B×A×x。alpha 控制微调的"力度"。当 alpha = rank 时，缩放因子 = 1；通常 alpha = 2×rank，缩放因子 = 2。这不是越大越好——太大会破坏原始模型的知识。
🔧 PEFT 库实战：5 分钟上手 LoRA ⏱ 15 min
PEFT (Parameter-Efficient Fine-Tuning) 是 Hugging Face 的库，把 LoRA/QLoRA 等参数高效微调方法封装成了几行代码。核心思路：加载预训练模型 → 包装成 PEFT 模型 → 正常训练 → 只保存 LoRA 权重。

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, TaskType

# === 1. 量化配置（QLoRA: 4bit 量化 + LoRA） ===
# 普通笔记本显存有限，用 4bit 量化把模型压缩到原来的 1/4
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,            # 4bit 量化加载
    bnb_4bit_quant_type="nf4",     # NF4 量化类型（正态分布数据最优）
    bnb_4bit_compute_dtype=torch.float16,  # 计算时用 float16
    bnb_4bit_use_double_quant=True, # 二次量化进一步压缩
)

# === 2. 加载 tokenizer ===
model_name = "Qwen/Qwen2.5-1.5B"  # 1.5B 小模型，适合学习
tokenizer = AutoTokenizer.from_pretrained(model_name, trust_remote_code=True)
tokenizer.pad_token = tokenizer.eos_token  # 设置 padding token

# === 3. 加载模型（4bit 量化） ===
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    quantization_config=bnb_config,
    device_map="auto",             # 自动分配设备
    trust_remote_code=True,
)

# === 4. LoRA 配置 ===
lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,       # 因果语言模型
    r=8,                                # LoRA rank
    lora_alpha=16,                       # 缩放因子
    lora_dropout=0.05,                   # Dropout
    target_modules=["q_proj", "v_proj"],  # 只对注意力 Q/V 做 LoRA
    bias="none",
)

# === 5. 应用 LoRA（包装模型） ===
model = get_peft_model(model, lora_config)

# 查看可训练参数
model.print_trainable_parameters()
# trainable params: 1,572,864 || all params: 1,545,851,392
# trainable%: 0.1017%
# 仅仅 0.1% 的参数需要训练！
target_modules 怎么选？
  • q_proj, v_proj：最经典、效果稳定，适合入门
  • q_proj, k_proj, v_proj, o_proj：覆盖全部注意力层，效果更好
  • q_proj, v_proj, k_proj, o_proj, gate_proj, up_proj, down_proj：覆盖 MLP 层，最强但显存需求增大
小数据量（<1000条）建议只用 q_proj+v_proj，数据充足时再扩展。
⚡ 训练 LoRA 模型 ⏱ 10 min 
from transformers import TrainingArguments, Trainer, DataCollatorForSeq2Seq

# === 1. Tokenize 数据集 ===
def tokenize_function(examples):
    """将文本转为 token ID 序列"""
    return tokenizer(
        examples["text"],
        truncation=True,
        max_length=512,      # 最长 512 tokens，足够术语解释
        padding=False,     # 动态 padding 由 collator 处理
    )

tokenized_dataset = dataset.map(tokenize_function, batched=True)

# === 2. 训练参数 ===
training_args = TrainingArguments(
    output_dir="./lora_output",
    num_train_epochs=3,            # 训练 3 轮（小数据集可以多轮）
    per_device_train_batch_size=2,  # 每卡 batch size
    gradient_accumulation_steps=4,  # 梯度累积（等效 batch=8）
    learning_rate=2e-4,            # LoRA 推荐学习率：1e-4 到 5e-4
    lr_scheduler_type="cosine",  # 余弦退火学习率
    warmup_ratio=0.1,             # 10% 步数做 warmup
    logging_steps=10,
    save_strategy="epoch",       # 每轮保存
    fp16=True,                 # 半精度训练加速
    optim="paged_adamw_8bit",   # 8bit Adam 优化器省显存
    report_to="none",            # 不上传 wandb
)

# === 3. 数据整理器 ===
data_collator = DataCollatorForSeq2Seq(
    tokenizer=tokenizer,
    padding=True,
    return_tensors="pt",
)

# === 4. 创建 Trainer 并训练 ===
trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_dataset,
    data_collator=data_collator,
)

print("🚀 开始 LoRA 微调训练...")
trainer.train()

# === 5. 保存 LoRA 权重（只有几十MB！） ===
model.save_pretrained("./lora_amc_terminology")
tokenizer.save_pretrained("./lora_amc_terminology")
print("✅ LoRA 权重已保存到 ./lora_amc_terminology")

    model_name,
    quantization_config=bnb_config,
    device_map="auto",
    trust_remote_code=True,
)

# 叠加 LoRA adapter
model = PeftModel.from_pretrained(base_model, "./lora_amc_terminology")

# === 测试生成 ===
def generate_answer(instruction, input_text, max_new_tokens=200):
    """使用微调后的模型生成回答"""
    prompt = (
        f"### Instruction:\n{instruction}\n\n"
        f"### Input:\n{input_text}\n\n"
        f"### Response:\n"
    )

    inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
    outputs = model.generate(
        **inputs,
        max_new_tokens=max_new_tokens,
        temperature=0.3,    # 低温度，输出更确定性
        top_p=0.9,
        do_sample=True,
        pad_token_id=tokenizer.eos_token_id,
    )

    # 只解码新生成的部分（去掉 prompt）
    new_tokens = outputs[0][inputs["input_ids"].shape[1]:]
    return tokenizer.decode(new_tokens, skip_special_tokens=True)

  • 不合并（推荐调试）：LoRA 权重独立加载，可以随时换不同的 adapter，方便 A/B 测试
  • 合并后部署：用 merge_and_unload() 把 LoRA 融入原始权重，推理时零额外延迟
📊 LoRA 核心参数调优指南 ⏱ 5 min
参数推荐值影响调优建议
r (rank) 8 ~ 64 表达能力 ↑ 显存 ↑ 入门用8；数据多/任务复杂用16-32；极复杂任务用64
alpha r × 2 微调力度 ↑ 通常 = 2 × rank；太大→遗忘通用能力；太小→学不到新知识
lora_dropout 0.05 ~ 0.1 正则化 数据少(<500)用0.1；数据多(>1000)用0.05或0
target_modules q,v → q,k,v,o → +mlp 覆盖面 ↑ 效果 ↑ 显存 ↑ 从小到大逐步添加，每加一组观察效果
learning_rate 1e-4 ~ 5e-4 收敛速度 LoRA 用比全量微调更大的学习率（全量一般1e-5）
epochs 1 ~ 5 训练充分度 小数据多轮(3-5)；大数据少轮(1-3)；配合 early stopping
微调数据黄金法则：
  • 质量 > 数量：100条高质量数据 > 1000条噪声数据
  • 多样性：覆盖各种提问方式和边界情况
  • 一致性：output 格式、术语、风格保持统一
  • 最少数据：LoRA 通常 500-1000 条就能看到明显效果
🚨 常见陷阱 Top 5
  1. 灾难性遗忘 — LoRA alpha 太大或 rank 太高时，模型可能"忘了"通用能力
    对策：alpha/rank 保持 1~2 之间；用原始模型测试通用问题是否退化
  2. 过拟合 — 7条数据训练50轮，loss归零但输出无意义
    对策：保留验证集监控；数据量 < 100 时 epochs 不要超过 3
  3. 数据格式错乱 — 微调数据的格式和推理时 prompt 格式不一致
    对策：训练和推理用完全相同的 template
  4. target_modules 漏选 — 只对 q_proj 做 LoRA，效果很差
    对策：至少选 q_proj + v_proj（这是最稳定的组合）
  5. 学习率过高 — loss 震荡不收敛
    对策：LoRA 用 2e-4 起步，配合 cosine scheduler + warmup
