🏗️ 在线问答 Pipeline 架构总览 ⏱ 10min

昨天（Day 50）我们完成了 离线索引管线：文档加载 → 分块 → Embedding → 向量存储。今天构建 在线问答管线——用户提问时，系统实时检索相关知识，让 LLM 基于真实数据生成回答。

数仓类比：离线索引 = ETL 批量加工（ODS→DWD），在线问答 = ADS 即席查询（用户提问 → 检索 → 汇总 → 返回结果）。两者共用同一张向量库，就像数仓的 ADS 层复用 DWD/DWS。

完整管线流程

1
用户提问 (Query)
接收用户自然语言问题，做基础清洗（去首尾空白、截断过长输入）
2
Query Embedding
将用户问题向量化（调用与索引阶段相同的 Embedding 模型，保证语义空间一致）
3
向量检索 (Retrieval)
从 ChromaDB 中按相似度召回 Top-K 个文档块，支持元数据过滤
4
重排序 (Reranking)
用 Cross-Encoder 对召回结果精排，筛选最相关的 Top-N
5
上下文组装 (Context Assembly)
将精排后的文档块拼接成 Prompt 中的参考上下文，控制 Token 预算
6
LLM 生成 (Generation)
将 Prompt（System + Context + Question）发给 LLM，生成最终回答（支持流式逐字输出）

今日目标

  1. 实现 Python 生成器与异步生成器（流式输出的核心机制）
  2. 构建 QueryPipeline 完整在线问答管线
  3. 实现流式输出（SSE 格式），让用户实时看到回答
  4. 封装为 FastAPI 接口，提供完整的 RAG 问答服务
🐍 Python 知识：生成器（Generator）与 yield ⏱ 20min

流式输出的核心是 生成器——一个能"暂停-恢复"的函数，每次 yield 产出一个值，调用方逐个消费。

2.1 基础生成器：yield vs return

# yield 会"暂停"函数，保留局部状态，下次调用时从暂停处继续
# return 直接结束函数，销毁所有局部状态

def count_to_three():
    """一个简单的生成器：逐个产出 1, 2, 3"""
    print("  开始生成...")
    yield 1          # 暂停在这里，把 1 给调用方
    print("  继续生成...")
    yield 2          # 恢复后继续，把 2 给调用方
    print("  最后一个...")
    yield 3          # 把 3 给调用方
    print("  生成结束")

# 使用方式：用 for 循环消费
for num in count_to_three():
    print(f"收到: {num}")
# 输出:
#   开始生成...
# 收到: 1
#   继续生成...
# 收到: 2
#   最后一个...
# 收到: 3
#   生成结束
生成器的本质：调用生成器函数不会立即执行代码，而是返回一个 generator 对象。只有调用 next() 或用 for 迭代时，代码才会一步步执行到下一个 yield。

2.2 yield from：委托给子生成器

# yield from 可以将一个生成器的产出"透传"给外层
# 类似于 SQL 的 UNION ALL，把多个查询结果合并

def source_a():
    yield "ODS 层数据"
    yield "DWD 层数据"

def source_b():
    yield "DWS 层数据"
    yield "ADS 层数据"

def all_sources():
    """用 yield from 委托给子生成器"""
    yield from source_a()   # 透传 source_a 的所有产出
    yield from source_b()   # 透传 source_b 的所有产出

2.3 生成器表达式：一行搞定

# 生成器表达式 vs 列表推导式：把 [] 换成 ()
# 内存占用：列表推导一次性加载全部到内存，生成器逐个产出

# 列表推导——立即计算，占用 O(n) 内存
chunks_list = [f"chunk_{i}" for i in range(100000)]  # 占内存

# 生成器表达式——惰性计算，O(1) 内存
chunks_gen = (f"chunk_{i}" for i in range(100000))   # 不占内存

print(next(chunks_gen))  # "chunk_0"
print(next(chunks_gen))  # "chunk_1"
# 生成器用完即弃，适合大数据流式处理

2.4 异步生成器：async def + yield（LLM 流式的核心）

import asyncio

async def mock_llm_stream(prompt: str):
    """模拟 LLM 流式输出：逐 token 产出"""
    # 模拟 LLM 一词一词生成
    tokens = prompt.split()  # 简化：按空格拆分
    for token in tokens:
        await asyncio.sleep(0.05)  # 模拟网络延迟
        yield token

# 异步消费方式 1：async for
async def main():
    async for token in mock_llm_stream("不良资产 清收 管理流程"):
        print(token, end=" ", flush=True)

asyncio.run(main())
# 输出: 不良资产 清收 管理流程 （逐个出现）

2.5 生成器的数据类型注解

from collections.abc import Generator, AsyncGenerator

def chunk_documents(docs: list[str]) -> Generator[str, None, None]:
    """同步生成器注解: Generator[YieldType, SendType, ReturnType]"""
    for doc in docs:
        yield doc[:100]  # 每次产出截断后的文本

async def stream_response(
    prompt: str
) -> AsyncGenerator[str, None]:
    """异步生成器注解: AsyncGenerator[YieldType, SendType]"""
    for word in prompt:
        await asyncio.sleep(0.01)
        yield word
记忆技巧：生成器 = 会暂停的函数。yield 是暂停键，next() / for 是恢复键。yield from 是遥控器（委托子生成器）。加 async 就变成异步版，适合 LLM 流式场景。
🔍 Step 1-2：Query Embedding + 向量检索 ⏱ 15min

在线问答的第一步：把用户的问题变成向量，然后在向量库中搜索最相似的文档块。

3.1 QueryPreprocessor：问题预处理

from dataclasses import dataclass, field
from typing import Optional


@dataclass
class QueryResult:
    """单个检索结果"""
    chunk_id: str           # 文档块 ID
    text: str               # 文档块内容
    score: float            # 相似度分数
    source: str            # 来源文件名
    metadata: dict = field(default_factory=dict)


@dataclass
class RetrievalResult:
    """检索阶段的完整输出"""
    query: str                          # 原始问题
    query_embedding: list[float]        # 问题向量
    candidates: list[QueryResult]       # 召回的候选文档块
    total_retrieved: int                # 总召回数量
    latency_ms: float                   # 检索耗时（毫秒）


class QueryPreprocessor:
    """问题预处理：清洗 + 长度检查"""

    MAX_QUERY_LENGTH = 500  # 最大问题长度（字符数）

    @classmethod
    def process(cls, query: str) -> str:
        """清洗用户问题"""
        # 1. 去首尾空白
        cleaned = query.strip()

        # 2. 合并连续空格（类似 SQL 的 TRIM + REPLACE）
        while "  " in cleaned:
            cleaned = cleaned.replace("  ", " ")

        # 3. 截断过长输入（防止超出 Embedding 模型的 token 限制）
        if len(cleaned) > cls.MAX_QUERY_LENGTH:
            cleaned = cleaned[: cls.MAX_QUERY_LENGTH]

        # 4. 空问题检查
        if not cleaned:
            raise ValueError("问题不能为空")

        return cleaned

3.2 ChromaRetriever：向量检索器

import time
import chromadb
from dataclasses import dataclass


@dataclass
class RetrieverConfig:
    """检索器配置"""
    collection_name: str = "amc_docs"
    chroma_path: str = "./chroma_db"
    top_k: int = 10             # 初始召回数量（粗排）
    score_threshold: float = 0.3  # 最低相似度阈值
    rerank_top_n: int = 5       # 重排后保留数量（精排）


class ChromaRetriever:
    """基于 ChromaDB 的向量检索器"""

    def __init__(self, config: RetrieverConfig, embedder=None):
        self.config = config
        self.embedder = embedder  # Day50 的 ZhipuEmbedder
        # 连接已有的 ChromaDB（离线索引阶段创建的）
        self.client = chromadb.PersistentClient(path=config.chroma_path)
        self.collection = self.client.get_collection(config.collection_name)

    def retrieve(self, query: str) -> RetrievalResult:
        """执行向量检索"""
        start_time = time.perf_counter()

        # Step 1: 预处理问题
        cleaned_query = QueryPreprocessor.process(query)

        # Step 2: 生成问题向量
        # 必须使用与索引阶段相同的 Embedding 模型！
        query_embedding = self.embedder.embed([cleaned_query])[0]

        # Step 3: 从 ChromaDB 检索
        results = self.collection.query(
            query_embeddings=[query_embedding],
            n_results=self.config.top_k,
            include=["documents", "metadatas", "distances"]
        )

        # Step 4: 解析结果 + 过滤低分项
        candidates = []
        for i in range(len(results["ids"][0])):
            distance = results["distances"][0][i]
            # Chroma 返回的是距离，需转为相似度分数
            # L2 距离 → 相似度：score = 1 / (1 + distance)
            score = 1 / (1 + distance)

            if score >= self.config.score_threshold:
                candidates.append(QueryResult(
                    chunk_id=results["ids"][0][i],
                    text=results["documents"][0][i],
                    score=score,
                    source=results["metadatas"][0][i].get("source", "unknown"),
                    metadata=results["metadatas"][0][i],
                ))

        latency = (time.perf_counter() - start_time) * 1000

        return RetrievalResult(
            query=cleaned_query,
            query_embedding=query_embedding,
            candidates=candidates,
            total_retrieved=len(candidates),
            latency_ms=latency,
        )
关键注意：embedder 必须与离线索引阶段使用 完全相同 的模型和参数。不同模型产出的向量在不同的语义空间中，无法互查——就像你不能用 MySQL 的排序规则去查 SQL Server 的数据。
📊 Step 3：Reranker 重排序 ⏱ 10min

向量检索（Bi-Encoder）速度快但精度有限。Reranker（Cross-Encoder）对 Query 和候选文档做 精细的交叉注意力计算，把 Top-10 精排到 Top-5。

4.1 CrossEncoderReranker 实现

import json
import requests
from dataclasses import dataclass


@dataclass
class RerankResult:
    """重排后的单个结果"""
    chunk_id: str
    text: str
    rerank_score: float       # 重排分数（0~1）
    original_score: float     # 原始检索分数
    source: str


@dataclass
class RerankOutput:
    """重排阶段的完整输出"""
    query: str
    results: list[RerankResult]
    top_n: int
    latency_ms: float


class CrossEncoderReranker:
    """
    基于 Cross-Encoder 的重排器
    原理：将 query + document 拼接后，模型做交叉注意力打分
    类比：Bi-Encoder = SQL WHERE 粗筛，Cross-Encoder = 人工审核精排
    """

    def __init__(self, api_key: str, model: str = "BAAI/bge-reranker-v2-m3"):
        self.api_key = api_key
        self.model = model
        self.api_url = "https://api.siliconflow.cn/v1/rerank"

    def rerank(
        self,
        query: str,
        candidates: list[QueryResult],
        top_n: int = 5,
    ) -> RerankOutput:
        """对候选文档重排序"""
        import time
        start = time.perf_counter()

        if not candidates:
            return RerankOutput(
                query=query, results=[], top_n=top_n, latency_ms=0
            )

        # 准备重排 API 的输入
        documents = [c.text for c in candidates]

        payload = {
            "model": self.model,
            "query": query,
            "documents": documents,
            "top_n": top_n,
        }

        headers = {
            "Authorization": f"Bearer {self.api_key}",
            "Content-Type": "application/json",
        }

        # 调用重排 API
        resp = requests.post(
            self.api_url,
            json=payload,
            headers=headers,
            timeout=10,
        )
        resp.raise_for_status()
        data = resp.json()

        # 解析重排结果
        results = []
        for item in data["results"]:
            idx = item["index"]  # 在 candidates 中的原始索引
            results.append(RerankResult(
                chunk_id=candidates[idx].chunk_id,
                text=candidates[idx].text,
                rerank_score=item["relevance_score"],
                original_score=candidates[idx].score,
                source=candidates[idx].source,
            ))

        latency = (time.perf_counter() - start) * 1000

        return RerankOutput(
            query=query,
            results=results,  # 已经按 rerank_score 降序排列
            top_n=top_n,
            latency_ms=latency,
        )
性能建议：Cross-Encoder 比向量检索慢 10-50 倍（因为它要做交叉注意力），所以只对 Top-10~20 的粗排结果做精排，而不是对全库做。就像数仓中先用索引定位到 100 条，再人工审核 top 5。
📝 Step 4：上下文组装 + Prompt 构建 ⏱ 10min

重排后的 Top-N 文档块需要组装成 Prompt 中的"参考资料"部分。关键问题是 Token 预算控制——不能把太多文档塞进 Prompt，否则会超出模型的上下文窗口或降低回答质量。

5.1 ContextAssembler：上下文组装器

from dataclasses import dataclass


@dataclass
class QAContext:
    """组装好的问答上下文"""
    query: str                   # 用户问题
    context_text: str            # 组装后的上下文文本
    sources: list[str]            # 来源文件列表
    total_chunks: int            # 使用的文档块数量
    total_chars: int             # 上下文总字符数
    truncated: bool              # 是否因 Token 预算截断


class ContextAssembler:
    """上下文组装器：将重排结果拼接成 Prompt 参考资料"""

    def __init__(self, max_context_chars: int = 3000):
        """
        Args:
            max_context_chars: 上下文最大字符数
                3000 字符 ≈ 1000 中文字 ≈ 1500 tokens（中文 1 字≈0.5 token）
                剩余 token 留给 system prompt + question + 回答空间
        """
        self.max_context_chars = max_context_chars

    def assemble(
        self,
        query: str,
        rerank_results: list[RerankResult],
    ) -> QAContext:
        """组装上下文"""
        # 按重排分数降序排列（API 已排好，但保险起见再排一次）
        sorted_results = sorted(
            rerank_results, key=lambda r: r.rerank_score, reverse=True
        )

        context_parts = []
        sources = []
        total_chars = 0
        truncated = False

        for result in sorted_results:
            chunk_text = result.text
            # 检查加入后是否超出预算
            if total_chars + len(chunk_text) > self.max_context_chars:
                truncated = True
                break
            context_parts.append(chunk_text)
            sources.append(result.source)
            total_chars += len(chunk_text)

        # 用分隔符拼接
        context_text = "\n\n---\n\n".join(context_parts)

        return QAContext(
            query=query,
            context_text=context_text,
            sources=list(dict.fromkeys(sources)),  # 去重保序
            total_chunks=len(context_parts),
            total_chars=total_chars,
            truncated=truncated,
        )

⚡ Step 5：LLM 流式生成器 ⏱ 15min

普通 LLM 调用：发送请求 → 等待 → 一次返回全部文本。
流式调用：发送请求 → LLM 逐 token 生成 → 每个 token 实时推送给用户。

6.1 同步流式生成器

import requests
import json


class ZhipuStreamGenerator:
    """智谱 GLM 流式生成器"""

    def __init__(self, api_key: str, model: str = "glm-4-flash"):
        self.api_key = api_key
        self.model = model
        self.api_url = "https://open.bigmodel.cn/api/paas/v4/chat/completions"

    def generate(
        self,
        messages: list[dict],
        temperature: float = 0.3,
    ) -> Generator[str, None, None]:
        """
        流式生成回答（同步生成器）

        Args:
            messages: [{"role": "system/user/assistant", "content": "..."}]
            temperature: 0=确定性, 1=创造性

        Yields:
            逐个产出的文本片段
        """
        headers = {
            "Authorization": f"Bearer {self.api_key}",
            "Content-Type": "application/json",
        }

        payload = {
            "model": self.model,
            "messages": messages,
            "temperature": temperature,
            "stream": True,  # 关键：开启流式
        }

        # 注意：stream=True 让 requests 逐块读取响应
        resp = requests.post(
            self.api_url,
            json=payload,
            headers=headers,
            stream=True,
            timeout=60,
        )
        resp.raise_for_status()

        for line in resp.iter_lines():
            if not line:
                continue

            line = line.decode("utf-8")

            # SSE 格式：以 "data: " 开头
            if line.startswith("data: "):
                data_str = line[6:]  # 去掉 "data: " 前缀

                if data_str == "[DONE]":
                    break  # 流结束

                try:
                    data = json.loads(data_str)
                    delta = data["choices"][0].get("delta", {})
                    content = delta.get("content", "")
                    if content:
                        yield content  # 产出一段文本
                except (json.JSONDecodeError, KeyError, IndexError):
                    continue  # 跳过格式错误

    def generate_full(self, messages: list[dict]) -> str:
        """非流式：收集全部文本后返回（用于测试/日志）"""
        return "".join(self.generate(messages))

6.2 异步流式生成器

import aiohttp
import asyncio
from collections.abc import AsyncGenerator


class AsyncZhipuStreamGenerator:
    """异步版本的流式生成器（适合 FastAPI 接口）"""

    def __init__(self, api_key: str, model: str = "glm-4-flash"):
        self.api_key = api_key
        self.model = model
        self.api_url = "https://open.bigmodel.cn/api/paas/v4/chat/completions"

    async def generate(
        self,
        messages: list[dict],
        temperature: float = 0.3,
    ) -> AsyncGenerator[str, None]:
        """异步流式生成"""
        headers = {
            "Authorization": f"Bearer {self.api_key}",
            "Content-Type": "application/json",
        }

        payload = {
            "model": self.model,
            "messages": messages,
            "temperature": temperature,
            "stream": True,
        }

        async with aiohttp.ClientSession() as session:
            async with session.post(
                self.api_url,
                json=payload,
                headers=headers,
                timeout=aiohttp.ClientTimeout(total=60),
            ) as resp:
                async for line in resp.content:
                    line = line.decode("utf-8").strip()

                    if line.startswith("data: "):
                        data_str = line[6:]

                        if data_str == "[DONE]":
                            break

                        try:
                            data = json.loads(data_str)
                            delta = data["choices"][0].get("delta", {})
                            content = delta.get("content", "")
                            if content:
                                yield content
                        except (json.JSONDecodeError, KeyError, IndexError):
                            continue
为什么要异步? FastAPI 是异步框架，同步生成器会 阻塞 整个事件循环。一个用户提问时，其他用户的请求会排队等待。异步生成器让多个用户的流式请求并发执行，就像餐厅的多名厨师同时做菜。

现在把所有组件串起来，构建一个完整的在线问答管线。

from dataclasses import dataclass, field
from typing import Optional
from collections.abc import AsyncGenerator
import asyncio


@dataclass
class PipelineConfig:
    """RAG 问答管线配置"""
    # 检索器配置

@dataclass
class QAAnswer:
    """问答结果"""
    query: str                     # 用户问题
    answer: str                    # 完整回答
    sources: list[str]             # 引用来源
    context_chunks: int            # 使用了多少个文档块
    context_chars: int             # 上下文总字符数
    retrieval_latency_ms: float   # 检索耗时
    rerank_latency_ms: float       # 重排耗时
    generation_latency_ms: float  # 生成耗时
    total_latency_ms: float        # 总耗时


class RAGQueryPipeline:
    """RAG 在线问答管线（全流程串联）"""

    def __init__(
        self,
        config: PipelineConfig,
        embedder,           # Day50 的 ZhipuEmbedder
        reranker,           # CrossEncoderReranker
        llm_generator,      # AsyncZhipuStreamGenerator
    ):
        self.config = config
        self.embedder = embedder
        self.reranker = reranker
        self.llm_generator = llm_generator

        # 初始化各组件
        retriever_config = RetrieverConfig(
            collection_name=config.collection_name,
            chroma_path=config.chroma_path,
            top_k=config.top_k,
            score_threshold=config.score_threshold,
        )
        self.retriever = ChromaRetriever(retriever_config, embedder)
        self.assembler = ContextAssembler(config.max_context_chars)

    async def query(self, question: str) -> QAAnswer:
        """非流式问答：返回完整回答"""
        import time
        total_start = time.perf_counter()

        # Step 1: 预处理 + 检索
        retrieval_result = self.retriever.retrieve(question)
        retrieval_ms = (time.perf_counter() - total_start) * 1000

        if not retrieval_result.candidates:
            return QAAnswer(
                query=question,
                answer="未找到相关资料，请尝试换个问法。",
                sources=[],
                context_chunks=0,
                context_chars=0,
                retrieval_latency_ms=retrieval_ms,
                rerank_latency_ms=0,
                generation_latency_ms=0,
                total_latency_ms=retrieval_ms,
            )

        # Step 2: 重排序
        rerank_start = time.perf_counter()
        rerank_output = self.reranker.rerank(
            question,
            retrieval_result.candidates,
            top_n=self.config.rerank_top_n,
        )
        rerank_ms = (time.perf_counter() - rerank_start) * 1000

        # Step 3: 组装上下文
        qa_context = self.assembler.assemble(question, rerank_output.results)

        # Step 4: 构建 Prompt
        messages = [
            {"role": "system", "content": PromptTemplate.SYSTEM_PROMPT},
            {"role": "user", "content": PromptTemplate.build(qa_context)},
        ]

        # Step 5: LLM 生成（收集全部）
        gen_start = time.perf_counter()
        full_answer = await self._generate_full(messages)
        gen_ms = (time.perf_counter() - gen_start) * 1000

        total_ms = (time.perf_counter() - total_start) * 1000

        return QAAnswer(
            query=question,
            answer=full_answer,
            sources=qa_context.sources,
            context_chunks=qa_context.total_chunks,
            context_chars=qa_context.total_chars,
            retrieval_latency_ms=retrieval_ms,
            rerank_latency_ms=rerank_ms,
            generation_latency_ms=gen_ms,
            total_latency_ms=total_ms,
        )

    async def query_stream(
        self, question: str
    ) -> AsyncGenerator[str, None]:
        """流式问答：逐 token 产出"""
        # Step 1-3 同上（检索 + 重排 + 组装）
        retrieval_result = self.retriever.retrieve(question)

        if not retrieval_result.candidates:
            yield "未找到相关资料，请尝试换个问法。"
            return

        rerank_output = self.reranker.rerank(
            question,
            retrieval_result.candidates,
            top_n=self.config.rerank_top_n,
        )
        qa_context = self.assembler.assemble(question, rerank_output.results)

        messages = [
            {"role": "system", "content": PromptTemplate.SYSTEM_PROMPT},
            {"role": "user", "content": PromptTemplate.build(qa_context)},
        ]

        # Step 5: 流式生成——直接 yield 给调用方
        async for token in self.llm_generator.generate(messages):
            yield token

    async def _generate_full(self, messages: list[dict]) -> str:
        """收集流式输出的全部内容"""
        parts = []
        async for token in self.llm_generator.generate(messages):
            parts.append(token)
        return "".join(parts)
设计亮点：query() 和 query_stream() 共用前三个步骤（检索→重排→组装），只在 LLM 生成环节分叉。前者的 Step 5 收集全部 token 后返回 QAAnswer；后者直接 yield 给调用方（FastAPI SSE）。

    return QuestionResponse(

@app.post("/api/v1/chat/stream")
async def chat_stream(req: QuestionRequest):
    """SSE 流式问答"""
    # SSE 格式：每行 "data: {json}\n\n"
    async def event_generator():
        try:
            async for token in pipeline.query_stream(req.question):
                # SSE 要求：每条消息以 "data: " 开头，两个换行结尾
                yield f"data: {json.dumps({'content': token})}\n\n"

            # 发送结束信号
            yield "data: [DONE]\n\n"
        except Exception as e:
            yield f"data: {json.dumps({'error': str(e)})}\n\n"

    return StreamingResponse(
        event_generator(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "X-Accel-Buffering": "no",  # 防止 Nginx 缓冲
        },
    )


@app.get("/api/v1/health")

⚠️ 常见陷阱 Top 5 ⏱ 3min
陷阱 1：Embedding 模型不一致
离线索引用 model-A，在线检索用 model-B → 语义空间不匹配 → 检索结果全错。
解法：项目配置中统一 Embedding 模型参数，用同一个 embedder 实例。
陷阱 2：流式输出的 Nginx 缓冲
Nginx 默认会缓冲响应，导致 SSE 无法实时推送 → 用户看到的是"卡住后突然出现全部文字"。
解法：设置 X-Accel-Buffering: no 响应头，或 Nginx 配置 proxy_buffering off。
陷阱 3：上下文超出 Token 限制
塞太多文档块进 Prompt → 超出模型上下文窗口 → API 报错或回答质量骤降。
解法：ContextAssembler 严格控制字符数，并为 system prompt + 回答预留空间。
陷阱 4：Reranker 结果为空但未处理
粗排结果全部低于阈值 → Reranker 输入为空 → 部分实现会报错。
解法：Pipeline 中每个阶段都做空值保护，返回友好的"未找到资料"提示。
陷阱 5：SSE 格式错误
前端收不到流式数据 → 检查是否漏了 \n\n 双换行、是否发送了正确的 Content-Type: text/event-stream。
解法：用 curl -N 测试原始 SSE 输出，排除前端问题。

练习 3：LeetCode #347 — 前 K 个高频元素（复习堆）

# 题目：给定整数数组 nums 和整数 k，返回前 k 个高频元素
# 思路：Counter 统计频率 + heapq.nlargest 取 Top-K
# 这与 RAG 检索中的 Top-K 选取是同一思想

from collections import Counter
import heapq


def top_k_frequent(nums: list[int], k: int) -> list[int]:
    """前 K 个高频元素 —— O(n log k)"""
    counts = Counter(nums)  # 统计频率
    # nlargest 取频率最高的 k 个
    return heapq.nlargest(k, counts.keys(), key=counts.get)


# 测试
print(top_k_frequent([1,1,1,2,2,3], 2))  # [1, 2]
print(top_k_frequent([1], 1))              # [1]
