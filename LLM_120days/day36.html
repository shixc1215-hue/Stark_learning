但 RAG 有一个局限：LLM 只能基于已有文档回答问题。它不能查数据库、不能发邮件、不能写文件。Agent 就是打破这个局限的下一步。

Agent（智能体）= LLM 大脑 + 工具箱 + 自主决策循环
核心：LLM 不只生成文本，还生成动作指令，程序执行动作后把结果喂回给 LLM，循环往复直到任务完成。

用一个类比理解 Agent 和 RAG 的区别：

维度RAG（Day 29-35）Agent（Day 36+）
核心能力 基于文档回答问题 自主完成多步骤任务
数据来源 向量库中的文档 任意工具（数据库/API/文件/计算器...）
决策权 人决定问什么 LLM 自己决定调用哪个工具
类比 给你一本参考书，你翻书找答案 给你一整个办公室，你自己决定用电脑、打电话还是查资料
循环 单次：问题→检索→生成 多次：思考→行动→观察→思考...
💡 Agent 和 RAG 不是替代关系！实际生产中，RAG 检索工具就是 Agent 工具箱里最常用的工具之一。Agent 是 RAG 的超集。

2 终止条件：什么时候停下来？
# Agent 的终止条件（必须设置，否则会无限循环！）

终止条件 1： LLM 主动输出 "Final Answer: ..."  → 任务完成
终止条件 2： 循环次数达到上限（如 max_steps=10）→ 防止失控
终止条件 3： 工具返回错误且重试次数耗尽 → 任务失败
⚠️ 没有终止条件 = 灾难！Agent 可能无限调用工具，烧掉 API 额度和钱。生产环境必须设置 max_steps。
🐍 Python 知识：类型注解（Type Hints） ⏱ 20 min

Agent 框架大量使用类型注解。它是 Python 3.5+ 的语法糖，让你给函数和变量标注数据类型。

1 基本类型注解
# ========== 基本类型注解 ==========

# 变量注解（Python 3.6+）
name: str = "张三"       # name 是字符串类型
age: int = 35            # age 是整数
balance: float = 5000000.0  # balance 是浮点数
is_active: bool = True     # is_active 是布尔值
data: list = [1, 2, 3]      # data 是列表
info: dict = {"k": "v"}      # info 是字典

# 函数注解（Python 3.5+）
def calculate_npl_ratio(bad_balance: float, total_balance: float) -> float:
    """计算不良资产率"""
    # 参数: bad_balance(浮点), total_balance(浮点)
    # 返回值: -> float 表示返回浮点数
    
    if total_balance == 0:
        return 0.0
    return bad_balance / total_balance

# 调用时类型注解不会强制检查（Python 是动态语言）
result = calculate_npl_ratio(500, 10000)  # 返回 0.05
result = calculate_npl_ratio("500", "10000")  # 不报错，但运行时会出错

from typing import List, Dict, Optional, Union, Any, Callable, Literal

# List[X] — 列表中的元素都是 X 类型
debtor_ids: List[int] = [1001, 1002, 1003]
names: List[str] = ["张三", "李四"]

# Dict[K, V] — 键类型K，值类型V
debtor_map: Dict[str, float] = {
    "张三": 8500000.0,
    "李四": 6200000.0,
}

# Optional[X] — 要么是 X 类型，要么是 None
def find_debtor(debtor_id: int) -> Optional[dict]:
    """根据ID查找债务人，可能找不到（返回None）"""
    
    db = {1001: {"name": "张三"}, 1002: {"name": "李四"}}
    return db.get(debtor_id)  # get 找不到返回 None

# Union[X, Y] — 要么是X类型，要么是Y类型
def parse_amount(value: Union[str, int, float]) -> float:
    """接受多种输入类型，统一转浮点"""
    
    return float(value)

# Any — 任意类型（少用，表示"不确定"）
def log_result(data: Any) -> None:
    """记录结果"""
    
    print(data)

# Callable — 函数类型，Callable[[参数类型], 返回类型]
def apply_transform(
    data: List[float],
    transform: Callable[[float], float]  # 接受一个参数float，返回float的函数
) -> List[float]:
    """对列表中每个元素应用变换函数"""
    
    return [transform(x) for x in data]

# 使用：传一个 lambda 或普通函数
result = apply_transform([1.0, 2.0, 3.0], lambda x: x * 10000)
# [10000.0, 20000.0, 30000.0]

# Literal — 限定为几个固定值之一（常用于配置）
def set_log_level(level: Literal["DEBUG", "INFO", "WARNING", "ERROR"]) -> None:
    """只接受这几个字符串值"""
    
    print(f"日志级别设为: {level}")

Agent 能力的上限 = 工具箱的质量。定义工具需要三要素：

要素说明AMC 示例

描述 详细说明功能、适用场景、注意事项 "执行 SQL 查询 AMC 数据库..."

1 用 dataclass 定义工具
from dataclasses import dataclass, field
from typing import Any, Callable

@dataclass
class ToolParameter:
    """工具参数定义"""
    
    name: str          # 参数名
    type: str          # 类型: "str", "int", "float", "bool", "list", "dict"
    description: str   # 参数说明（LLM 会读这个）
    required: bool = True   # 是否必填
    default: Any = None      # 默认值

@dataclass
class Tool:
    """Agent 工具定义"""
    
    name: str                                # 工具名（LLM 通过这个名字调用）
    description: str                         # 功能描述（LLM 决策的主要依据！）
    parameters: list[ToolParameter]          # 参数列表
    function: Callable[[dict], str] = None  # 实际执行函数

    def execute(self, args: dict) -> str:
        """执行工具"""
        
        return self.function(args)

    def to_prompt_description(self) -> str:
        """生成给 LLM 的工具描述"""
        
        params_desc = "\n    ".join(
            f"- {p.name} ({p.type}){'【必填】' if p.required else '【可选, 默认:'+str(p.default)+'】'}: {p.description}"
            for p in self.parameters
        )
        return f"""
工具: {self.name}
描述: {self.description}
参数:
    {params_desc}
"""

2 工具描述的"心法"
LLM 依靠工具描述来做决策！描述写得越好，Agent 越聪明。

好的描述："查询 AMC 数据库。表 npl_detail 含不良资产明细（debtor_id, balance, report_date），表 debtor_info 含债务人基本信息。只支持 SELECT。"
差的描述："查询数据库"
  • 写清楚能做什么和不能做什么
  • 列举可用的表名/字段名（否则 LLM 瞎猜表名）
  • 注明注意事项（"只读"、"最大返回100行"）
  • 给 LLM 看一个示例调用（Agent 框架通常支持 examples 字段）
⚙️ 手写 Agent 核心：不依赖框架，理解本质 ⏱ 25 min

现在我们不用 LangChain/任何框架，纯 Python 手写一个完整的 Agent。这能帮你真正理解底层原理。

import json
import re
from dataclasses import dataclass, field

# ========== Agent 对话记录 ==========

@dataclass
class AgentStep:
    """单步记录"""
    
    step_num: int
    thought: str | None = None     # 思考
    action: str | None = None      # 动作（工具名）
    action_input: dict | None = None  # 动作参数
    observation: str | None = None  # 观察结果
    final_answer: str | None = None # 最终答案

    def __str__(self) -> str:
        """格式化输出（便于调试）"""
        parts = [f"Step {self.step_num}:"]
        if self.thought:
            parts.append(f"  Thought: {self.thought}")
        if self.action:
            parts.append(f"  Action: {self.action}({json.dumps(self.action_input, ensure_ascii=False)})")
        if self.observation:
            parts.append(f"  Observation: {self.observation[:200]}")
        if self.final_answer:
            parts.append(f"  ✅ Final Answer: {self.final_answer}")
        return "\n".join(parts)


# ========== 简单的 Agent 实现 ==========

class SimpleAgent:
    """
    最简 Agent 实现（不依赖框架）

    工作原理:
    1. 接收用户问题 + 工具列表
    2. 构造 Prompt 告诉 LLM 有哪些工具可用
    3. LLM 回复 → 解析出 Action（调工具）/ Final Answer（结束）
    4. 循环直到得到 Final Answer 或超过 max_steps
    """

    def __init__(self, llm_client: Any, tools: list[Tool], max_steps: int = 10):
        self.llm = llm_client      # LLM 客户端（任何能对话的都行）
        self.tools = tools          # 可用工具列表
        self.max_steps = max_steps  # 最大循环次数
        self.steps: list[AgentStep] = []  # 执行记录
        self._tool_map = {t.name: t for t in tools}  # 名称→工具映射

    def _build_system_prompt(self) -> str:
        """构造系统提示词"""
        
        tool_descriptions = "\n".join(
            t.to_prompt_description() for t in self.tools
        )
        return f"""你是一个智能助手，可以使用工具来回答用户问题。

可用工具:
{tool_descriptions}

工作流程:
1. 思考（Thought）：分析问题，决定下一步做什么
2. 行动（Action）：选择合适的工具并传入参数
3. 观察（Observation）：获取工具返回的结果
4. 重复上述步骤，直到你能给出最终答案

当你能回答用户问题时，请输出:
Final Answer: 你的回答

重要规则:
- 每次只调用一个工具
- 调用工具时必须使用 JSON 格式的参数
- 如果工具返回错误，尝试修正参数后重试
- 最多执行 {self.max_steps} 步，之后必须给出答案

输出格式（严格遵守）:
Thought: 你的思考...
Action: 工具名
Action Input: {"参数名": "参数值"}
"""

    def _parse_response(self, response: str) -> dict:
        """
        解析 LLM 的回复，提取 Thought/Action/Action Input/Final Answer
        这是 Agent 中最关键的部分！
        """
        result = {
            "thought": None,
            "action": None,
            "action_input": {},
            "final_answer": None,
        }

        # 优先检查 Final Answer
        final_match = re.search(r"Final Answer:\s*(.+?)(?:\n|$)", response, re.IGNORECASE)
        if final_match:
            result["final_answer"] = final_match.group(1).strip()
            return result

        # 提取 Thought
        thought_match = re.search(r"Thought:\s*(.+?)(?=\nAction:|\n$)", response, re.DOTALL)
        if thought_match:
            result["thought"] = thought_match.group(1).strip()

        # 提取 Action（工具名）
        action_match = re.search(r"Action:\s*(\w+)", response)
        if action_match:
            result["action"] = action_match.group(1).strip()

        # 提取 Action Input（JSON 参数）
        input_match = re.search(r"Action Input:\s*(\{.*?\})", response, re.DOTALL)
        if input_match:
            try:
                result["action_input"] = json.loads(input_match.group(1))
            except json.JSONDecodeError:
                result["action_input"] = {"raw": input_match.group(1)}

        return result

    def run(self, question: str) -> str:
        """
        执行 Agent 主循环
        """
        messages = [
            {"role": "system", "content": self._build_system_prompt()},
            {"role": "user", "content": question},
        ]

        for step_num in range(1, self.max_steps + 1):
            # 1. 调用 LLM
            response = self.llm.chat(messages)
            parsed = self._parse_response(response)

            # 2. 记录步骤
            step = AgentStep(step_num=step_num)
            step.thought = parsed["thought"]

            # 3. 检查是否得到最终答案
            if parsed["final_answer"]:
                step.final_answer = parsed["final_answer"]
                self.steps.append(step)
                print(step)
                return parsed["final_answer"]

            # 4. 执行工具
            tool_name = parsed["action"]
            if tool_name in self._tool_map:
                step.action = tool_name
                step.action_input = parsed["action_input"]
                # 调用工具获取结果
                observation = self._tool_map[tool_name].execute(
                    parsed["action_input"]
                )
                step.observation = observation
                self.steps.append(step)
                print(step)

                # 5. 把 Observation 加入对话历史，让 LLM 看到结果
                messages.append({"role": "assistant", "content": response})
                messages.append({
                    "role": "user",
                    "content": f"Observation: {observation}\n\n继续思考下一步，或给出 Final Answer。",
                })
            else:
                # 工具不存在，告诉 LLM 并重试
                messages.append({"role": "assistant", "content": response})
                messages.append({
                    "role": "user",
                    "content": f"Error: 工具 '{tool_name}' 不存在。可用工具: {list(self._tool_map.keys())}。请重新选择。",
                })
                print(f"Step {step_num}: ❌ 未知工具 '{tool_name}'")

        return "⚠️ Agent 达到最大步数限制，未能完成任务。"

    def show_trace(self) -> str:
        """输出完整的执行轨迹（用于调试和审计）"""
        return "\n---\n".join(str(s) for s in self.steps)
💡 这就是 Agent 的全部核心！不管 LangChain 的 AgentExecutor 还是 OpenAI 的 Assistants API，底层都是这个循环：Prompt → LLM → 解析 → 工具 → 结果 → 再 Prompt。框架只是帮你做了格式解析和错误处理。

🛡️ 常见陷阱 & 最佳实践 ⏱ 5 min
❌ 陷阱 1：不设 max_steps — Agent 可能无限循环，烧光 API 额度。务必设置最大步数（建议 5-15 步）。
❌ 陷阱 2：工具描述太简短 — LLM 不知道工具能做什么，会瞎调或不用。描述要像写给新同事看的文档一样详细。
❌ 陷阱 3：解析格式依赖 LLM 严格输出 — LLM 偶尔会不按格式输出。解析器要健壮，做好容错和重试。
❌ 陷阱 4：工具权限过大 — 给了 db_query 却没限制只能 SELECT，Agent 可能执行 DELETE。每个工具都要做安全边界。
❌ 陷阱 5：上下文爆炸 — 每轮循环都把历史塞进 messages，超过 token 上限会截断。要及时裁剪中间步骤，保留首尾。
🧠 Prompt 工程心法
System Prompt 必须明确：可用工具列表、输出格式要求、终止条件、错误处理指引
🔧 工具设计心法
每个工具做好三件事：清晰描述（给 LLM 看）、参数校验（防注入）、安全边界（最小权限）
📊 可观测性
记录每步的 Thought/Action/Observation + 时间戳。这是调试 Agent 的唯一线索
🔄 上下文管理
超过 token 上限时，保留 System Prompt + 最近 2-3 轮 + 摘要中间步骤
