🔍 一、Reranker 是什么？为什么需要它？ ⏱ 10min
Reranker（重排序器）：在向量检索召回的候选结果基础上，用一个更精细的模型对每个 query-document 对进行交叉打分，重新排序后只取 Top-N 给 LLM 生成。

类比理解：数仓的两阶段查询

作为数据开发工程师，你一定熟悉这个场景：

  • 第一阶段（粗筛）：WHERE 过滤出 1000 条 → 类似向量检索（Recall）
  • 第二阶段（精排）：ORDER BY + LIMIT 取 Top 10 → 类似 Reranker

SQL 里你写 ORDER BY relevance_score DESC LIMIT 5，RAG 里 Reranker 就是那个 ORDER BY。

为什么 Bi-Encoder 检索不够精确？

# Bi-Encoder（Day30 学的）独立编码 query 和 document
query_emb = embed("不良资产处置有哪些方式？")      # → [0.12, -0.34, ...]
doc_emb   = embed("不良资产处置包括债务重组...")    # → [0.15, -0.31, ...]
score     = cosine(query_emb, doc_emb)               # → 0.82

# 问题：query 和 doc 是分别编码的，模型看不到它们的交互关系
# 就像你只看简历关键词匹配，不面试怎么知道真合不合适？

Cross-Encoder 如何解决？

# Cross-Encoder：把 query 和 doc 拼接后一起送入模型
input = "[CLS] 不良资产处置有哪些方式？ [SEP] 不良资产处置包括债务重组、资产证券化... [SEP]"
score = cross_encoder(input)  # → 0.95  ← 精准多了！因为模型同时看到 query 和 doc 的每个词

# 类比：不是看简历关键词匹配度，而是让候选人和HR面对面面试

完整 RAG 管线中的位置

Query │ ▼ [Retriever] ──召回 Top-20（Bi-Encoder 向量检索，快但粗） │ ▼ [Reranker] ──精排 Top-5（Cross-Encoder 交叉编码，慢但准）← 今天学这个 │ ▼ [Generator] ──LLM 基于上下文生成回答 │ ▼ Answer
核心 tradeoff：Reranker 的本质是用计算时间换检索精度。Bi-Encoder 对每篇文档只编码一次（离线），Cross-Encoder 每次查询都要和每篇候选文档"交互"（在线）。

2.1 lambda 匿名函数：一行搞定简单逻辑

Reranker 经常需要对列表做"按某个分数排序"，lambda 是最常用的写法。

# 基本语法：lambda 参数: 返回值
square = lambda x: x ** 2
print(square(5))  # 25

# 等价于
def square(x):
    return x ** 2

# lambda 最常见场景：sorted() 的 key 参数
scores = [("doc_A", 0.82), ("doc_B", 0.95), ("doc_C", 0.71)]
ranked = sorted(scores, key=lambda x: x[1], reverse=True)
print(ranked)
# [('doc_B', 0.95), ('doc_A', 0.82), ('doc_C', 0.71)]
lambda 使用原则：lambda 只适合单行简单表达式。如果逻辑超过一行（有 if-else 分支），写成普通 def 函数更清晰。

2.2 sorted() 高阶用法回顾与扩展

Day32 学了 sorted 基础，今天扩展到更复杂的排序场景。

# 场景1：多字段排序（先按分数降序，分数相同按文档ID升序）
results = [
    {"id": 3, "score": 0.92, "source": "AMC年报"},
    {"id": 1, "score": 0.92, "source": "监管文件"},
    {"id": 5, "score": 0.88, "source": "处置公告"},
]

# 方法A：lambda 返回元组
ranked = sorted(results, key=lambda x: (-x["score"], x["id"]))
# score 降序(加负号) → id 升序

# 方法B：itemgetter（比 lambda 快一点点）
from operator import itemgetter
ranked = sorted(results, key=itemgetter("score", "id"), reverse=True)

print([r["id"] for r in ranked])  # [1, 3, 5] 或 [3, 1, 5]

# 场景2：稳定排序 — 多次 sorted 实现"先按X分组，组内按Y排序"
# 先按 source 分组（稳定排序不改变相同 key 的相对顺序）
by_source = sorted(results, key=lambda x: x["source"])
# 再按 score 降序
by_score = sorted(by_source, key=lambda x: x["score"], reverse=True)
# 效果：相同 score 的文档，按 source 字母序排列

from dataclasses import dataclass, field
from typing import Optional

@dataclass(order=True)  # 自动生成 __lt__ 等比较方法
class RetrievalResult:
    """检索结果 —— 支持 sorted() 直接排序"""
    score: float                          # 第一个字段 = 默认排序依据
    doc_id: str = field(compare=False)      # 不参与比较

    source: str = field(default="", compare=False)
    rerank_score: Optional[float] = field(default=None, compare=False)

# 直接用 sorted 排序（按 score 字段）
results = [

    RetrievalResult(0.95, "d2", "债务重组操作指南...", "监管文件"),

print([r.doc_id for r in ranked])  # ['d2', 'd1', 'd3']

# 如果需要按 rerank_score 排序（不是第一个字段）
ranked_by_rerank = sorted(
    results,

3.1 Bi-Encoder vs Cross-Encoder 对比

维度Bi-Encoder（检索用）Cross-Encoder（重排用）
输入query 和 doc 分别编码query 和 doc 拼接后一起编码
交互❌ 看不到词间交互✅ 每个词都能attend到对方
速度⚡ 快（离线预计算）🐢 慢（每次在线计算）
精度够用但不精确高精度
用途从百万篇中召回 Top-K从 Top-K 中精排 Top-N
类比简历关键词筛选面对面面试
代表模型bge-large / text-embedding-3bge-reranker / cohere-rerank

3.2 Cross-Encoder 打分过程

# Cross-Encoder 的输入格式
text_pair = f"{query} [SEP] {document}"

# 模型内部：
# 1. Tokenizer 拼接 → [CLS] query_tokens [SEP] doc_tokens [SEP]
# 2. BERT self-attention → query 和 doc 的每个 token 可以互相看到
# 3. [CLS] 的隐向量 → Linear → sigmoid → 相关性分数 (0~1)

# 关键：query 的"处置" 可以 attend 到 doc 里的"债务重组"
#       因为"处置"和"债务重组"在 BERT 训练中学到了语义关联
为什么两阶段设计？ 如果直接用 Cross-Encoder 检索百万文档 → 每次 query 要计算百万次 → 太慢。所以用 Bi-Encoder 粗筛（快）+ Cross-Encoder 精排（准），速度快100倍以上的同时保持高精度。

3.3 Reranker 评分公式

rerank_score = sigmoid(W · H[CLS] + b) ∈ [0, 1]
H[CLS] = BERT([CLS] query [SEP] document [SEP]) 的 [CLS] 隐状态

from dataclasses import dataclass, field
from typing import Optional

# ========== 1. 定义结果数据类 ==========
@dataclass(order=True)
class RankedDocument:
    """带重排分数的检索结果"""
    rerank_score: float
    retrieval_score: float = field(compare=False)
    doc_id: str = field(compare=False)
    text: str = field(compare=False)
    source: str = field(compare=False)

    def __str__(self):
        return f"[{self.doc_id}] score={self.rerank_score:.3f} | {self.text[:60]}..."


# ========== 2. Jina Rerank API 调用 ==========
def jina_rerank(
    query: str,
    documents: list[str],
    top_n: int = 5,
    api_key: str = None,
    model: str = "jina-reranker-v2-base-multilingual",
) -> list[dict]:
    """
    调用 Jina Rerank API 对候选文档重排序
    
    Args:
        query: 用户查询
        documents: 候选文档列表
        top_n: 返回 Top-N 结果
        api_key: Jina API Key（免费注册）
        model: 重排模型名称
    
    Returns:
        重排结果列表，每项包含 index, relevance_score
    """
    url = "https://api.jina.ai/v1/rerank"
    headers = {
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json",
    }
    payload = {
        "model": model,
        "query": query,
        "documents": documents,
        "top_n": top_n,
    }

    resp = requests.post(url, headers=headers, json=payload, timeout=30)
    resp.raise_for_status()
    result = resp.json()

    return result.get("results", [])

# ========== 4. 执行重排序 ==========
def rerank_pipeline(query: str, raw_results: list[dict], top_n: int = 5) -> list[RankedDocument]:
    """
    完整的重排序管线：
    1. 提取文档文本
    2. 调用 Rerank API
    3. 组装排序后的结果对象
    4. 返回 Top-N
    """
    documents = [r["text"] for r in raw_results]

    # 调用 Rerank API
    rerank_results = jina_rerank(
        query=query,
        documents=documents,
        top_n=top_n,
        api_key="your-jina-api-key-here",  # ← 替换为你的 API Key
    )

    # 组装排序结果
    ranked = []
    for item in rerank_results:
        idx = item["index"]          # 原始结果中的索引
        score = item["relevance_score"]  # 重排分数
        original = raw_results[idx]

        ranked.append(RankedDocument(
            rerank_score=score,
            retrieval_score=original["score"],
            doc_id=original["id"],
            text=original["text"],
            source=original["source"],
        ))

    return sorted(ranked, reverse=True)  # 按 rerank_score 降序

4.3 封装通用 Reranker 工具类

"""
通用 Reranker 工具类 — 支持 API 和本地两种模式
"""
from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from typing import Optional
import requests


@dataclass
class RerankResult:
    """单条重排结果"""
    doc_id: str
    text: str
    score: float
    index: int           # 在原始列表中的索引
    metadata: dict = field(default_factory=dict)


class BaseReranker(ABC):
    """Reranker 抽象基类 — 策略模式"""

    @abstractmethod
    def rerank(
        self,
        query: str,
        documents: list[str],
        doc_ids: Optional[list[str]] = None,
        top_n: int = 5,
    ) -> list[RerankResult]:
        """对候选文档重排序，返回 Top-N"""
        ...


class JinaReranker(BaseReranker):
    """Jina API Reranker"""

    def __init__(self, api_key: str, model: str = "jina-reranker-v2-base-multilingual"):
        self.api_key = api_key
        self.model = model
        self.url = "https://api.jina.ai/v1/rerank"

    def rerank(self, query, documents, doc_ids=None, top_n=5):
        if doc_ids is None:
            doc_ids = [str(i) for i in range(len(documents))]

        headers = {
            "Authorization": f"Bearer {self.api_key}",
            "Content-Type": "application/json",
        }
        payload = {
            "model": self.model,
            "query": query,
            "documents": documents,
            "top_n": top_n,
        }

        resp = requests.post(self.url, headers=headers, json=payload, timeout=30)
        resp.raise_for_status()

        results = []
        for item in resp.json().get("results", []):
            idx = item["index"]
            results.append(RerankResult(
                doc_id=doc_ids[idx],
                text=documents[idx],
                score=item["relevance_score"],
                index=idx,
            ))

        # 按分数降序
        return sorted(results, key=lambda r: r.score, reverse=True)


# ========== 使用示例 ==========
reranker = JinaReranker(api_key="your-key")

query = "不良资产处置的主要方式有哪些？"
docs = [

    "债务重组是不良资产处置的核心手段...",
]

5.1 召回数量 vs 重排数量的 tradeoff

推荐配比：Bi-Encoder 召回 Top-20~50，Reranker 精排取 Top-3~5。召回太少会丢失相关文档，召回太多会拖慢 Reranker 且 LLM 上下文装不下。 
# 最佳实践参数配置
RERANK_CONFIG = {
    "retrieval_top_k": 20,    # 向量检索召回 20 篇（够多，不容易漏）
    "rerank_top_n": 5,        # 重排后取 5 篇（LLM 上下文窗口够用）
    "score_threshold": 0.3,   # 低于此分数直接丢弃（过滤噪音）
}

5.2 分数阈值过滤

def filter_by_threshold(
    results: list[RerankResult],
    threshold: float = 0.3
) -> list[RerankResult]:
    """过滤低于阈值的结果，避免把不相关的内容送入 LLM"""
    filtered = [r for r in results if r.score >= threshold]

    if len(filtered) < len(results):
        dropped = len(results) - len(filtered)
        print(f"⚠️ 过滤掉 {dropped} 条低分结果（阈值 {threshold}）")

    return filtered

5.3 Reranker 常见陷阱 Top 5

#陷阱后果解决方案
1 不用 Reranker 直接把 Top-20 送 LLM LLM 被不相关内容误导，回答质量下降 永远加 Reranker 精排环节
2 Reranker 和 Embedding 用不同语言训练 语义空间不匹配，排序效果差 用同一系列模型（如 bge-embed + bge-rerank）
3 文档过长截断后送 Reranker 丢失关键信息，打分不准 Reranker 输入限制 512 tokens，送原文前几段
4 忽略重排耗时 API 调用延迟高，用户体验差 异步并发 + 缓存 + 降级方案
5 只看分数不看内容 可能过滤掉文本短但高度相关的结果 设置合理阈值 + 人工抽查

5.4 何时不需要 Reranker？

可以跳过 Reranker 的场景：文档库较小（<1000篇）、查询意图非常明确、对延迟要求极高（<100ms）、原型验证阶段。必须用 Reranker 的场景：文档库 >1万篇、用户查询含糊/多义、需要高精度回答的生产系统。
