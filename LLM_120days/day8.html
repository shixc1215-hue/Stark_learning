with 上下文管理器：文件操作的标配写法

with 语句确保文件用完自动关闭，即使中途出错也不会泄露文件句柄。以后永远用 with，不要手动 open()/close()。

# ====== 读取文本文件 ======
with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()       # 读取全部内容
    lines = f.readlines() # 读取所有行（含换行符）

# ====== 写入文本文件 ======
with open("output.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n")
    f.write("第二行\n")

# ====== 追加写入（不覆盖） ======
with open("log.txt", "a", encoding="utf-8") as f:
    f.write("新的日志条目\n")

# 模式："r"读 | "w"写(覆盖) | "a"追加
💡 重要习惯：读写文件时永远加 encoding="utf-8"。Windows 默认用 GBK 编码，不指定会导致中文乱码或 UnicodeEncodeError。

JSON 文件读写（LLM 应用最常用）

API 返回值是 JSON、对话记录存 JSON、配置文件用 JSON。掌握 json 模块就够了。

import json

# ====== 写入 JSON ======
data = {
    "project_name": "某AMC项目",
    "principal": 10000000,
    "status": "处置中",
}

with open("project.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
# ensure_ascii=False → 中文直接写入不转义
# indent=2 → 文件可读性好

# ====== 读取 JSON ======
with open("project.json", "r", encoding="utf-8") as f:
    loaded = json.load(f)

print(loaded["project_name"])  # 某AMC项目

# ====== 字符串 ↔ JSON 互转（不写文件时用） ======
json_str = json.dumps(data, ensure_ascii=False)
parsed = json.loads(json_str)

Step 2：封装保存和加载函数

import json, os
from datetime import datetime

HISTORY_FILE = "chat_history.json"

def save_chat(messages: list, model: str = "glm-4-flash"):
    """将对话历史保存到 JSON 文件"""
    data = {
        "model": model,
        "updated_at": datetime.now().strftime("%Y-%m-%d %H:%M:%S"),
        "messages": messages,
    }
    with open(HISTORY_FILE, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)

def load_chat() -> dict:
    """加载对话历史，文件不存在或损坏时返回空对话"""
    if not os.path.exists(HISTORY_FILE):
        return {"model": "glm-4-flash", "messages": []}
    try:
        with open(HISTORY_FILE, "r", encoding="utf-8") as f:
            return json.load(f)
    except json.JSONDecodeError:
        return {"model": "glm-4-flash", "messages": []}
💡 关键设计：load_chat() 用 os.path.exists 检查文件 + try/except 捕获 JSON 错误。永远假设文件可能不存在或损坏——这是生产级代码的基本素养。

Step 3：完整的多轮对话程序（带持久化）

整合 Day 6 while 循环 + Day 7 函数封装 + 今天文件读写：

import json, os
from datetime import datetime
from openai import OpenAI

HISTORY_FILE = "chat_history.json"
MAX_HISTORY = 20
SYSTEM_PROMPT = "你是宁波AMC的不良资产业务专家。请用专业但通俗的语言回答。"

client = OpenAI(
    api_key="你的智谱API Key",
    base_url="https://open.bigmodel.cn/api/paas/v4/"
)

# save_chat 和 load_chat 完整定义见 Step 2，此处直接引用

def ask_llm(messages):
    """调用 LLM，传入完整 messages 列表"""
    response = client.chat.completions.create(
        model="glm-4-flash",
        messages=messages,
        temperature=0.7
    )
    return response.choices[0].message.content

# ====== 主程序 ======
# 1. 启动时加载历史
chat = load_chat()
messages = chat["messages"]

# 如果历史为空，插入 system prompt
if not messages:
    messages.append({
        "role": "system",
        "content": SYSTEM_PROMPT
    })

print("=== AMC 业务问答助手（输入 quit 退出，new 开启新对话） ===")
print(f"当前历史消息数：{len(messages)}")

while True:
    user_input = input("\n你：").strip()

    if user_input == "quit":
        save_chat(messages)  # 退出前保存！
        print("对话已保存，再见！")
        break

    if user_input == "new":
        messages = [{"role": "system", "content": SYSTEM_PROMPT}]
        save_chat(messages)
        print("已开启新对话！")
        continue

    # 添加用户消息
    messages.append({"role": "user", "content": user_input})

    # 滑动窗口：只保留最近 N 条（控制 token）
    if len(messages) > MAX_HISTORY:
        system_msg = messages[0]
        messages = [system_msg] + messages[-(MAX_HISTORY - 1):]

    # 调用 LLM
    reply = ask_llm(messages)
    messages.append({"role": "assistant", "content": reply})

    # 每次对话后自动保存
    save_chat(messages)

    print(f"\nAI：{reply}")
💡 核心要点：
  • 每次对话结束后立即保存（不是退出时才保存）——防止中途崩溃丢失数据
  • 滑动窗口保留 system prompt（messages[0]）——它定义了 AI 的人设，不能丢
  • new 命令清空历史重新开始——体现了"程序状态管理"的概念

📖 碎片知识：Embedding 概念 ~15 分钟
为什么今天学 Embedding？ — 明天（Day 9）你就要用 LLM 的输出来做"结构化数据提取"，而 Embedding 是 RAG（Phase 2 核心）的基础概念。提前建立直觉，后面学向量数据库时就不会懵。

一句话解释 Embedding：把文本变成一串数字（向量），让"语义相近的文本"在数学空间中"距离更近"。

打个比方：你把所有 AMC 业务术语放在一张巨大的地图上。"债权转让"和"债权打包出售"虽然字不完全一样，但它们在地图上的位置会很近；而"债权转让"和"煎饼果子"会隔得很远。

文本Embedding 向量（简化示意）
债权转让[0.23, 0.87, -0.12, 0.45, ...]
债权打包出售[0.21, 0.85, -0.10, 0.42, ...]
债务重组[0.18, 0.72, 0.05, 0.38, ...]
煎饼果子[-0.65, 0.11, 0.92, -0.33, ...]

余弦相似度（Cosine Similarity）：衡量两个向量"方向是否一致"。值越接近 1 = 越相似。不需要记公式，记住这个直觉就行。

💡 和你工作的关联：
Embedding 是 RAG 系统的核心。RAG 的流程是：用户提问 → 问题变向量 → 在向量数据库中找最近的文档 → 把文档喂给 LLM → 生成回答。

你现在的数据仓库经验（ODS/DWD/DWS 分层）会在 Phase 2 转化为"文档预处理管道"的经验——数据质量是 RAG 生命线，这正是你的强项。

LeetCode #344 · 反转字符串（Easy）

编写一个函数，反转字符串。必须原地修改输入数组、使用 O(1) 额外内存。

示例：s = ["h","e","l","l","o"] → 输出 ["o","l","l","e","h"] 

def reverseString(s: list) -> None:
    """原地反转字符串列表（双指针）"""
    left, right = 0, len(s) - 1
    while left < right:
        s[left], s[right] = s[right], s[left]  # Python 交换
        left += 1
        right -= 1

# 测试
s = ["h", "e", "l", "l", "o"]
reverseString(s)
print(s)  # ['o', 'l', 'l', 'e', 'h']

# Python 一行写法（面试可以说你见过，但要能写双指针版本）
# s.reverse()

为什么这道题重要？双指针是面试高频考点。而且字符串操作在 LLM 应用中无处不在——解析 JSON 输出、提取关键词、处理 Prompt 模板，都需要操作字符串。
